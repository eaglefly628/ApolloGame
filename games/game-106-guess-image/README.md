# Game 106 · 你画我猜

题目图片从重度马赛克开始，随时间逐渐变清晰。玩家要在四个选项里**尽早**认出答案 ——
猜得越早，分值越高。

## 运行

纯静态页面，无构建步骤、无外部依赖，直接打开即可：

```bash
open games/game-106-guess-image/index.html
```

或起一个本地服务：

```bash
npx serve games/game-106-guess-image
```

## 玩法

| 规则 | 说明 |
|---|---|
| 局长 | 8 题，题目从 27 张图库中随机不重复抽取 |
| 揭晓节奏 | 约 13 秒从全马赛克到全清晰，之后有 4 秒宽限期 |
| 分值 | 随清晰度从 **1000** 线性衰减到 **150** |
| 干扰项 | 优先取**同类别**的其它题目，避免靠背景色蒙对 |
| 猜错 | 错 1 次本题分值减半并继续；错 2 次本题作废 |
| 连击 | 连续答对累积加成，每层 +10%，上限 ×1.5 |
| 超时 | 不作答则本题 0 分，连击清零 |

结算按总分给出 S/A/B/C/D 评级，历史最佳存在 `localStorage`。

支持键盘 <kbd>1</kbd>–<kbd>4</kbd> 作答，<kbd>Enter</kbd>/<kbd>Space</kbd> 开始。

## 实现要点

### 题图是程序化绘制的，不是图片资源

`js/artwork.js` 里的 27 道题全部用 Canvas 现场画出来，仓库里没有任何 `.png`/`.jpg`。
好处是**完全离线可用**、体积极小、任意分辨率都清晰。

每个题目的 `draw(ctx)` 都工作在**单位坐标系**中 —— 画布已被 `ctx.scale(S, S)`，
所以坐标、半径、线宽一律用 0~1 的比例值，与实际渲染尺寸解耦：

```js
{ id: 'apple', name: '苹果', cat: 'food',
  draw: function (ctx) {
    bg(ctx, '#fff6e2', '#ffd9a6');
    ell(ctx, 0.41, 0.60, 0.23, 0.25, 0, '#d93a34');
    ...
  }
}
```

题目按 `cat` 分成 食物 / 动物 / 交通工具 / 物件 / 自然 五类，每类至少 4 项，
保证干扰项能凑齐同类别的三个。

### 马赛克是逐级折半降采样得到的

一次性把 512px 大比例缩到 8px，部分浏览器会退化成稀疏采样，马赛克块的颜色会失真。
所以 `downscale()` 采用**反复折半**逼近目标尺寸，得到接近盒式滤波的平均值，
再用 `imageSmoothingEnabled = false` 放大回画布，保留硬边方块：

```
512 → 256 → 128 → … → n   （每级 imageSmoothingQuality='high'）
                    ↓
        放大到画布（关闭平滑）
```

块边长按 `block = 64^(1-t)` 指数衰减（t 为清晰度 0~1），
即每过 1/6 时长块大小减半：64 → 32 → 16 → 8 → 4 → 2 → 1。
实测 t≈0.4 时大部分题目已可辨认，难度曲线合适。

### 月牙不能用双圆缠绕来挖

`ring()` 用两个反向缠绕的同心圆 + nonzero 填充规则来挖洞，这对**完全包含**在内的洞有效。
但月牙的切割圆必然伸到外圆之外，那部分区域缠绕数是 −1，nonzero 照样会填充，
结果退化成一个圆环。所以 `crescent()` 改用离屏画布 + `destination-out` 真正打洞。
