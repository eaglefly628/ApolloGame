# 战功系统（老兵资历 · collection 养成 · owner 2026-07-03）

> owner 2026-07-03：引入**战功系统**——一张牌在战场上战胜过多少敌人，作为**隐藏数值存在卡牌里**、增加**收藏属性**；当一张牌**战场累计战胜 > 108 次**，其**战力永久 +1**。
> 定性（design G·CORE RULE）：**接受**。收藏情感钩子 + 一条"用出来的强"养成轴（区别于地支/deckBias 的"买出来的强"）。**数据驱动·下沉成通用能力**（非 game-g 专属代码）。

## 一、核心规则
- **每张玩家收藏牌**带一个**持久 `kills` 计数**（战场每赢一次掷命对决 +1·跨战斗/跨 run 累计·存进存档）。
- **`kills ≥ 108` → 该牌战力永久 +1**（里程碑·永久生效）。
- **⭐ 108 的立意**：水浒星宿结构 = **三十六天罡 + 七十二地煞 = 108**（本作天罡/地煞命名正取自此）。一张牌杀满 108 = "凑齐三十六天罡七十二地煞、修成正果"。**这个数在我们自己的体系里有含义·非拍脑袋**。

## 二、设计决策（owner 2026-07-03 OK design G 默认）
1. **隐藏程度**：战场 HUD **不显**（不干扰对决）；**收藏界面可看**（`kills` 是可炫耀的收藏属性·带进度）。
2. **里程碑**：**先单个 108 → +1**；阶梯（216→+2…）留作后续可选扩展·不现做（YAGNI）。
3. **归属**：**仅玩家收藏牌累计**；**Boss 每关用全新写死 16 牌·不累计战功**（Boss 难度走明牌 kit·不靠隐藏老兵值）。

## 三、数据驱动落地（下沉成通用"老兵/资历里程碑"能力·非专属码）
三块现成能力拼成，**不写 game-g 专属逻辑**：
1. **持久 `kills` 计数** = 每张收藏牌一个持久 Resource（存档带走）→ 复用 **`services/save` save-port**（版本化信封·迁移链已在）。
2. **战胜 +1** = `resolveClash` 胜者 `kills++` 的**事件计数钩子**（小·确定性·outcome-first）。
3. **满 108 → +1 战力** = 复用 **`t2-modifier-stack`**：`ModifierSource {target:'战力(P)', op:'add', value:1, gate: kills≥108}`（gate 门控正是它的活）。
> = "**任意牌 · 累计任意事件 · 到阈值触发任意修正**"的通用系统（别的游戏也能用·如"部署过 N 次 / 施法过 N 次 → 解锁修正"）。尺子过：最弱 LLM 只填 `{事件, 阈值, 修正}` 三段数据。

## 四、平衡账（低风险）
- **慢**：108 杀 ≈ 一张牌打 **25-35 场**（留场续攻一场杀 3-5）→ **长尾荣誉·非早期强度杠杆**。
- **小**：+1 战力在掷战力骰下边际 ≈ +1/(2P) 胜率（P≈10 时 ~+5%·高战力更小）。
- → **温和 power creep**·sim 里当**一档养成 favor** 建模（同地支）·可控。**真正奖励是"荣誉/收藏故事"·+1 是象征**。

## 五、落地顺序（排队·核心之后）
战功 = **收藏打磨·与战斗核正交**。**排在核心拍死之后**（动作模型/AOE/经济/玩家AI 稳了）再开工——别往正动的地基加零件。**派单已立·status 排队**（见 `requests.md REQ-G-战功系统`）。

## 六、开放（后续可选）
- 阶梯里程碑（108→+1 · 216→+2 · …）——若单个 108 手感淡再加。
- 其它"用出来的"资历（部署次数 / 连携次数 / 破家次数 → 各自里程碑）——同一通用能力·想扩就填数据。
- 战功可视化（收藏界面进度环 / "百将"称号 / 满108 特效）——程序B·收藏屏。
