# 13 · 终局 Boss 阵容（牌王座 · 每 run 轮换）

> game design G ｜ 2026-06-15 ｜ 承 `11` §二终局 Boss + program G T-G5 余项"Boss 真起手干预（需对称干预算子）"。
> 现状：T-G5 已建终局 Boss 槽（第 5 场牌王座 + 高 favor），但 Boss 还**没有性格**。本篇给一池**拟人化扑克 Boss**，每 run 轮换一名当终局 → 重玩性（仿 gameF 太阁轮换）。

---

## 〇、设计目标

- **每 run 终局从池中轮换一名 Boss** → "这把遇到谁"的新鲜感 + 针对性布阵（看 Boss 流派调你的分兵）。
- 每个 Boss = **一个扑克人格 + 一招看家 gimmick**，全部**复用已落系统**（favor 偏置 / 将领 / 干预 / 牌型 / 机关），纯数据。
- Boss 比常规更凶 = 高 favor 偏置 + **起手甩干预卡**（见 §二对称干预）。

---

---

## 二、对称干预（解 program G 的"Boss 真起手干预"余项）

> program G 问：Boss 出干预需"对称干预算子"。**答：不需要新算子——干预效果本就按"侧/路"参数化，应用到 AI 侧 = 纯数据。**

- 现 `applyInterventions` 在揭晓前改 favor/主将/兵力，**目标已带 side（己/敌）+ lane**。让 Boss 起手干预 = 在揭晓前，**对 AI 侧也跑一遍 `applyInterventions`**，吃 Boss 的 `openingLevers` 列表（如 `[诅咒→敌(玩家)上路, 斩首→敌中路主将]`）。
- **对称性 = 把"谁是施加方"做成参数**，不是两套算子。玩家干预 = 玩家命令；Boss 干预 = 数据列表 `openingLevers`。同一函数、同 outcome-first（都在揭晓前改输入）。
- → **零新能力**：Boss 起手干预 = 现有干预系统 + 一个数据列表 + "对 AI 侧也调用一次"的接线。⚠️ 若 `applyInterventions` 现在写死只作用玩家侧，则是**小接线**（加 side 参数），非新算子；program G 核一下，真要小改照 game 侧改（不动引擎）。

---

## 三、Boss 节奏（让终局有记忆点）

- **入场**：Boss 揭晓人格 + 看家台词（表现层）；起手甩 `openingLevers` → 玩家先吃一记，逼应对。
- **决战**：玩家用攒下的干预能量◈ 反制（留能量打 Boss = `11` 终局张力）。
- **轮换**：每 run 随机一名（或按段位解锁更多）→ "集齐图鉴"留存钩子。

---

## 四、复用 / 缺口（CORE RULE）

| 机制 | 判定 |
|---|---|
| Boss 偏强 Formation + favor 偏置 | ✅ 纯数据（`09`/`11`）|
| Boss gimmick（将领/牌型/spawn/赌）| ✅ 复用 `06`/`10` 各系统 |
| **Boss 起手干预（对称）** | ✅ 复用 `applyInterventions` + `openingLevers` 数据；⚠️ 若现写死玩家侧→小接线加 side 参数（游戏侧，非引擎）|
| 每 run 轮换 | ✅ 关卡数据选一名（RandomSeed）|

> **零新引擎能力**。对称干预是"加 side 参数"的游戏侧小接线（若需要），非新算子。

## 五、验收（未来，并入 T-G5 收尾 / T-G6）

1. Boss 池 6 名，每 run 终局轮换一名，各带 Formation + favor 偏置 + gimmick。
2. Boss 起手干预生效（对 AI 侧跑 `applyInterventions` 吃 `openingLevers`），outcome-first 不破。
3. 同 seed + 同 Boss + 同决策 → 逐拍 hash 一致。
4. tsc + vitest + build 全绿。

> 复诵：6 名拟人化扑克 Boss、每 run 轮换给终局新鲜感；Boss 起手干预 = 现有干预系统应用到 AI 侧（加 side 参数的小接线，非新算子），零新能力。终局有性格、有记忆点 = "有趣丰满"。
