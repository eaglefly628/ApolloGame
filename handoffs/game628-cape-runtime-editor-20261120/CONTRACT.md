# G628-CAPE-A 统一交换契约

三线共同契约为 [Engine DEV v2](../game628-cape-runtime-engine-20261120/CONTRACT.json)。[联合包快照](inputs/engine-contract.json)与布料版型声明的 SHA 一致。[编辑器数据](cape-contract.json)仅记录本场景的体型映射、试穿请求与档位状态。编辑器根据当前可见演员解析体型。Engine DEV 在同一渲染帧提供骨点与动态消费，布料线提供版型与身体代理。

## 坐标与选点

- 右手系，Y-up，+Z 向前，米制。左和右指角色自身。双肩统一使用 `LeftUpperArm` / `RightUpperArm` 的近端原点。骨前定义的 `LeftShoulder` / `RightShoulder` 在锁骨内侧，不能直接配用现有按肩距拟合的布料样件。
- 双侧扣点偏移为该骨局部轴的 [0, 0, -0.025] 米，使用归一化动画骨旋转。该偏移随贴合验收结果由领域负责人更新。
- (B_w) 为当前动作之后骨节点世界矩阵，(R_w) 为当前角色所显示模型根的单位尺度刚体变换。骨点世界位置取 (B_w) 的平移。非零偏移用 (B_w) 的归一化世界旋转将米制偏移转到世界再相加。骨架层的 0.0086 缩放已经进世界矩阵，米制偏移只旋转一次。
- 统一交给布料的是角色可见根局部肩点 (p_{actor} = R_w^{-1}p_{world})。布料世界求解直接使用 (p_{world}=R_w p_{actor})。布料局部求解先用该实例当前刚体坐标 (C_w^{-1} R_w p_{actor})。动态根变化和针脚运动用增量通道推进，正常走停转期间保留顶点及速度历史。

## 顺序与状态

1. 编辑器根据当前显示的草稿或已应用外观解析 bodyId，并提供请求开关和 normal / low / off 档。换外观中的脸、帽子、手不会更换体型 ID。
2. 提交 sim 根位姿，模型在该渲染帧完成位置、转向、动作采样及世界矩阵更新。取可见演员真实姿态的角色根及双肩。动作时钟取正在播放的实际样本，同一帧标记 poseRevision。
3. 同一 poseRevision 转换肩点与布料线代理，更新两点和身体代理，再推进布料求解并绘制。图像帧和角色动作样本必须一致。
4. 试穿关闭或 off 时清理布料实例。正常走停转、持续动画不得重建。不同拓扑或体型代理需要重建时要显式记录原因。重穿需要从当前角色姿态初始化。只有实际配置 low 的动态通道就绪时，UI 才可宣称已启用低档。

动态联合候选已接入同一份引擎通道和版型数据。Chrome 与原生 WASM 结果、网格贴合的待修项见 [联合试玩记录](README.md)。
