# Game 628 全身居民编辑与交互手

Wii Mii Channel 把脸拆成可独立选择的部件，再提供位置、大小、角度、间距和颜色调节。身高与体型各有独立滑杆。Game 628 沿用这种编辑方式，采用自己的居民造型、色板和界面。 [Nintendo Wii 功能手册第 20–25 页](https://www.nintendo.co.jp/wii/support/pdf/wiimanual_functions.pdf)

## 当前全身样件

全身页用同骨架模型和共享二进制提供 36 个可混搭的预设组合。摘帽恢复冠部头发的体积，宽掌只增加手部网格的比例，左右手腕和指骨的位置保留。两种手形均可播放已有挥手动作。精细的五官调整仍在独立捏脸页。

## 角色外观数据

| 区域 | 保存的数据 | 变更约定 |
| --- | --- | --- |
| 身体 | 身高、躯干胖瘦 | 身高调骨架比例并保持脚底落地。胖瘦调肩胸腰臀和衣服适配，脸和手的参数独立。 |
| 头部 | 头型 ID、肤色 ID | 每种头型提供五官、耳朵、发际和帽位基准。更换头型时重新定位部件。 |
| 五官 | 眼、眉、鼻、嘴样式 ID，各自可用的颜色、大小、垂直位置、间距、倾角 | 眼眉成对相对脸中线调整。鼻嘴沿脸中线移动。每个头型分别验证参数极值的组合。 |
| 帽发与装饰 | 发型、发色、帽子、帽色、眼镜、脸部细节 | 帽子可为空。每顶帽子定义适配头型和压发区域。摘帽恢复同一发型。 |
| 手 | 手形 ID、大小、惯用手 | 手掌宽度、指长和袖口适配由外观资产记录。动作使用统一的手腕、指骨和握持点，各手形单独校准局部偏移。 |

存档记录版本和稳定的部件 ID。现有四个五官索引可映射到原部件，新字段使用默认值。脸部编辑使用半身近景，体型和手部动作提供全身及斜侧面预览。

## 通用交互手

手指先做拇指、食指、其余三指三组控制。手形决定外观，姿态预设决定指骨如何张开或合拢，动作负责接近和回收，握持点与接触点负责对位。每只手有握持、捏取、食指尖、掌面四个局部锚点。道具提供自己的把手、按压面或交接点。

| 动作 | 可复用约定 | 验收 |
| --- | --- | --- |
| 打招呼、指向 | 自由手势使用基础动作和手指预设。指向使用食指朝向。 | 正面及斜侧看动作是否可辨，检查食指反弯。 |
| 按键 | 食指端点接近按钮面，在接触窗口内下压并撤回。 | 看端点与按压面、下压方向、手掌间隙。 |
| 拿杯、递物 | 手接近道具握持点，闭手后携带。交接帧更新携带方，再松手和回收。 | 三种体型各用左右手重放，量杯柄接触，检查道具漂移和易手跳位。 |
| 双手操作 | 主手持物，副手对道具的第二接触点求解。 | 腕肘不穿躯干。目标不可达时保持道具原位。 |

所有动作按接近、接触、保持或操作、释放、回收的阶段描述。角色可用不同的手掌造型和动作幅度表现差异，接触点在操作阶段仍满足同一套约定。现版店员已有指骨，可见的手是整块手部网格。捏、按、抓需要可变形的手指资产，首轮在至少两种手形上验收。

## 接入选择

现有 State、EventWhen、Effect 和 Visibility 能运行有限整角色变体。本地 Model3D 提供模型键、等比缩放和整体着色，Anim3D 管实体变换。远端主线已有 Attach3D 和 IK3D，提供骨骼挂接和两段手臂求解，可用性仍需在 Game 628 骨架实测。主线 RenderBinding3D 的目标目前覆盖光照、溶解、粒子频率和光晕透明度。

- **A · 通用角色装配，推荐。** 在同一骨架上解析版本化外观字段、挂接件和有界连续参数，道具沿用现有挂接与 IK 接缝。需要引擎负责人审核组件契约及加载性能，居民编辑、街景和其他游戏可复用。
- **B · Game 628 专用宿主。** 游戏宿主解释外观数据，继续依赖现有模型和动画加载。更快验证单款游戏，部件适配、存档兼容和引擎升级回归由 Game 628 承担。

首条完整原型用同一角色组合验证三件事：切换身形、换帽后恢复头发、在不同体型上用同一个动作拿杯并递出。
