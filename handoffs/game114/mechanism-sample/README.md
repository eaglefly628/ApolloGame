# 百工机关 · Apollo 3D 渲染演示

已实现原创低模机关龟、机关牛、房屋、树石和拾取木材。默认庭院场景以绘本风格底图承载群体寻路演示；牛群压力场景接入网格寻路、ORCA 避让与圆形硬碰撞。早期河流/木桥版本保留在独立参考包中。

## 查看

本机服务：http://127.0.0.1:5187/ 。重启：在本目录 `npm run dev`。默认打开可驾驶的庭院试战；`?scene=garden` 查看原来的庭院对冲压力测试，`?scene=stress` 查看开放战场。
重新生成模型：`npm run models`；验证资产：`node verify-models.mjs`；构建：`npm run build`。运行 `npm run verify:play` 检查主路径巡逻、键盘驾驶与建筑阻挡；`npm run verify:garden` 重放庭院对冲 64/128 头牛；`npm run verify:battle` 保留开放战场测试。

## 绘本庭院（2026-10-13）

根据用户提供的氛围参考，生成原创庭院底图；默认九宫格使用边缘透明的绿草与暖白道路版本 `public/textures/garden-map-v4.png`，由 `garden-assets.json` 登记为本地贴图资源。九块贴图覆在一整块草地底层上，道路在跨格处由暖白色连接带接合；相机从原先偏离正顶视 15° 再倾斜 15°，当前约为 30°。默认场景的可行走数据由 `play-scene.ts` 将 64×64 网格镜像铺成 384×384 网格；每块建筑和围墙占 811/4096 格，约 19.8%，其余约 80.2% 可移动。九块都有对应的不可见硬碰撞体；移动单位使用圆形碰撞、ORCA 和路径重规划。底图中的细小花木目前只是视觉元素，不单独阻挡；房屋仍是画在地面上的二维美术，未建成可绕视角观察的三维模型。

默认布局验证九宫格主路径：三条东西向和三条南北向巡逻线按当前底图的道路两侧草地边界求中点，航点存于 `road-centrelines.json`；岔路口保持路线连续，共用路段使用同一条中线。路线跨越格子接缝，在岔路交错避让。路径只用细线、路点和方向箭头标注，可一键隐藏。初始 36 辆小型机关巡逻车遍布九格，可用 `+2`、`−2`、`×2` 调整到最多 96 辆，使用 PathFollow、按对方圆形尺寸提前偏移的 ORCA 与圆形硬碰撞。大车由 WASD / 方向键驾驶。此布局不放牛；牛群只在 `?scene=garden` 和 `?scene=stress` 中作为独立寻路压力测试。巡逻车仍是临时 NPC 占位造型，尚无吞噬、伤害、升级或胜负循环。

没有调用第三方模型生成服务或建模软件。`build-models.mjs` 使用项目已有 Three.js，直接创作几何、材质和动画，输出六种原创 GLB。全部模型和动画可重建，报告见 model-report.json / validation.json。

## 引擎接入

当前演示消费本仓库引擎的 Engine、ThreeRenderer、AssetManager、ModelAssetLoader。模型通过 AssetManager 的本地 key 注册并由 Model3D 加载；机关牛步态由 AnimState3D 播放，整车和牛群的位移由 PathFollow、ORCA、硬碰撞共同驱动。没有修改引擎渲染器。

目前单独 sample 已运行，但没有挂入原项目 launcher 的 game-i 菜单。原工作树存在其他游戏的未提交改动；集成应将本演示蓝图和资产目录登记到指定 sample 的独立模块，不需要改渲染器。

## 动画

GLB 内有四个车轮、两座弩台、投石臂，共七条节点旋转动画轨道，8 秒循环；无需骨骼绑定。车体转向时全部 GLB 部件跟随。动画目前是展示循环，不包含攻击判定或战斗状态切换；动画里的发射动作不能替代模拟层伤害事件。

## 画面边界与验证

地面和场景块使用引擎 toon 三阶材质。导入 GLB 保留自带的低模平面法线与粗糙 PBR 材质：当前 Model3D 不直接消费 Material3D 的 toon 设置，因此尚未宣称整车是三阶 cel 着色；没有私改 ModelPool 绕过此边界。

这是概念图的低复杂度实机初版，屋顶、龟甲和武器造型仍需细化；没有复刻概念图的 HUD、弹道或战斗。所有资产原创，不使用参考游戏素材。

六个 GLB 的容器、内嵌缓冲与七条动画轨道校验通过；Vite production build 通过（共享渲染包超过 500 kB 有体积警告）。64/128 头场景做了固定步长数值检查，仍需在正式目标设备上测试渲染帧率。

## 材质与阴影细化

`build-textures.py` 用 Python 标准库创作可平铺的 512×512 木纹与草地 PNG。木纹内嵌到机关、房屋等 GLB 的基础色材质，草地通过 ImageAssetLoader 与 Material3D.map 接入；树石保持原来的低模材质和几何。当前战场地面宽 110，阴影贴图 4096；放大取景后尚未做跨设备的阴影精度与帧率测试。

## 2026-10-09 导航接入

当前版本改为消费正式项目引擎（vite.config.mjs 的 engineAliases 指向项目根），旧 engine-review 快照仍完整保留。动态模型用共享网格 + A* + 通用 ORCA + 离散碰撞，原有轨道版本入口源码保留为 main-before-navigation.ts。导航数据为 navigation.json，世界组装为 scene.ts。刷新页面从初始位置重新演示。

此变更发生在交接哈希核验之后，因此 transfer-manifest.json 仍是原始交接基线，不表示后来编辑的样例与原件相同。原始 task-2 成果未修改。

## 当前压力演示（2026-10-12）

地图使用一张 128×128、格边 0.5 的 `NavigationGrid`。底图在本压力场景中保持开放，仍有道路/草地 cost 1/2；移动单位占用给 A* 回路追加软代价。16 头基础牛分上下各 5、左右各 3，浏览器启动时补成 64 头；多条平行路线形成交叉编队，大车横穿战场。偏离路线时流场和 A* 帮助回路，每条牛道优先给侧边更空且能算出回路的 2 头牛绕行名额；之后由 ORCA 与圆形硬碰撞处理单位间避让。车继续用速度惯性限制急转。

左上角按钮可显示/隐藏路线与 RVO 规避矢量，还可轮换查看纵向牛道、横向牛道和大车道的流场：亮箭头为底图 cost 1 的道路方向，灰箭头为 cost 2 的场地方向，橙框为移动单位当前占用的格子（A* 额外软代价）。箭头只表示静态流场，橙框不会使箭头实时转向；场数据更新时箭头重建，占用框每 8 个画面更新周期采样。路线矢量默认收起；每次增减 4 头牛或从 64 头翻倍到 128 头。刷新页面可从 64 头初始编队重播。`npm run verify:navigation` 验证基础 16 头，`npm run verify:stress` 验证 32 头，`npm run verify:battle` 验证 64/128 头。

牛群沿用早期 16/32 头场景筛选出的参数：ORCA 预测时长 37、偏离原路线 2.5 单位后启动 A* 回路、占用格软代价系数 0.45。历史搜索结果在 `navigation-tuning-results.json`，不把它当作新开放战场的全局最优证明。当前场地 64 头连续 600 步全部单位有位移、圆形最深重叠约 0.0001、模拟单步 p95 约 12.6 毫秒；128 头同样全部有位移、最深重叠约 0.0024、p95 约 16.3 毫秒。计时只包括无渲染的模拟步骤，终端机器与浏览器实际帧率可能不同。

`build-battle-navigation.mjs` 可重建当前开放战场的路线和网格数据。以前的桥口场景与流场截图属于历史阶段：[流场与边缘重规划](edge-repath-preview.jpg)。当前仍只是移动/规避压力演示，没有攻击、伤害或吞噬规则。
