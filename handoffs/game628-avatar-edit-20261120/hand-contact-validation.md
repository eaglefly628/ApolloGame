# G628-AVATAR-EDIT 手部接触验证

使用原有角色骨架与 Game 628 活动 IK 候选的两段求解器。本票复制求解器快照用于离线资产制作，摘要为 `4c7b3c58e4de123d2fa4b9deaec42bf6bd34811b5d5f98116470d19a856b1249`。动作以 30 Hz 烘焙，导出后由 GLTFLoader 和 AnimationMixer 以 60 Hz 回放重新量取手和道具节点距离。

现有可见手为刚性手网格。按按钮用掌部支撑点，拿杯和递物用手侧支撑点。释放距离取动作末尾一帧的锚点分离量。这个数值只度量命名锚点，完整网格碰撞、分指闭合和任意目标实时跟踪尚未验收。

接触时间窗以秒计。拿杯右手 0.80–2.40，按按钮右手 0.80–1.65，递物右手 0.80–2.20、左手 1.75–3.15。递物在最后一个释放动作后保留观看时间。

## 运行时能力核对

本地检出的 Model3D、AnimState3D 和 Visibility 可以播放已经烘焙的 glTF 轨迹。3D 手册的 Path3D 移动的是实体整体，Timeline 可以安排时间点。两者都无法用当前角色的实时指尖／掌面接触决定按键或道具持有权。远端主线已有 Attach3D 和 IK3D，可作为实时挂接和求解的底座，当前候选没有接入那套运行时。

A 路线复用远端挂接与 IK，再由共享交互契约处理碰触触发、持有权与跨体型姿态，收益为同一套数据可供居民和其他场景使用。B 路线在 Game 628 宿主接入道具动作，单场景试错成本较低，后续则由项目维护时序、接触与引擎升级兼容。建议保留 A，等待原有裁决流程。披风同样由独立布料线消费已交付的编辑器数据契约。
