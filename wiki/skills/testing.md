# 游戏测试模块知识

> 覆盖：测试分类学、测试代码质量、覆盖映射、flakiness、QA 证据分级、bug/试玩流程
> 主要参考：CCGS 框架三线深读（2026-07-04·蒸馏去向见 reference-claude-game-studios.md §八）+ 行业惯例
> ⚠ 分工：本文=行业知识；「在 ZeroCraft 怎么测」查 `docs/playbooks/testing.md`。

## 核心原则

- 游戏测试四类目录法：**unit**（纯逻辑）/ **integration**（系统协作）/ **performance**（帧预算·基准）/ **playtest**（人玩·主观反馈结构化）。
- 证据两级：**BLOCKING**（挡门·逻辑与数值改动的自动测试）与 **ADVISORY**（存档·截图/走查/签核·视觉与手感）。禁双向越界：逻辑改动只交人肉走查=不合格；advisory 项当 blocking 用=过度门禁。
- **「无法验证 ≠ 通过」**：缺基线/缺设计目标/机器测不了 → 判黄（CONCERNS / MANUAL CHECK NEEDED），绝不默认绿，也**绝不编造目标值**。
- 判词=闭集 token（PASS / PASS WITH WARNINGS / FAIL 等），机器可 grep、配退出码；不用散文结论。

## 测试代码质量五标准（审计闭集）

1. 命名 `test_[系统]_[场景]_[期望]`；
2. Arrange / Act / Assert 三段结构；
3. **确定性：真实时间等待（sleep/timer 墙钟）与外部 IO 直连 = FAIL 级违规**（信号/mock 替代）；
4. 隔离：不依赖全局单例、不依赖测试间顺序；
5. 无内联魔数（fixture 常量化；边界测试除外）。

- 测试工厂函数：已知默认值（`createPlayer(health=100)`）、依赖注入、默认值溯源设计数据；已有 helper 扩展不替换。

## 覆盖映射与回归

- **验收标准 ↔ 测试双向对账**：每条 AC 至少一条点名断言；缺口列名字（不笼统"补测试"）；关键路径 AC 无测试=CRITICAL GAP 挡关单。
- 反向：无 AC 对应的测试标 **ORPHAN**（advisory·可能属过去/将来的需求），不静默删。
- **靶向回归**：改动后先跑受影响系统的定向清单（每条=测什么/怎么算过/失败长啥样）；"test everything" 不是尽责是偷懒——全量留给推前门禁。
- flakiness 三源：无种子随机、真时间等待、外部 IO；pass-rate 低于 ~95%（多跑历史）即列嫌疑。

## 持久化边界用例清单（存档/回放必测）

三类状态往返（写→读→比对）· 覆盖已有档 · **旧版本档向后兼容**（migrate 链）· **损坏档优雅拒绝**（不 crash、可报错）。

## 性能与基准纪律

- **尖峰与均值分治**：均值达标但尖峰超预算=黄不算过；超标帧按帧号点名。
- **预算外置**：帧预算/体积预算/数值公差写在机读数据一处，审计器只读不内嵌；**偏差超公差 2 倍机械升 HIGH**。
- **delta 制度**：同场景保留上次结果，每次自动出 prior vs current 差值与回归判定（改善也记录），防温水退化。
- 过关项也列 PASS 行——证明查过，而非没查。

## bug 与试玩流程

- bug 单 7 必填：Title / Repro / Expected / Actual / Severity / System / Build；缺复现标 NEEDS REPRO INFO 留表内；crash 一律 CRITICAL；先查重后立单；多系统 bug 一张单多标签。
- triage：先严重度、同级最旧优先；疑似重复只互标不合并不删。
- 试玩报告四段：手感与可及性 / Bug / 设计反馈 / 下一步——bug 与设计反馈**分流**（QA 不裁决设计）；多测试者标多数/少数派（如 2/3）。
- **不可测的验收标准（"手感直观"类）不许自行发明解释**：打回并附 2-3 个量化替代供拍板。
- 关单遗留：任何"这条以后补"的延期项必须登记来源并自动汇入欠账/补丁盘点，防关单即蒸发。

## 常见陷阱

- 测试全过但覆盖有洞就宣绿（MISSING 要显式列名并绑定关单条件）。
- 前置缺失还半跑出残表（应 fail-fast 非零退出 + 指路补救命令）。
- 均值绿掩盖尖峰红；只报坏项不列 PASS 行。
- 把编排/编纂类廉价活跑在高档模型上（触发条件机械的活配低档）。
