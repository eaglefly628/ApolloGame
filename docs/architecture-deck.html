Paradigm Shift

传统游戏 vs Apollo 游戏

❌ 传统游戏引擎

  • 渲染管线 — 自己写 Canvas/WebGL/3D 渲染
  • 美术资产 — 精灵图、3D 模型、动画序列帧
  • 逻辑与渲染紧耦合 — 加个特效改三层代码
  • AI 是辅助工具 — 生成素材，人来集成

成本：百万级美术预算，画面品质锁死在开发时刻

→

✅ Apollo 模式

  • AI 视频模型 = 渲染器 — 不写一行渲染代码
  • 语义指令 = 美术资产 — 描述场景，模型生成画面
  • 逻辑与画面彻底分离 — 引擎只管状态和控制
  • AI 是核心引擎 — 视频模型进化 = 画质升级

成本：近乎零美术成本，画面品质随 AI 模型自动升级

核心洞察：视频生成模型正在以指数速度进化。
不自己写渲染 = 搭上了 AI 视觉能力的增长曲线。

Director Protocol

场景导演 — 语义到视频的桥梁

Director 不生成像素。它把 ECS 状态翻译成视频模型能理解的语义指令。 随着视频模型进化，同样的指令产出越来越好的画面。

// Director 输出的场景描述（喂给视频模型） { "scene": { "style": "dark fantasy, cinematic", "camera": "side-view, slight low-angle", "environment": "ancient stone arena, torchlit" }, "regions": [ { "id": "hero", "bounds": [0.05, 0.15, 0.40, 0.70], "content": "armored warrior, standing", "reference": "ref://hero-001.png", "motion": "raising sword to strike" }, { "id": "boss", "bounds": [0.55, 0.05, 0.95, 0.75], "content": "massive red dragon", "reference": "ref://dragon-001.png", "motion": "recoiling from hit" } ], "relations": [ { "from": "hero", "to": "boss", "type": "attacks", "visual": "sword slash energy arc" } ] }

📍 SceneRegion

屏幕上的语义区域。用归一化坐标 [0,1] 定义。告诉视频模型"这块区域应该出现什么"。

🎬 SceneContent

区域内容描述 + 参考图 + 动作指令。参考图保证角色形象一致性。动作描述当前状态。

🔗 SceneRelation

区域间的语义关系："攻击"、"治疗"、"连接"。视频模型据此生成跨区域的视觉效果（能量弧、光束...）。

🎥 CameraDirective

镜头语言：俯视/侧视/特写、平移/缩放/切换。电影级镜头控制，无需 3D 引擎。

🔄 Temporal Coherence

参考图 + 上一帧输出 = 时间连续性。角色不会帧间突变。随模型进化不断增强。

Semantic Protocol

Component 语义词汇表

每个 Component 有语义分类。AI 看到分类就知道如何使用 — 资源绑进度条，场景喝视频模型，事件触发一次后消失。

语义分类 Component 类型签名 用途 / AI 理解
Resource Health { current, max } 有上限的数值 → 绑定进度条 → 可被增减
Event DamageEvent { amount, damageType } 一次性触发 → 被 consume 后消失
Intent AttackIntent { target: EntityId } 来自外部输入 → 被 System 转化为 Event
Marker Dead { } 存在即有意义 → 触发死亡逻辑/UI
Scene SceneRegion { bounds, zIndex } 屏幕语义区域 → 视频模型的空间指引
Scene SceneContent { description, ref, motion } 区域内容描述 → 参考图 + 动作指令
Scene SceneRelation { from, to, type, visual } 区域间关系 → 跨区域视觉效果（光束、攻击）
Scene CameraDirective { angle, focus, transition } 镜头语言 → 电影级叙事控制
Config Attacker { baseDamage, target } 长期存在 → 描述实体属性

AI-Native

双 AI 架构 — LLM 设计 + 视频模型渲染

1

🧠 LLM 读取 Capability 清单

"有 health（资源，current/max）、damage（事件，读 AttackIntent 写 DamageEvent）、director（场景，读状态写指令）..."

2

📝 LLM 生成新 Capability + Assembly

输出 PoisonCapability：声明 writes: [DamageEvent]，每回合自动产生伤害。同时输出 Assembly 蓝图，一键实例化。

3

🎬 视隑模型生成画面

Director 把 ECS 状态翻译为场景描述 → 视频模型（Sora / Kling / Runway）生成连续画面 → 叠加 UI = 完整游戏
