# Game B：乙游视觉小说（Otome Visual Novel）

> 负责人：PB（Programmer B）
> 定位：引擎验证游戏 — 压测状态机 + 叙事分支 + 资源管理 + UI 系统
> 参考：Persona 系列、火焰纹章支援、恋与制作人、万千心途

---

## 一、游戏概要

玩家扮演一位新人制作人，在娱乐圈中经历事业成长与情感纠葛。通过做选择推进剧情，管理属性资源，与不同角色发展关系。核心体验是"每个选择都有代价，每段关系都有重量"。

**一句话描述**：娱乐圈背景的乙女养成，选择驱动剧情，属性决定命运。

---

## 二、核心设计

### 2.1 角色设定

| 角色 | 定位 | 关系线 |
|------|------|--------|
| 玩家（女主） | 新人制作人 | — |
| 角色 S | 高冷前辈导演 | 事业线 — 帮助成长但要求严格 |
| 角色 T | 阳光偶像艺人 | 社交线 — 真诚但有秘密 |
| 角色 U | 神秘投资人 | 悬疑线 — 背景复杂、亦正亦邪 |

每个角色有独立的好感度线和专属事件。

### 2.2 核心循环

```
┌─────────────────────────────────────────────┐
│                                             │
│  ┌─────────┐    ┌──────────┐    ┌────────┐  │
│  │ 日程选择 │───→│ 场景/事件 │───→│ 结算   │  │
│  │(分配行动)│    │(对话+检定)│    │(数值变化)│ │
│  └─────────┘    └──────────┘    └────┬───┘  │
│       ↑                              │      │
│       └──────────────────────────────┘      │
│              下一周期                        │
└─────────────────────────────────────────────┘
```

#### 日程选择（每周期开始）

玩家从可用行动中选择一个：
- **工作**：提升事业值，可能遇到事业事件
- **社交**：拜访某角色，提升好感度
- **学习**：提升属性（魅力/智慧/体力）
- **休息**：恢复体力，可能触发随机事件

#### 场景/事件（行动展开）

- 进入对应场景，触发对话
- 对话中有选择分支
- 关键节点触发**检定**（属性 + 好感度 + 骰子）

#### 周期结算

- 消耗体力
- 好感度变化结算
- 检查是否触发阈值事件（好感度 30/60/90）
- 推进时间线

### 2.3 属性系统

| 属性 | ECS 映射 | 用途 |
|------|---------|------|
| 魅力 | Resource { id: 'charm' } | 社交检定、角色好感加成 |
| 智慧 | Resource { id: 'wisdom' } | 事业检定、选项解锁 |
| 体力 | Resource { id: 'stamina' } | 行动消耗、过低无法行动 |
| 事业值 | Resource { id: 'career' } | 解锁新场景、影响结局 |
| 好感度 S | Resource { id: 'affection_S' } | 角色 S 关系进度 |
| 好感度 T | Resource { id: 'affection_T' } | 角色 T 关系进度 |
| 好感度 U | Resource { id: 'affection_U' } | 角色 U 关系进度 |

### 2.4 检定系统

玩家做关键选择时，成败取决于属性：

```
检定分数 = 基础属性值 + 好感度修正 + 随机(1-20)
通过阈值 = 难度值（按剧情进度递增）
```

- 成功：剧情走好路线，好感 +，可能解锁隐藏选项
- 失败：剧情走坏路线，好感 -，但可能开启另一条支线
- 关键：**失败不是 Game Over**，而是走向不同的故事

### 2.5 好感度阈值事件

| 阈值 | 触发 | 内容 |
|------|------|------|
| 30 | 认识深入 | 角色分享个人故事，解锁新对话选项 |
| 60 | 关系升温 | 关键情感事件，需要做重大选择 |
| 90 | 最终事件 | 告白/决裂/合作高潮，影响结局 |

### 2.6 结局系统

根据最终周期结算时的数值组合：
- **事业结局**：事业值最高 → 成为顶级制作人
- **角色结局**（×3）：某角色好感最高 → 与该角色的专属结局
- **隐藏结局**：三线平衡 + 全检定通过 → 特殊完美结局
- **失败结局**：体力归零 / 所有好感低于 20

## 三、开发路线（与引擎迭代对齐）

| 版本 | 引擎依赖 | 游戏交付物 |
|------|---------|-----------|
| **v0.1** | state, text, input, action-map | 一个场景、一段对话、打字机效果、一个选择 |
| **v0.2** | resource, resource-modify, ui-binding | 属性面板 + 好感度显示 + 选择影响数值 |
| **v0.3** | flag, timer, state-changed | 日程系统 + 周期结算 + 阈值事件触发 |
| **v0.4** | random-seed（检定骰子） | 检定系统 + 成功/失败分支 |
| **v0.5** | scene-management, animation | 多场景 + 角色立绘 + 表情切换 + 过渡动画 |
| **v0.6** | UI theming (sakura-otome) | 完整 UI 套装：对话框、选项、属性面板、好感度 |
| **v1.0** | serialization | 存档/读档 + 多结局 + 完整一周目（10 个周期） |

## 四、引擎验证重点

Game B 特别压测以下引擎能力：

| 引擎能力 | 怎么压测 |
|---------|---------|
| **state 状态机** | 游戏状态（日程/对话/检定/结算）+ 角色情感状态 |
| **resource 系统** | 7+ 种资源并存，频繁修改，阈值触发 |
| **resource-modify 事件链** | 选择 → 修改好感 → 检查阈值 → 触发事件，多级联 |
| **flag 条件网络** | 选过什么、见过谁、解锁了什么 — 大量 flag 交叉判断 |
| **text + 对话系统** | 长文本、打字机、分支对话树、角色名标签 |
| **UI binding** | 7+ 个资源实时反映到 UI，属性面板、好感度条 |
| **UI theming** | sakura-otome 主题全套组件实战验证 |
| **scene-management** | 多场景切换（日程→场景→结算→日程） |
| **serialization** | 复杂状态存档（资源 + flag + 好感 + 剧情进度） |
| **random-seed** | 检定骰子确定性，存档重放结果一致 |
| **timer** | 周期倒计时、打字机速度、过渡动画计时 |

## 五、对话数据格式

对话内容存在 JSON 中，数据驱动：

```json
{
  "scene_01_meeting_S": {
    "speaker": "S",
    "lines": [
      { "text": "你就是新来的制作人？", "emotion": "neutral" },
      { "text": "我对新人不抱期待。", "emotion": "cold" }
    ],
    "choices": [
      {
        "text": "我会证明自己的。",
        "effects": [{ "resource": "affection_S", "amount": 5 }],
        "next": "scene_01_impressed"
      },
      {
        "text": "请多指教。",
        "effects": [{ "resource": "affection_S", "amount": 2 }],
        "next": "scene_01_polite"
      },
      {
        "text": "（沉默）",
        "check": { "attribute": "charm", "difficulty": 15 },
        "successNext": "scene_01_mysterious",
        "failNext": "scene_01_awkward"
      }
    ]
  }
}
```

## 六、美术方向

- 风格：日系乙游风格立绘 + 柔粉色调背景
- 立绘：每角色 3-5 种表情差分（neutral/smile/angry/blush/shock）
- 背景：简单场景图（办公室/咖啡厅/录影棚/街道）
- UI 主题：sakura-otome（樱花乙女套装）
- MVP 阶段可用纯色块 + 文字代替立绘，先验证系统
