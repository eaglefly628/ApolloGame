# Game A：双人协作冒险（Co-op Platformer）

> 负责人：PA（Programmer A）
> 定位：引擎验证游戏 — 压测实时协作物理 + 平台跳跃 + 机关交互
> 参考：双人成行 (It Takes Two)、传送门 2 (Portal 2 Co-op)、Unravel Two

---

## 一、游戏概要

两个玩家各控制一个角色，在手工设计的关卡中通过跳跃、解谜、协作通关。核心体验不是打怪，而是"两个人必须配合才能前进"。每个关卡引入一种新的协作机制，保持新鲜感。

**一句话描述**：两个能力互补的角色，只有合作才能通过越来越巧妙的关卡。

---

## 二、核心设计

### 2.1 双人操控

| 角色 | 按键 | 能力特点 |
|------|------|---------|
| 角色 A（蓝） | WASD + Space 跳 + E 交互 | 轻巧：二段跳、可钻小洞、不能推重物 |
| 角色 B（橙） | 方向键 + / 跳 + . 交互 | 力量：推重物、举起A抛射、不能二段跳 |

- 同屏共享画面（相机取两人中点，动态缩放保证都在视野内）
- 两人离太远时相机拉远提示，超过极限距离则限制移动

### 2.2 协作机制库

每关围绕一个核心机制设计，以下是机制池（按开发顺序排列）：

#### 第一批（v0.1-v0.2，基础协作）

| 机制 | 描述 | 引擎原子 |
|------|------|---------|
| **踩开关** | A 站上开关（触发区），B 侧的门打开；A 离开则关闭 | trigger-zone + flag |
| **限时门** | 开关激活后 N 秒关闭，另一人必须在倒计时内通过 | timer + flag |
| **重量台** | 需要两人同时站在台上才激活（检测两个实体重叠） | trigger-zone + tag |

#### 第二批（v0.3，能力差异）

| 机制 | 描述 | 引擎原子 |
|------|------|---------|
| **抛射搭档** | B 举起 A → 按交互键抛出 → A 飞到高平台 | relation + velocity 覆写 |
| **小洞通道** | 只有 A 能钻过的窄缝，到对面按开关让 B 绕行 | shape 大小 + collision |
| **推箱垫脚** | B 推动重箱到指定位置，A 踩箱跳上高台 | mass + collision-separate |

#### 第三批（v0.4-v0.5，进阶协作）

| 机制 | 描述 | 引擎原子 |
|------|------|---------|
| **弹性绳索** | 两人之间有绳（距离约束），可利用摆荡过悬崖 | relation + 距离约束 |
| **跷跷板** | 杠杆平台，一端踩下另一端弹起，配合时机弹射搭档 | 旋转 + 碰撞 + timer |
| **传送镜** | A 走进左镜出现在右镜位置，B 反之 | trigger-zone + transform 覆写 |
| **风扇/气流** | B 举盾挡住气流改变方向，A 借气流飘到对岸 | acceleration + flag |

#### 第四批（v0.6+，环境挑战）

| 机制 | 描述 | 引擎原子 |
|------|------|---------|
| **追逐关** | 巨石/怪物从后方追来，两人必须一起跑 + 配合过障碍 | AI + timer + velocity |
| **Boss 协作** | 一人吸引 Boss 注意，另一人攻击弱点 | AI chase + health + projectile |
| **连锁反应** | A/B 各触发一端的机关，在中间汇合产生效果 | state + timer 同步 |

### 2.3 关卡结构

```
世界 1：基础跳跃（3关）— 熟悉操控 + 踩开关
世界 2：能力互补（3关）— 抛射 + 推箱 + 小洞
世界 3：绳索与弹射（3关）— 弹性绳 + 跷跷板 + 传送
世界 4：综合挑战（3关）— 混合机制 + 追逐 + Boss
```

每关 2-3 分钟通关时间。失败重试从最近检查点开始。

## 三、开发路线（与引擎迭代对齐）

| 版本 | 引擎依赖 | 游戏交付物 |
|------|---------|-----------|
| **v0.1** | collision, gravity, controllable, input | 双人移动 + 跳跃 + 几个平台，能跑能跳 |
| **v0.2** | trigger-zone, flag, timer | 3 个开关关卡，基础协作可玩 |
| **v0.3** | relation, velocity 覆写, shape 差异 | 抛射 + 推箱 + 小洞，能力差异体现 |
| **v0.4** | tilemap, scene-management | 用 Tiled 设计关卡，场景切换 |
| **v0.5** | particles, animation, camera | 双人相机、角色动画、特效打磨 |
| **v0.6** | health, knockback, AI patrol | 环境敌人、追逐关、Boss |
| **v1.0** | serialization, checkpoint | 存档、关卡选择、完整 4 世界 12 关 |

## 四、引擎验证重点

Game A 特别压测以下引擎能力：

| 引擎能力 | 怎么压测 |
|---------|---------|
| **双人输入** | 两套键位同时操作，不能冲突 |
| **trigger-zone** | 大量开关/机关触发区，进出检测要准确 |
| **flag 联动** | A 的动作影响 B 的环境，flag 传递链 |
| **碰撞精度** | 平台边缘跳跃手感，coyote time |
| **相机系统** | 双人动态相机，缩放 + 跟随 + 边界 |
| **timer 精度** | 限时机关的倒计时必须确定性一致 |
| **relation** | 抛射搭档、绳索连接等实体间动态关系 |
| **scene-management** | 关卡切换、检查点、进度保存 |

## 五、美术方向

- 风格：简洁几何体（方块人 + 圆形头），彩色区分角色
- 关卡：线条 + 纯色方块，重功能不重美术
- 主题色：A 角色蓝色系，B 角色橙色系，环境灰色系
- 机关：开关绿色亮/灰色暗，门打开/关闭状态明确
- UI 主题：minimal-dark（默认）

## 六、验收标准

- [ ] 两人同屏操控流畅，无输入冲突
- [ ] 至少 6 种协作机制可玩
- [ ] 至少 6 个手工关卡通关
- [ ] 所有关卡 tick 确定性（hash 一致）
- [ ] 存档/读档正常
- [ ] 场景切换无泄漏
