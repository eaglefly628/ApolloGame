## 1. 设计纪律（最高优先 · 加任何复杂度都不许破这几条）

1. **深度藏系统、决策摆明面（readability 铁律）**：系统可以六层乘算，但玩家每回合的决策必须**2 秒看懂**。敌人**属性/弱点/抗性/本回合攻击全明牌**（图标+颜色+大白话）；新手期直接提示"水系骰在这有效"。
2. **对随机的掌控权（防挫败）**：需要特定颜色却掷不出 = 最易让随机变挫败。**重掷/锁定/变色/商店买对色骰**必须够——前两小关就是攒"对色掌控力"的。
3. **结构锁、内容迭代**：骨架（攻防两层、四层乘算、骰子轴）定了别推翻；档位/数值/清单靠玩调。
4. **复杂度 = 数据，不是新引擎能力**：骰属性/抗性/攻防分配全是数据。系统再复杂，引擎不变，只是数据更丰富（数据驱动宣言）。

## 2. 骰子模型

- **一颗骰 = 6 面，每面 =（数字, 颜色）**。颜色 = 元素。
- **骰子库** = 通用骰（彩虹·6 面 6 色）+ 特制骰。
- **骰子属性轴**（任何骰 = 这几根轴上一个点·纯数据 schema·往里塞无穷骰也不乱）：
  | 轴 | 取值 | 例 |
  |---|---|---|
  | 颜色分布 | 彩虹 / 单色 / 半半 / 加权 | "某属性骰" |
  | 数值分布 | 标准 / 高滚 / 低而稳 | "点数小" / "点数大" |
  | 代价 | 免费 / 损耗 / 一次性 / 蓄力 | "消耗性很高" |
  | 特效（可选） | 附带小规则（掷 6 再掷…） | 稀有花头 |
- **构筑张力**：彩虹骰=灵活难凑大同色；单色专精骰=押注一元素换大倍率但僵硬。

---

## 3. 骰斗回合骨架（结构锁 · 攻防两层挂在第 3 步）

1. **明牌**：敌人亮出 属性 / 弱点 / 抗性 / 本回合攻击（元素+威力）。
2. **掷 & 筛**：两人掷骰池，锁定想要的、重掷其余，组装（快艇骰式）。
3. **分配（攻/防两池）**：
   - **攻击池** → 砸敌人血：`伤害 = Σ点数 × 颜色组合倍率 × 弱点系数 × 小丑修正`
   - **防御池** → 挡敌人本回合攻击：对的属性挡最有效；没挡住的扣**队伍生命**
   - **核心张力**：骰子永远不够两边分 → 速杀(全压攻击·硬吃伤害) vs 稳扎(先防·慢磨)；两人分工谁攻谁防。
4. **结算**：敌人掉血、你掉没挡住的血、套小丑/道具、判胜负。
- **退化基线**：最简单 = 点数直接扣血（你说的地板逻辑永远成立）。

## 4. 伤害公式骨架（数值档位待 playtest）

```
最终伤害 = (Σ 投入点数)            ← 加法地板
         × 颜色组合倍率            ← 3同色×2 / 5同色×3 / 6同色满色(1-6)×5  [档位待调]
         × 敌人弱点系数            ← 弱点×2 / 抗性×0.5或仅加法 / 免疫→挡掉
         × 小丑修正                ← buff 层（order 待定）
```
- **防御侧**：对应属性的 block 值，元素匹配增效（公式待怼）。

## 5. 敌人模型

- **元素类型** + 弱点 / 抗性 / 免疫（克制关系）。
- **HP** + **属性护甲**（"抵前 X 点非弱点伤害""对红色免疫"→ 逼换元素）。
- **本回合攻击**（元素 + 威力）→ 玩家要防。
- **Boss 刁难**（专属）：诅咒你的骰、要求伤害奇偶、抗性每轮轮换…→ 让你"很难掷出正确过关组合"。

---

## 6. 局结构：一层 = 3 小关（owner 拍）

- **小关 1、2（备料）**：打小兵 → 掉素材 / 选择 / 合成 / 预准备；**（建议）侦察 Boss 属性** → 针对性囤克制色骰/buff。
- **小关 3（Boss）**：属性 + 刁难拉满，逼你用前两关备好的料才打得过。
- **弧线**：备料 → 构筑 → Boss 检验（"我准备对了！"的爽）。小丑层照旧叠在最上面。

## 7. 呈现 / 关卡流式（owner 2026-06-29 加 · 技术对齐）

- **视图**：固定 **45° 等距(ortho)正视角**，随队伍前进**推进(forward dolly)**。= `Camera3D` 数据配置（ortho + follow + 固定角·**均已支持**）·**render-only 出 hash**。
- **关卡流式**：房间逐个流式加载，**线性前进、不回头**。**关键简化**：房间间的"抽 buff / 商店"**过场 = 天然加载边界**（不需无缝开放世界流式·只需"过场时加载下一房"）。
- **"永不停步" vs 回合制的调和**：宏观永远向前（过场时相机前推 + 流入下一房）；**战斗时相机定在当前房**（回合制掷骰静止）。"永不停步" = 主题/视觉贯穿（线性不回头）。
  - ⬜ **待 owner 确认**：战斗中相机是否也要微推进（"传送带"感）？还是战斗静止、仅过场推进（默认）。
- **确定性切分**：房间序列（哪个房·里面什么）= 确定性 sim（GameFlow + 种子）；前推/加载/卸载 = 纯表现。
- **实现两条路（M0 验证哪条够用）**：
  - **(A) 房间 = prefab 实例**：前方 spawn、身后 destroy（引擎已有 Prefab/spawn/destroy·**可能纯现成能力够**→ 全数据·不报主程）。**赌 A 够。**
  - **(B) assembly 层蓝图 load/unload seam**（**主程域**·若 A 不够才报评审）。
