# Claude Designer 设计描述（Design Brief）

> 面向 AI 设计协作者（Claude Designer）的项目简报。把这份文档作为上下文，即可继续产出关卡表、数值表、技能配置、原型代码等交付物。

## 1. 一句话定位

**game103 · 《幸存者核心原型》**：一款俯视角、单摇杆走位、武器全自动开火的 **吸血鬼幸存者式（Vampire-Survivors-like）割草 Roguelite**。玩家在单局内不断升级、拾取技能、凑齐进化组合，从「被一群怪追着跑」成长为「屏幕清屏机器」，最终在限定时间/波次内活到 Boss 并击杀。参考标杆：Habby《Survivor.io（幸存者！.io）》与《Vampire Survivors》。

## 2. 复刻的是"核心玩法"，不是整包

明确 **In Scope / Out of Scope**，避免范围蔓延：

| In Scope（本次核心） | Out of Scope（后续/不做） |
| --- | --- |
| 单局 15 分钟割草循环 | 账号系统、云存档、社交 |
| 单摇杆走位 + 武器自动攻击 | 内购、抽卡、Gacha 商业化 |
| 经验/升级/三选一 | 复杂剧情、过场动画 |
| 武器 + 被动 → 进化 | 多角色/皮肤养成的完整深度 |
| 敌群刷怪 + 精英 + Boss | PvP、联机 |
| 拾取物（经验宝石/金币/回血/道具） | 大地图探索、开放世界 |
| 单局结算 + 元进度（局外升级）雏形 | 完整活动/赛季运营 |

## 3. 核心体验目标（设计北极星）

1. **"雪球"爽感**：前 60 秒紧张（走位求生）→ 中期滚雪球（技能叠加）→ 后期清屏（碾压快感）。这条功率曲线是全部数值调优的核心。
2. **每局不同**：三选一 + 进化组合带来构筑（build）差异，重开动力来自"这次凑什么流派"。
3. **零学习成本**：唯一操作是"移动"。所有深度藏在升级选择里。
4. **短时高频**：单局 15 分钟内有明确起承转合与胜利/失败判定。

## 4. 给 Claude Designer 的协作指令

当被要求推进设计/实现时，请遵循：

- **先数值、后手感、再内容**：任何机制先给出可调参数表（JSON/表格），再谈实现。
- **一切可配置**：武器、敌人、波次、掉落、进化都走数据驱动配置表，不硬编码到逻辑里。
- **给出具体数字**：不要写"伤害较高"，要写"基础伤害 12，每级 +4"。默认值见 `02-core-gameplay-GDD.md` 的数值表。
- **保持功率曲线自洽**：新增内容时给出它在 DPS 曲线中的定位，说明会不会破坏雪球节奏。
- **交付物结构化**：优先输出配置表（`config/*.json`）+ 简短说明，而非长篇散文。
- **命名与代码风格**：跟随仓库既有约定；未建立时用清晰英文标识符 + 中文注释。

## 6. 技术选型建议（待与工程确认）

- 目标平台：优先 **H5 / 移动端**（触屏单摇杆天然契合）。
- 引擎候选：Web 侧 **Phaser 3 / PixiJS + TypeScript**；或 **Unity（C#）**。默认按 **TypeScript + 数据驱动** 假设撰写配置格式，实现层可替换。
- 架构关键：**大量实体（数百敌人 + 数百子弹）**，需对象池 + 空间网格碰撞，避免 O(n²)。
