## §0 算番总流程（对齐 `yaku.ts::scoreWin` → `fu-score.ts::calcFu`/`limitAndBase`/`buildPayment`）

```
和了手 hand14 + WinContext（自风/场风/立直/自摸/宝牌指示…）
  → ① 分解枚举（enumDecomps）：标准形4面子+雀头 / 七対子 / 国士——多解全取
  → ② 逐解算役（evalInterp）：先判役满（有→直接役满点·不看番符）
                              否则累加各役番 yakuHan
  → ③ 1番缚：yakuHan==0（含只有光宝牌）→ 该解 null（不得和）
  → ④ 宝牌加番：表宝牌 + 赤宝牌 + 裏宝牌（立直和了才计裏）→ totalHan
  → ⑤ 符计算 calcFu：底符→面子符→雀头符→待ち符→自摸/门清荣和→切上
  → ⑥ 基本点 limitAndBase：base = 符×2^(2+totalHan)，封满贯档（见 §6）
  → ⑦ 四家支付 buildPayment：庄/闲 × 自摸/荣和 × 百位切上
  → ⑧ 多解取高（better）：役满 > 点数 > 番 > 符
外层（game-state）：+本场（荣300/自100 每家）+ 供托全归和者 → delta（Σ=0 守恒）
```

**门清定义（实现收口·D6）**：应为「**门前清 = 无吃/碰/大明杠**（暗杠仍算门清）」，**不是**「melds 数组为空」。现状 `settleWin` 用 `melds.length===0` 判闭手 → **含暗杠的门清手被误当开手走占位**（P6b 修·见 §9）。

## §9 实现状态总览 + 缺口工单（**指派：Opus**·P6b 主体）

**现状定性**：**闭手（门前清·无副露）算番引擎 = 完整且正确**（§2-§6 标 ✅ 的役/符/点数全在 `yaku.ts`+`fu-score.ts`，闭手 walkthrough 已绿）。**未落的都在开手/杠/首巡这三片**，且多为**接线**而非算错。按优先级：

### 缺口 G1 · 开手真算分（P6b 主体·最高优先·`naki-design.md P6b`）
现状：`settleWin` 仅 `melds.length===0` 走 `scoreWin`，**开手走占位固定分**。要落真算分需：
1. **`WinContext` 扩展 called-meld 结构**：新增 `melds: {kind:'chi'|'pon'|'minkan'|'ankan'|'kakan', tiles, open:boolean}[]` + `concealedHand: number[]`（暗手）。`scoreWin` 分解时**副露面子固定不再枚举**，只枚举暗手余牌。
2. **门清限定 gating**：`open = melds.some(m=>m.open)`（暗杠不算 open）。`open==true` → 立直/両立直/一発/門前自摸/平和/一盃口/二盃口/七対子 **一律不计**。
3. **喰い下がり**：`open==true` 时 §1 六役各 −1 番（三色/一気/混全 2→1·純全/混一 3→2·清一 6→5）。
4. **暗刻计数修正**：开手的碰=**明刻**，不得计入三暗刻/四暗刻（现从 14 张分解误判所有非荣刻为暗）。四暗刻须「四刻**全暗**（暗杠算暗·碰/大明杠不算）」。
5. **测试**：`mahjong-core-tests.md §3` 带 ◇喰い下がり 行的**副露分支**逐条落断言 + 开手门清限定役反例（开手宣称平和/一盃口→不计）。
6. **验收剧本**：开手真算分落地后我（GD）补一本 `open-hand-scoring.scenario.jsonc`（鸣牌局非占位·真番符）钉死。

### 缺口 G2 · 杠符 + 杠子役（配合 G1·D6）
- `calcFu` 补明/暗杠面子符（8/16/16/32·§5）。
- 「闭手」定义改为「门前含暗杠」（`melds` 仅暗杠时仍走 `scoreWin`）——修 D6「含暗杠门清手被当开手占位」。
- 新增 **三槓子**（2番·§2）、**四槓子**（役满·§3）役判定（`melds` 中杠数 ==3/==4）。

### 缺口 G3 · 九蓮宝燈（役满·spec 与 impl 双缺·本档补）
- 判定：门清清一色 且 暗手计数匹配 `1112345678999` + 任一同色牌。纯正九蓮（9面听）= R-7 单倍（v1）。
- 加进 `yaku.ts` 役满段（`d.form==='standard'` 且单一花色数牌 且 counts 匹配九蓮模板）。
- `mahjong-core-tests.md §3` 役满段**补一行 九蓮宝燈**（现表遗漏）。

### 缺口 G4 · 首巡/一发/两立直 track（`WinContext` 旗未喂真值）
- `ippatsu`/`doubleRiichi`/`tenhou`/`chiihou` 现恒 false/未接。需 game-state 记「立直巡计数 + 首巡无鸣标志 + 一发窗口（被任意鸣牌打断即灭）」并注入 `WinContext`。
- 测试：`mahjong-core-tests.md §8` 一发窗口/裏宝牌/两立直点名。
