# Game D《骰途》· 视觉设计 Brief（交付外部设计师 / Cloud Design）

> **用途**：把《骰途》当前两块核心画面——**①开场 Title 屏** 和 **②塔内场景（gameplay 视图）**——用文字描述清楚，供设计师产出视觉设计（mockup / key art / 色板 / 控件皮）。
> **配套**：世界观与玩法见 `game-d-gdd.md`；UI 实现规范见 `ui-playbook.md`。本文只管「要长成什么样」。
> **基线**：两块都已有可运行的程序化雏形（见 §附·截图），设计师是在**把雏形提升成有质感的美术**，不是从零猜。

---

## 0. 一页速览（设计师 TL;DR）

- **游戏**：《骰途 · 命运之塔》——双人合作 **骰子 Roguelike**。两名「掷命者」结伴攀登一座会改写命运的古塔，**所有战斗用掷骰解决**，一层层往上闯，每层 2 试炼 + 1 守关者(BOSS)。
- **基调**：**奇幻明快 + 一点神秘宿命感**。体素(像素方块)风 + 柔光泛光的**童话微缩模型质感**。**不暗黑、不写实**——温暖、可爱、彩色、一点魔幻。参照气质：《哈迪斯》的精致 + 《弓箭传说》的近俯视战场 + 《奇诺比奥队长》的微缩盒庭 + 《Balatro》的桌面神秘感。
- **要两块画面**：① 开场 Title 屏（品牌门面）；② 塔内场景（近俯视体素竞技场，玩家大部分时间看的画面）。
- **核心美术命题**：**几何永远是廉价的立方体（体素），丰富度全压在「贴图 + 光照 + 色彩」上**——避免高面数建模，做成「带精美贴图的体素世界」（类《我的世界》方块但贴图更精致考究）。

## 1. 游戏与基调（背景给设计师）

- **世界**：命运之塔。塔分多层，每层一处幻境（见 §4 色板：翠庭 / 古殿 / 熔心 / 晶顶…）。玩家**从塔底往塔顶攀登**，画面**往上推进**。
- **主角**：两名掷命者（双人合作；单人则一人掌双骰）。当前用一只 **showcase 小黄鸭**占位（可设定为「塔灵 / 吉祥物」）。
- **战斗**：不挥剑，**掷「命运骰」定胜负**。骰子带**颜色=元素**（火/水/木/雷/风/暗），凑颜色组合克制敌人属性。
- **受众/平台**：桌面 + 触屏，双人同屏友好。明快、易懂、上手快。

## 2. 屏 A · 开场 Title 屏（品牌门面）

> **目的**：第一眼建立「神秘命运之塔 + 骰子 + 双人冒险」的气质，并给出开始入口。

**当前雏形**（见 §附图1）：暗紫渐变底，居中：🎲 + 「骰途」金字 +「命运之塔 TOWER OF FATE」+ 一行 tagline + ▶开始攀塔 + 双人/单人/设置 + 版本号。结构对，**但还是占位字+按钮，没有美术**。

**★ 主视觉 = 一颗活的 3D 滚动骰子（owner 2026-06-29 拍板·这是 3D 游戏，开场要用 3D 骰子）**：
- 屏幕中央是一颗**真 3D 的骰子在缓缓翻滚/旋转**（不是平面 🎲 图标）——立体、有体积、有光影反射，骰面带**颜色=元素**（六色），随滚动露出不同面。它是开场的绝对焦点，第一眼就告诉玩家「这是个 3D 骰子游戏」。
- **技术上可落地**：Title 屏背后可跑一个真 3D 场景（引擎渲染器渲一颗 `Mesh3D`/`Model3D` 骰子 + 光照 + 缓慢旋转），2D UI（标题/按钮）叠在它上面。设计师定骰子的**造型/材质/六色元素的面**与旋转氛围。
- 可叠氛围：发光符文、微粒、柔光，烘托骰子。

**希望设计师产出的其余视觉**：
- **背景**：骰子之后是**神秘高塔的剪影/远景**向上消失在云雾/星空里（呼应「往上攀登」「命运」）。暗色调（深紫/靛蓝/墨）+ 高光点缀，**神秘但不压抑**。骰子在前、塔在后，层次分明。
- **Logo / 标题**：「骰途」做成**有设计感的主标 logo**（可融入骰子点数/塔的意象），配英文副标「TOWER OF FATE」。金色 / 暖光质感，与 3D 骰子一起构成视觉焦点。
- **主按钮**「开始攀塔」：醒目的 hero 按钮（带微光/呼吸感），下方小字「第一层 · 翠庭」。
- **次级入口**：双人同攀 / 单人 / 设置（次要、低调）。
- **氛围元素**：两名掷命者的小剪影站在塔脚？一对发光骰子？由设计师发挥，强化「两人结伴 + 骰子」。
- **情绪关键词**：神秘、期待、温暖冒险、命运感。

## 3. 屏 B · 塔内场景（gameplay 视图 · 玩家大部分时间看的画面）

> **目的**：一屏一个独立战场竞技场，玩家在此掷骰战斗；视角**近俯视**、关卡**往上推进**、房间**一间接一间**。

**当前雏形**（见 §附图2/3）：近俯视(垂直向下偏~30°)的 ortho 等距视角，一屏框住**一座方块竞技场**——地台 + 四面低矮围墙 + 前方出口门洞（通向上一间）+ 中心发光焦点 + 散落色块 + showcase 小黄鸭；柔和软影 + 移轴景深 + 泛光 + 渐变天空。**几何对、构图对，但表面是纯色块、没有贴图美术。**

**希望设计师产出的视觉**：
- **体素贴图**：把纯色方块升级成**带精美贴图的体素**——地面(草/石/熔岩/水晶按层)、墙体、门、装饰，每种材质一套**顶面/侧面贴图**（像《我的世界》方块，但更精致考究、有手绘质感）。
- **每层主题氛围**：见 §4 色板。每层换一套材质 + 光色 + 天空，给「攀塔换景」的递进感。
- **竞技场构成**（设计师给出美术）：
  - **地台 / 地面**：竞技场的「舞台」，要清爽好读（战斗物件要在它上面看得清）。
  - **围墙 + 出口门**：框住「一间房」的感觉；出口门（朝画面上方）要有「通向更高层」的引导感（发光门楣/符文）。
  - **中心焦点**：战斗间放宝物/祭坛，BOSS 间放一座**守关者**（占位是发光巨块→设计师给真造型，可体素怪物或少量精模）。
  - **散落物件**：未来的「类型物件」（机关/道具/元素物），先用颜色区分→设计师给图标化的体素小物。
- **骰子呈现**：3D 骰子会**掷进场景里翻滚**（战斗时），骰面带**颜色=元素**。需要设计师给**骰子的材质 + 六色元素的视觉语言**（颜色 + 可选小符号）。
- **HUD 叠层**（2D·叠在 3D 场景上·见 §5 落地约束）：当前层/房间/类型、队伍生命(心)、骰池、buff、货币、进度。要与场景气质统一的一套**HUD 皮**。
- **光照氛围**：保留「微缩模型」感——柔和接触阴影 + 移轴景深(上下渐糊) + 轻泛光(让发光物自发光)。温暖、通透。

## 3.5 · 屏 C · 战斗 / HUD UI（骰库底栏 + 敌人 + 过关奖励 · owner 2026-06-29 补）

> 玩家战斗时的核心交互屏。布局：**上=敌人 + 竞技场，下=两名玩家的「骰子口袋」，边角=HUD**。

- **敌人区（上 / 中）**：敌人造型 + **信息卡**——名字、血条、**元素徽章 + 弱点/抗性**、**本回合威胁**（全明牌·呼应 ui-playbook「决策摆明面」铁律）。骰子掷进竞技场里 3D 翻滚。
- **底栏 = 两名玩家的「骰子口袋」（owner 核心设想）**：左 = 玩家A骰库、右 = 玩家B骰库。每颗骰 = 一个**带元素色的 token**（显示颜色 / 点数 / 类型）。玩家从口袋里**挑要掷的骰**（"选择你怎么用"）+ 一个「已选」暂存区。需给：**骰子 token 视觉语言**、基础骰 / 特殊骰 / 局外骰的**区分**、选中态。
- **中央控制区**：掷骰 / 重掷(锁定) / 攻·防分配 / 确定 / 道具格。
- **边角 HUD**：层·房间·类型、**队伍生命(心)**、货币、进度、buff 栏。
- **过关奖励浮层**：清空敌人 → **三选一卡片菜单**（新骰 / 强化骰 / buff / 道具·哈迪斯式）。需给：奖励卡视觉 + 三选一布局。
- 全部走组件化 UI（Card / Panel / Label / ProgressBar / Badge）+ 与场景统一的一套皮。

## 4. 美术风格指南（全局）

- **几何**：体素(立方体)为主 + 极少量精模(BOSS/吉祥物)作 showcase。**别做高面数复杂模型**——这是省成本、可扩展、可批量渲染的硬约束。
- **丰富度来源**：**贴图 + 光照 + 色彩**，不是建模。每种材质 = 一套体素贴图（顶/侧）。
- **整体调性**：明快、温暖、彩色、童话微缩 + 一点魔幻神秘。**非写实、非暗黑**。
- **每层主题色板（元素/幻境）**：
  | 层 | 幻境 | 主色调 |
  |---|---|---|
  | 1 | 翠庭 | 草绿 + 暖土 + 金色高光 |
  | 2 | 古殿 | 石蓝灰 + 青色高光 |
  | 3 | 熔心 | 暗褐 + 炽橙红高光（熔岩自发光） |
  | 4 | 晶顶 | 青蓝 + 紫色水晶高光 |
- **六色元素（骰子/战斗）**：🔴火 / 🔵水 / 🟢木 / 🟡雷 / ⚪风 / 🟣暗——给每色一套**视觉语言**（颜色 + 质感 + 可选符号）。
- **参照气质**：《哈迪斯》(精致俯视) ·《弓箭传说》(近俯视战场) ·《奇诺比奥队长》(微缩盒庭) ·《Monster Train》(往上攀塔) ·《Balatro》(桌面神秘 + 骰/牌质感)。

## 6. 技术落地约束（设计需可实现 · 重要）

- **2D UI（Title/HUD/菜单/过场）走引擎统一 UI 库**：闭集控件（Panel / Label / Button / Screen / ProgressBar / Tabs / Badge / Image 等）+ 语义色令牌 + flow 布局。**设计可以美，但最终要能映射到这套组件**——即"面板/标签/按钮/进度条"的组合，不是任意自由切图堆叠。背景大图/logo/图标可作 `Image`/底图资产引入。
- **3D 场景走体素渲染器**：物件是 `Mesh3D` 立方体 + 贴图（贴图能力待引擎补、已在路线上）+ `Model3D` glTF（少量精模）。**贴图按「顶面/侧面」给**（体素盒贴图模型）。
- **氛围**：光照/移轴景深/泛光/天空盒都是引擎现成数据化能力，设计师定参数风格即可。
- **一句话**：**几何省（体素），美术堆在贴图和光色上；UI 走组件化不走自由切图。** 这样设计能 1:1 落地、且可批量扩到无限房间。
