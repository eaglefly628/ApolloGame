# 7·29-30 审核冲刺纲领（Demo Sprint · owner 2026-07-07 定向）

> **审核方要验什么**：这台引擎能不能**用自然语言描述，快速生成 playable 的游戏**。
> **量化口径（owner 转述）**：①一周能出 ~30 款；②以**换皮**（美术资源换皮）为主力量产手段；③基本玩法 OK 即可（先投放素材验证，再精加工）。
> **当前最大管线缺口 = 美术**：生成的游戏是程序化色块（game-q 实证：零真资产），审核观感立死。必须把美术 API（千问 2D wanx / Tripo 3D·Meshy 可插）**自动接进生成流**。
> 本纲领=Lead 图纸总纲；分单见 `docs/workflow/requests.md` REQ-DEMO-0729 系列。**冲刺期内本纲领优先级压过一切非冲刺工单。**

## 一、核心洞察：美术自动化不需要动引擎

数据接口早已存在——`art:<英文关键词>`（`src/assembly/resolve-art-refs.ts`）：LLM 只写查询串，选材发生在引擎解释器里（确定性排序、留痕可审计）。缺口只是：**素材库没有的东西，现在解析失败退化成占位**。

对齐方案 = 在**生成/保存时**加一步确定性编排（服务层，非引擎）：

```
自然语言 → LLM 生成 manifest（art: 引用 + 风格包选择·纯数据）
        → art: 一律解析到免费库（placeholder·游戏立即可玩）
        → 机器推导「替换列表」（编号/类型/规格/表现描述·全类型登记）
        → 配风格包 → 批量调美术 API（万相/Tripo/Meshy·整批同风格）
            → 确定性后处理（palette-snap/规格缩放）
            → 落游戏资产目录 + provenance + 台账
        → 按编号对位替换 placeholder → 风格成套的可玩卡带
```

> **工作流正式档（owner 2026-07-08 定形两段式·唯一权威）：`docs/design/art-replacement-workflow.md`**——placeholder 先行保秒可玩；整批生成保风格成套；换皮/单槽优化=同一机制重跑。

- **对弱 LLM 零新负担**：还是只写 `art:关键词`；新增的 `artStyle` 是一个纯数据块 `{stylePrompt, palette, mode: library|generate|auto}`——模板里带默认值，LLM 不填也能跑。
- **换皮=同一 manifest × 新风格锚**：玩法数据一字不改，重跑美术编排 → 新卡带。这就是 30 款/周的乘法器。
- **无 key 不阻塞**：mock 兜底（占位图+MOCK 标记+凭证探针输出），流水线永远走得通；有 key 自动升真。
- **成本控制**：内容寻址缓存——`hash(provider+prompt+参数)` 相同 → 复用已生成资产，换皮批量时同风格素材免重复扣费。

### 风格一致性五层防线（owner 2026-07-08 问·Lead 定design）

> 病理：N 张图独立生成，纯文字风格描述只能松散趋同——必须叠确定性手段。

| 层 | 手段 | 性质 |
|---|---|---|
| 1. 风格包闭集 | `artStyle.stylePack` 从**预调试风格包**里选（像素/卡通厚涂/霓虹合成波/低多边形/水墨…每包=在真 provider 上试跑调稳的 prompt 模板+参数组）——弱 LLM 只能选，不能自由发挥散风格；自由 stylePrompt=显式逃生口 | 事前·闭集 |
| 2. 同款钉死供应商 | 一款游戏的全部资产**钉死同一 provider+model（+seed 可用则钉）**——混供应商是一致性头号杀手；台账记录、编排器强制 | 事前·确定性 |
| 3. 定调图参考 | 先生成 1 张主视觉定调图（人看一眼认可）→ 后续资产走**图生图/参考图模式**（万相/Tripo 均有 image 入参）——图锚比文字锚强一个量级；adapter 不支持参考模式则记 blocker 进台账、降级纯文字锚 | 事中·强锚 |
| 4. 确定性统一后处理 | 引擎侧 recipe 纯数据 op：**palette-snap**（量化到风格锚调色板）+ 统一分辨率网格（如全部精灵 64px 栅格化）——不同来源的图过同一道后处理，观感立刻成套；确定性、mock 路径也走 | 事后·机器保证 |
| 5. 台账墙+评分卡抽检 | 缩略图墙一屏扫全款资产（不成套一眼可见）→ 按编号点名重做；评分卡维 1（艺术方向）抽检把关出货 | 事后·人闸 |

分期：层 1/2/5 进 T1（便宜·纯数据+纪律）；层 4 palette-snap 进 T1（确定性 op·小）；层 3 定调图参考=T2 施工时验 adapter 真实能力再接（真支持则一并落，不支持记 blocker）。

## 二、生成资产的归置与优化闭环（owner 2026-07-07 拍板）

- **自动生成直接入游戏（owner 认可可行）**：产物一律落**该游戏自己的资产目录**+登记游戏本地索引（provenance 硬字段照旧+标 `unreviewed`），直接接线，立即可玩——demo 与量产走这条。
- **硬要求：台账编号+浏览+替换闭环**（owner 原话「做完以后需要有一个完整的浏览和优化的流程」）：
  - 每款游戏产出**美术台账**：每条资产一个**可念出口的编号**（art-01/art-02…·按槽位确定性分配·重跑不漂移）+ 槽位语义（哪个实体哪个字段）+ prompt + 来源（library/generated/mock）+ provenance + 缩略图；
  - studio 里可**逐款浏览**全部美术资产（缩略图墙+编号）；
  - 人能**按编号点名替换**——「art-03 做得不好」→ ①重新生成（可改 prompt）②从共享库换 ③上传替换，替换即重钉 manifest 引用+更新台账。
- **共享货架不变**：进共享库 index 仍必须过 M2.5 人审门（守共享库不被污染）；精加工阶段从各游戏台账挑好料走人审入库。

## 七、demo 判定口径（彩排即照此验收）

1. 现场输入一句自然语言 → 出可玩卡带（含真美术皮）——端到端耗时记录在案。
2. 同一款玩法现场换 2-3 套皮，各成独立卡带。
3. **现场按编号点名一件不满意的资产**（「art-03 重做」）→ 改 prompt 重生成 → 游戏里立刻换上——展示「可控的优化闭环」，不是一锤子买卖。
4. 出示量产证据：T3 批量冒烟报告（N 款/耗时/成本）折算周产能 ≥30。
5. 出示治理证据：provenance/台账/审计/评分卡——「快而不失控」是我们对比裸 LLM 写代码路线的护城河。
