# 数据驱动第一性原则（Data-Driven First Principle）

> **本引擎的最高原则。任何设计、任何 PR、任何 session 都不得偏离。与本文冲突的一律以本文为准。**

## 0. 一句话

**整个游戏是数据，不是代码。** 代码只是固定的解释器；游戏的全部内容用"填好的数据模板（schema）"描述。AI 与用户只编辑数据，永不生成代码。

## 1. 两条不可违背的底线（原则的来由）

1. **目标用户不是程序员** —— 他们只碰数据，永远不碰代码。
2. **不同 LLM（强的弱的）产出必须一致** —— 创作被降维成"按文档化的数据模板（schema）填空 + 从固定 capability 目录组合"，而不是"写程序"。自由代码的 LLM 方差是天文级的，**只要授权层能写代码，第 2 条立刻破功。**

> 推论：**口子一旦是"代码"，就和核心目标直接矛盾。**

## 2. 神圣的线

- **代码 = 引擎 + capability**：固定、审计过、确定性、**极少新增**。这是"解释器 / 词汇表"。
- **数据 = 整个游戏**：蓝图 + 组件 + 资产槽位 + 内容。流动、AI/人可改、可 diff、可回滚、**无限多**。这是"用词汇写的句子"。

## 3. 分层（谁碰什么）

| 层 | 是什么 | 谁碰 | 形态 |
|---|---|---|---|
| **组合 Composition** | 实体 + 组件 + capability 接线 | AI / 用户 | **数据** |
| **导演 Director / 流程清单** | 场景/状态序列（菜单→关卡→结局） | AI / 用户 | **数据**（不是"流程代码"！） |
| **自定义玩法规则 Custom-Rule** | 长尾的特制玩法 | AI / 用户 | **数据**（声明式表达式/脚本 DSL） |
| **能力 Capability（词汇表）** | 引擎的"动词" | **只有引擎团队** | 代码（审计、确定性、可复用） |

- **用户和 AI 永远只在上面三层（全是数据）。**
- **代码只存在于最底层（引擎词汇表），且只有引擎团队加，永不让 AI 生成。**

## 4. 下沉纪律（缺了表达力怎么办）

当游戏需要现有数据表达不了的东西时，**绝不在游戏层写代码**，只有两条路：
1. **换种组合**：用现有 capability 重新拼（Condition→Event→Effect / tween / …）。
2. **下沉成通用 capability**：把它做成**引擎侧的一个通用能力**（代码只加这一次，加在引擎/词汇表），之后**所有游戏用数据调用它**。

> 例：VN 的"对话运行器"不是某个游戏的代码文件，是引擎的通用 `dialogue` capability，游戏只喂对话 JSON（数据）。

## 5. 唯一逃生舱：自定义能力（Custom Capability）

真到了 DSL 也表达不了、又不值得马上通用化的最后 1%：
- 一个**沙箱化的确定性纯函数**（固定窄签名、无 IO / 无异步 / 无全局态）；
- **由工程师写，绝不由 AI 写，绝不进入"一句话生成"的 AI 创作回路**；
- **记为技术债**，有空就下沉成通用 capability。

它给了务实的出口，又不污染"用户无代码 + LLM 一致"两条底线。**它在引擎侧，不在游戏数据里。**

## 6. 一把尺子（所有"该数据还是代码"的裁决标准）

> **"一个最弱的 LLM，能不能也产出一模一样的东西？"**
> 能 → 它是合格的数据接口。
> 不能（因为要写自由代码）→ 拒绝。要么做成 DSL，要么下沉成 capability。

## 7. 硬指标

**"一个游戏里，数据 vs 代码的占比。"** 目标渐进逼近 **100% 数据**。每存在一个游戏专属代码文件（自定义系统 / 手写 React / 对话运行器…），这个数字就掉一点 —— 它是对本原则的**负债**，要么删（变数据），要么下沉（进引擎）。

## 8. 当前诚实状态（2026-06-04）

- ✅ 已有：数据驱动的 substrate（26 原子 + Tier1-4 涌现 capability + 蓝图 + Condition→Event→Effect + TBF 资产）。
- ❌ 仍是代码债：游戏层手写系统、手写 React UI、`*.ts` 蓝图（应变纯数据 manifest）。
- 🚧 最硬的两座堡垒：**UI**（要变数据描述的 UI，不是每游戏手写 React）、**新玩法**（不写，要么组合、要么下沉）。
- 偿还方向：把 coop-goal / dialogue 这类下沉成通用 capability；蓝图 .ts → 纯数据 Game Manifest；UI → 数据描述 + 通用解释器。
