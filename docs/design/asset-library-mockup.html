1导入资产：进导入向导（视图 B/C）。浏览器 = 浏览 + 导入 双职能。
2全文搜索：分词全命中（沿用 searchArtlib 语义），命中 id/名称/描述/tag。
3下拉过滤：类型 / 状态（filled·tbf·placeholder）/ 排序（名称·尺寸·最近导入）。
4tag chips：可叠加多个 tag 过滤（AND），点 × 移除。
5类型目录树 = 统一分类法：贴图(按用途槽位分子类)·音频(BGM/SFX/语音/环境)·动画·视频·材质·网格·字体。空类型也常驻显示——这就是「先把目录建起来」。
6来源（包）过滤：项目资产(assets/index.json) / FreeArtLib 素材包 / 各游戏清单(只读聚合)。解决现状三套索引各管各的问题——一个浏览器看全部。
7详情面板：大预览 + 元数据 + tags 编辑 + 一键复制 key（key 即游戏数据里的 textureKey）。
8usedBy 溯源：哪个游戏/实体在引用此资产（接现有 assets-model 扫描）。

9三种导入模式对应你说的三种来源：散图（批量归一命名+变体分组+重复剔除）/ 未切割精灵表（网格切割→sprite-sheet 或命名 atlas）/ 乱命名目录（规则化重命名映射表）。
步骤④ 提交写库：文件落 assets/<type>/… + assets/index.json 增量条目（含 spec + tags + 来源溯源 provenance），经 apollo.py 新增 POST /api/assets/import 写盘（限定 assets/ 子树）。无 apollo 时降级为只读预览 + 导出 JSON 包。
确定性边界不变：库与导入全在表现层，sim 只认字符串 key；同一份输入 + 同一份归一化 profile → 永远产出同一份索引（可审计、可复放）。
