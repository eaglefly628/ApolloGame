# Codex × S1–S8 视觉开发流程 review（2026-10-02）

## 结论

当前仓库已有设计讨论、S1–S8 看板与编排器、UI Gallery 检索、真浏览器截图、UI 机械审计、标准照和 S7 评分卡。但它们没有形成一条可重复的「讨论定稿 → 设计任务 → Gallery 选型 → 逐关施工 → 按目标图评分 → 自动返工」链。主要问题是**设计目标没有被转成机器可消费的视觉契约**，其次是 Codex 尚未接入现有阶段编排器。

本 review 把「DeZign 工作」暂按设计任务包理解：包含屏幕清单、参考图、布局与视觉要求、Gallery 选型、验收标准。若 DeZign 是特定外部产品，接入层需按其输入输出协议再定。

## 目标流程

1. **讨论定稿**：把用户确认的概念冻结为版本化 design brief；同时记录不可变的游戏目标和可调整的视觉偏好。
2. **设计任务编译**：自动生成逐屏任务包。每屏至少有用途、状态、参考图、信息层级、交互路径、视觉关键词、不可接受的偏差和验收权重。没有参考图时，先产可供用户选择的候选视觉方向，再冻结目标。
3. **Gallery 选型**：根据每屏需求调用 `ui-find --json`，生成 `gallery-map.json`：需求、候选控件/section、采用的示例文件、采用理由；找不到时记录 capability gap。S4 开工前必须在档。
4. **S1–S8 逐关执行**：沿用 `game-pipeline.mjs` 作为状态与证据真相。给编排器增加 Codex 执行适配器；每个阶段只领阶段手册、board、游戏目录和该阶段的结构化任务包。阶段完成后独立复跑原有机器门，保留不同执行者复查与真人签核。
5. **S4 结构验收**：按设计任务包检查每个关键状态的布局、信息层级、可见动作及浏览器可驱动路径；产出固定视口的截图序列。
6. **S5 视觉迭代**：同一浏览器环境重拍同一状态，对比目标图、当前图、上一轮图；机器量重叠、可读性、裁切、空白、状态覆盖和 Gallery 映射；视觉评估器按逐屏 rubric 给分及定位到区域的修改建议。只改未达标项，重拍、重评，直至达线或到达预算上限。
7. **S7 独立复核**：保留现有八维评分卡作为整体品质判断；逐屏视觉分及其证据进入评分卡输入。S7 不承担首次发现 UI 偏差的职责。

## 视觉评分契约

每个屏幕以**同一输入状态、同一视口、同一字体与资源版本**截图。评分需要同时给出分数、证据图、失败区域和修法，不能只有一个总分。

建议逐屏 100 分：结构/信息层级 25、与目标图的视觉一致性 25、可读性与布局 20、交互状态完整性 15、风格统一性 15。机器检查作为硬门：关键动作不可见/不可点击、异常重叠、文字裁切、严重低对比、浏览器错误任一存在时不予通过。图像评估器的主观分只做迭代反馈，不代替这些硬门。

通过条件建议为：每个关键屏 ≥85 且各项 ≥70%；所有硬门为绿；关键状态（默认、悬停/按下、弹窗、失败、完成、重开）均有图；相邻两轮得分与差异有记录。若连续两轮分数不升、超过最大迭代轮次或目标图互相矛盾，则停在当前阶段，列出具体冲突或缺件供用户裁决，不自行降低门槛。

标准照与目标图分开管理：**目标图**定义要达到什么；**标准照**在某版经批准后防止以后意外漂移。像素 diff 不能当作美观分，也不能因为截图“变化很大”就断定质量提高。

## 最小落地顺序

### 第一批：把 Gallery 变成施工输入

- 扩设计分解产物：增加逐屏 `ui-brief` 与参考图清单，保留既有 GDD/能力计划。
- 加一个任务编译步骤，使用 `ui-find --json` 产 `gallery-map.json`，写明每项需求的来源 section 和示例文件；S4 前置检查其完整性，S5 审计核对最终 LayoutNode 是否消费了所选能力。
- 在 S4/S5 阶段 prompt 中加入该任务包及选型结果；避免让阶段会话只凭一句「先看 Gallery」自行猜。

### 第二批：浏览器视觉自评闭环

- 以现有截图和走查工具为底，建立逐屏状态清单及固定拍摄条件；产 `target/current/previous` 三列图、差异标注和机器检查 JSON。
- 加逐屏视觉 rubric 评估和最多 N 轮定向修订。评分报告记录每轮分项、证据、修改、再评分；不要让同一模型的口头“已优化”成为过门证据。
- S5 gate 读取报告与截图清单，并独立复跑机器检查；无目标图或无评分报告要明确显示「未做视觉验收」，不能以 golden-shot 无基准的提示代替通过。

### 第三批：Codex 接入编排器

- 把 `pipeline-orchestrator.mjs` 的会话启动抽成运行时适配接口，保留现有 Claude 路径，增加 Codex 路径。适配器必须回传任务/会话 ID、运行状态、产物路径及退出原因；board/gate/signoff 仍由原 CLI 管理。
- 在 Codex 中先跑一个游戏的 S1→S8 试点，对照看板、截图、评分报告和最终游戏逐关复盘，再推广到其他游戏。

## 试点验收

选一款小型 2D 游戏，至少覆盖菜单、主玩法、结果三屏。给定同一概念和三张目标图，从讨论定稿后到 S7 评分前，系统须能自动产任务包、Gallery 选型、阶段证据、每屏多状态截图和迭代记录。用户只需裁视觉方向和既有人门；任一屏不过线时，报告要指出哪块画面、哪条要求、哪轮修改后仍不合格。

本次为流程与代码接线 review，未修改运行逻辑，也未碰当前 `game113` 的在途改动。
