## 关键结论（给 owner / Lead）

### ✅ 好消息：几乎白捡的一个游戏
本作 = game-103 的**输入端对调**——英雄从玩家输入改为 `t2-behavior-tree` 驱动，刷怪从 `t2-spawn-director` 波表改为玩家实时指令，
**核心模拟层（移动/索敌/开火/命中/被动聚合/DoT/三选一/进化）与 103 完全共用**。
GD 逐条核查 registry 后把初拟的三项新能力申请**全部撤回**（`t2-effect-apply`/`atoms/destroy`/`t2-group-count` 已覆盖）：
**对引擎的净新增需求 = 0**。两作还互为对方的 AI 陪练。

### ✅ 玩法内核已被模拟验证
6 个策略机器人跑 seed 1–5：龟缩(0 养分) < 无差别进攻(66) < 只打最强(762) < **分诊(1660)**。
owner 设想的"割弱 / 拖强 / 收割"三动词结构在数值上成立，且**有限兽群 + 等级赏金**正确地惩罚了"低级全割"。

### ✅ 属性防御系统解开了阻塞项（2026-08-05）
owner 定向「英雄只是个 NPC，要能看到他的技能数值和属性防御；投放的是属性怪的叠加」。
落地为**三条可见的属性防御条（锐/蚀/缚）+ 侧写落差 7.3 倍 + 破防增伤 ×1.5**：
杀强敌不再是「线性追指数」的军备竞赛，而是**读面板 → 选属性 → 剥防 → 穿透**的组合题。
模拟验证：最佳策略从 **1 杀（不达标）→ 22 杀·养分 1842/1800 达标**，
且**只有读面板的两个策略（G/H）能达标**，其余六个全败 —— 证明「看得见的数值」是主玩法而非 UI 装饰。

### ⚠ 矩形化后需重标定
Lead Y1 裁决：`t2-bounds-clamp` 纯 AABB 无圆形 ⇒ 场地改矩形（已同步 `gdd.md` §3）。
圆形版的数值标定因此失效，`balance-design.md` §5.0 已记录三处连锁改动与重标定方向。
**§5.1 的达标数字是圆形版口径，不得当作当前状态引用。**

### 🟡 仍待定案：牧养 vs 早割
达标策略平均在 Lv1.7 就收割，仍是高效清剿。根因已定位：腐化度靠打架赚，等待即断科技（详见 `gdd.md` §7.2）。

### ⛔ 引擎缺口（已提单）
`REQ-STATUSSET`：全库无能力能把「资源见底」写成 `Status` 位，破防门控缺 Flag→Status 一跳。
