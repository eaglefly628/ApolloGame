## 一、总判决（先说结论）

**底座不胖，缺口比赘肉重要。** 原子层 30 项职责正交干净，是任何 ECS 引擎的标准词汇；tier 层的"孤儿"绝大多数是词汇表资产（创作台的表达力）或配套件，不是过度设计。真正的问题是：**4 个 canonical 缺口该做没做**（其中"UI 锚定"正是 owner 点名的历史欠账 REQ-ARCH-ANCHOR）、**1 个设计分叉**（输入链两套真相）、**1 个登记漏洞**（tray）、**壳层三套 UI 基建并存**（唯一的真赘肉，退役令已存在被 game-f 冻结连带推迟）。

## 三、过度设计审查（设计视角，非消费计数）

| 嫌疑 | 判决 | 理由 |
|---|---|---|
| 原子层 30 项 | ✅ 无罪 | 每项职责单一正交（transform/velocity/mass/…任何 ECS 的标准词汇）；3D 三原子归 P3D 线 roadmap 认领 |
| 19 个孤儿能力 | ✅ 多数无罪 | 三类：**词汇表资产**（match3-board/tilemap/anim-state——品类表达力，owner 口径：需求量小≠不该存在）；**配套件**（rotation-apply/friction/ground-sense/jump——平台跳跃链，preset 在用其组件）；**刚下沉未接线**（t2-dice-roll——game-d 接线欠账，非设计问题） |
| t2-card-play（REQ-016/017） | 🔶 排期错位 | 为未启动的联机线预铺的接缝（provides 空）；不删（D/F 双人是既定方向），标注「待 net 线激活」，**联机线不批前不再为它扩任何东西** |
| autochess 组件域（7 组件）+ f-only 11 能力尾巴 | 🔶 冻结随 f | 下沉本身成立（自走棋品类通用词汇），错在没有第二消费方验证通用性；随 game-f 判决——**不扩不删** |
| **输入链两套真相** | 🔴 设计分叉（要收敛） | i1-input-capture/i2-action-map 定义了契约，net 层却自建 RawInputData/InputQueue 绕行，Action 由 net/commands.ts 直写——不是原子过度设计，是**契约与实现分叉**。收敛方向二选一（net 回归原子契约 / 承认原子契约废弃改文档），归 net 线立项时一并裁决 |
| **三套 UI 基建并存**（ui/components + ui/shell + ui/vn） | 🔴 唯一真赘肉 | 退役令已存在（CLAUDE.md），被 game-f 冻结连带推迟；**game-f 判决日=退役执行日**，在那之前两套死缓栈禁止任何新消费 |
| 单独成件的小能力（hierarchy-cascade 等） | ✅ 无罪 | 小而正交，合并收益小于折腾成本 |
