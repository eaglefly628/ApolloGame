## 1. owner brief 要点（归纳）

- 品类：**幸存者类割草 Roguelite**（吸血鬼幸存者 / Habby《Survivor.io 幸存者！.io》核心）。
- 复刻范围：**核心玩法**（单局循环），非整包（不含商业化/社交/多角色养成完整深度）。
- 参照物：Survivor.io、Vampire Survivors。

## 2. 一句话定位

俯视 2D、单摇杆走位、武器**全自动开火**的割草 Roguelite：走位躲怪 → 自动杀怪 → 捡经验升级**三选一** → 凑「武器×被动」**进化** → 从被追着跑变成清屏机器 → 活满限时打 Boss。

## 3. GD 架构评判（该不该做 · 怎么做才对）

按宪法尺子逐条过：

| 判据 | 结论 |
|---|---|
| **能用现有 capability 表达？** | ✅ 能。核心系统全部映射到在册能力（详见 capability-plan）：移动=`t1-motion-apply`、敌追=`t3-aggro`+`t2-steering`、开火=`t3-caster`+`t3-prefab`+`t2-launch`、命中=`t2-hitbox`、死亡=`t2-mortal`、**被动加成=`t2-stats`+`t2-modifier-stack`**、DoT=`t2-over-time`、三选一/掉率=`t2-dice-roll`。 |
| **是否虚胖数据（表+游戏层自写解释器）？** | ⚠ 风险点=**"三选一/进化触发/波次调度"** 三处编排逻辑。若游戏层自写 for 循环解释，就是虚胖。→ 已在 plan §4 逐条申请为例外 or 指向现有能力（进化=条件触发、波次=timer/spawn 数据），**开工前必须过审**。 |
| **最弱 LLM 能否产出一模一样的数据？** | ✅ 内容层（武器/敌人/被动/波次/掉落）= 纯 JSON 数据表，弱模型可产。仅编排规则需固定解释器（引擎侧），不属内容层。 |
| **"能出复杂的东西"（owner 07-11 价值序第一要素）** | ✅ 强命中。进化构筑 × 三选一 × 敌群编排 = 深度组合玩法，正是引擎该证明的复杂度上限。 |

**评判结论：接受立项**，但**有前置条件**——

1. **capability-plan 必须先过 Lead 审**（尤其三选一/进化/波次三处编排的解释器归属），过审前零游戏层代码。
2. 幸存者是引擎**首个实时动作全游戏**（现有 `game-i` 的 physics-lab/ai-lab 只是能力展示台，非成品游戏）。能力层已验证可行，但**"数百移动实体 + 连续碰撞 + 实时输入"的成品级性能/手感尚无先例**——列为 S2/原型阶段头号风险，需早验证（见 §5）。
3. 一切随机（三选一、散射、掉落）**走种子 PRNG，禁裸 Math.random**（randomness.md 红线）。
