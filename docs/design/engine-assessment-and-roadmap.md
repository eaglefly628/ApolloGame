## 0. 一页摘要

**Apollo 是什么**：一台**数据驱动的确定性游戏引擎**。整个游戏 = 一份纯数据 Manifest（实体+组件+能力接线）；代码只存在于引擎侧——固定、审计过、确定性的"解释器 + 能力词汇表"。AI 与用户只编辑数据，永不生成代码。

**核心命题（反共识押注）**：**智力在引擎，不在模型。** 把"做游戏"从"写程序"降维成"按 schema 填空 + 从能力目录组合"，于是**最弱的 LLM 与最强的 LLM 产出一致**——这是写进宪法（`data-driven-manifesto.md`）的不变量②，也是全部商业价值的来源：

> 自由代码路线：模型方差 = 产品方差，必须用最贵的模型，仍不可审计。
> Apollo 路线：方差被 schema + 校验器 + 确定性解释器吸收，**DeepSeek 级模型即可驱动**。

**现状一句话**：内核健康（tsc 干净 / 880 测试全绿 / build 1.5s），5 个品类切片游戏（平台跳跃 / 乙游 VN / 三消换装 / 暗黑 ARPG / Balatro 卡牌 rogue）趋近纯数据跑通，多模型生成管线（含 DeepSeek）已真实接入，lockstep 联机确定性已双端证明。正在攻第 6 品类：**Game F 自走棋**（本轮主战场）。

## 1. 技术现状评估（2026-06-10）

### 1.1 架构一图

```
数据(Manifest) ──parseManifest──▶ WorldBlueprint ──engine.load──▶ World ──tick──▶ 确定性状态(可hash/快照/回放)
   ▲  capabilities:[id] + entities:{id:{Comp:data}}                                  │
   └────────────── exportManifest（导出=导入的逆运算，对称闭环）◀──────────────────────┘
```

| 层 | 形态 | 谁碰 |
|---|---|---|
| 组合（实体+组件+能力接线）/ 流程 / 自定义规则 | **数据** | AI / 用户 |
| 能力词汇表（26 原子 + Tier1-3 涌现能力） | 代码 | 只有引擎团队 |

### 1.2 强点（有证据的真功夫）

1. **内核极简且解对了真问题**。World ~200 行；`phase + 组件读写拓扑 + runsAfter/runsBefore 显式边覆盖反向推断边` 干净解掉"两系统读改写同组件判成环"的 ECS 真实工程难题（R10），且不掩盖真环。
2. **逻辑链成体系而非特性堆**。Condition→Event→Effect 一拍反馈、edge/level 迟滞、`op/order/valueFrom`——Balatro 级计分链（牌型→逐张→retrigger→有序加乘→资源×资源）被证明为**纯数据装配，零游戏代码**。每个"为什么必须下沉为引擎能力"的论证（如 retrigger 乘性耦合不可被聚合计数表达）都成文可审。
3. **确定性纪律渗透每个角落**：状态 hash 排除纯表现组件、缓动只用多项式（不碰超越函数）、处处实体 id tie-break、整数 tick、PRNG 进快照、碰撞解算 Box2D 同构且接触对确定序。由此**免费**获得：lockstep 联机（已 2 端证明）、录放、存档、反作弊指纹。
4. **治理文化罕见健康**。需求池（requests.md）有成文的回驳记录：REQ-023 因 YAGNI 不 greenlit 并给出重组等价写法；Tier4（AI 行为层）**刻意为空**——行为=数据装配而非代码。宣言不是挂墙上的。
5. **校验护城河已起步**：R12 组件 schema 校验（类型错拒绝加载）+ assetKey 硬校验（AI 编造的资产 key 加载期拒绝）+ 能力目录自描述注入生成 prompt（新能力零 prompt 维护、不漂移）。

## 2. 发展评估与路线图（主战场：Game F 自走棋）

### 2.1 为什么 Game F 是对的下一仗

- **工程上**：前 5 个游戏的逻辑只压"全局单例"（按 id 路由）；自走棋第一次压满**实体寻址轴**——self（每单位自治）/ 集合读（羁绊计数）/ 集合写（光环）。这是引擎从"单角色叙事/计分"走向"百单位群体模拟"的关键一跃，query 倒排索引（已落地）正是为此备的地基。
- **商业上**：自走棋/合成战斗是移动端长青品类，单位=prefab 模板（纯数据）、羁绊=计数规则（纯数据）、阵容=组合空间——**品类本身就是"数据驱动"的最佳代言**：内容无限多而代码零增长。
- **叙事上**：8 人对战吃 lockstep 确定性（我们免费有），录放/复盘/反作弊 hash 全是品类刚需。

### 2.2 近期：Game F 拉动的引擎缺口（实体寻址轴三连）

| 需求 | 裁决 | 状态 |
|---|---|---|
| REQ-021 self-rule（每实体：读自身条件→对自身施效） | ACCEPT——mortal/over-time 的通用化 | ✅ 已落地（872 绿时代） |
| REQ-022 group-count（按 Tag 计数→写 Resource） | ACCEPT **但裁剪**：只做"集合计数→资源"；原案的 `thresholds:[{at,signal}]` **回驳**——越阈值锁存发信号 = `event-when{resource cmp, mode:edge}` 已有语义，按 manifesto §4 先重组不重造 | 🔜 本轮实现 |
| REQ-023 group-effect（效果 fan-out 到一组实体） | **维持回驳（YAGNI）**：羁绊光环 = group-count 数层数→写全局 buff 资源→各单位 stats 读全局（已有全局 id 路由）。真出现"逐单位异质状态"再议 | ⏸ 不 greenlit |

其余 Game F 件（商店/合成/升星/波次）预判为**既有能力重组**：craft-recipe（购买/合成）+ prefab（单位模板）+ caster（上场生成）+ flow（备战→战斗→结算回合环）+ self-rule（单位自治）+ aggro/steering/hitbox（战斗）。**原则：先装配，装不出来再立案。**

### 2.3 中期：产品化三大件（创作侧闭环）

1. **结构化意图层（GDD-first）**⭐用户已点名最优先：NL/视频 → 一份小的"游戏意图"结构化数据（对象/规则/节奏）→ 再装配 manifest。收窄生成空间、降模型发散——这是"弱模型也稳"的第二道闸（第一道是 schema）。
2. ~~**Manifest 引用链接器**~~ ✅ 已落地（2026-06-10）：id 交叉引用闭包检查（信号有无生产者、条件叶子 id 是否存在、effect 目标是否可达、flow/dialogue 图内跳转）。"最弱 LLM 最常犯的错"从运行期静默变成加载期告警。
3. **真截图 + VLM 视觉评审**：headless 浏览器截帧接进 ApolloBench Visual 轴，消掉 §1.3 第一红项，也是对投资人最直观的"画面对不对"证据。

### 2.4 远期：堡垒与品类红利

- **UI 数据化**（最硬堡垒）：声明式 UI 描述 + 通用解释器，消灭 per-game React。
- **编辑器结构编辑**：透视器从"改字段"到"增删实体/组件"，人与 AI 同一数据面。
- **跨端确定性实证**：双端 hash 对比协议 → 解锁真远程 lockstep 对战（自走棋 8 人 / 卡牌天梯）。
- **资产闭环**：四 provider（生成/库选/上传/程序化占位）+ 从蓝图自动派生资产购物单（已有）。

### 2.5 我们刻意不做什么（护城河纪律）

- 不收自由代码（哪怕"就这一次"）——口子开了不变量②立刻破功。
- Tier4 行为层保持为空——AI 行为永远是数据装配。
- 不为想象中的需求加宽引擎（REQ-023 式回驳是常态而非例外）。

## 3. 融资叙事："让 DeepSeek 也能做出好游戏"

### 3.1 痛点：AI 生成游戏的方差灾难

让 LLM 直接写游戏代码的路线有三个结构性死穴：
1. **方差天文级**——同一句话，强模型与弱模型产出天差地别；同一模型两次也不同。质量被钉死在"最贵模型 × 最好运的那次采样"。
2. **不可审计、不可维护**——生成的自由代码无法 diff/回滚/校验，坏了只能重 roll。
3. **成本曲线错误**——内容生产成本随模型档位线性上涨，UGC 平台经济模型不成立。

### 3.2 Apollo 的反共识押注：智力在引擎，不在模型

把创作降维成**"按文档化 schema 填空 + 从固定能力目录组合"**。模型只做一件事：把人的意图翻译成一份纯数据 Manifest。执行的全部智力——物理、逻辑链、计分、AI 行为、流程——都在引擎这台审计过的确定性解释器里。

> **一把尺子（宪法 §6）：最弱的 LLM 能不能产出一模一样的东西？能 → 合格的数据接口；不能 → 拒绝，做成 DSL 或下沉成引擎能力。**

推论即商业模型：**当 DeepSeek 与 Claude 在这台引擎上产出趋同，内容生产成本下降 1–2 个数量级**，且天然适配国产模型生态（DeepSeek/Qwen/本地 Ollama——三者已真实接入）。

### 3.3 证据（在仓库里，不在 PPT 里）

### 3.4 给投资人的三张图（下一步跑出来的可量化指标）

1. **方差收敛图（核心）**：同一组游戏意图 × {DeepSeek, Qwen, GPT, Claude} → ApolloBench 五轴得分。论点：**在 Apollo 上各模型得分方差趋零**；对照组（自由代码生成）方差爆炸。
2. **数据占比走势**：每个游戏的 数据:代码 比（宪法 §7 硬指标），逐版本逼近 100%。
3. **单游戏生成成本曲线**：一个可玩游戏的 token 成本 × 模型档位——证明"DeepSeek 价格、Claude 质量"。
4. **品类边际能力递减曲线（最便宜也最硬）**：每个新品类拉动的新 capability 数——Game D≈12 → Game E≈6 → Game F=2（第 3 条被重组裁掉）。词汇表收敛 = 引擎泛化成立的直接实证，从 git 历史即可绘出。

### 3.6 风险与诚实对冲

- **表达力天花板**（DSL 终究不如自由代码万能）→ 宪法已设唯一逃生舱：沙箱化确定性纯函数 custom capability，由工程师写、记技术债、不进 AI 回路。五个品类切片证明天花板比直觉高得多。
- **视觉质量未经人眼验证** → 真截图 + VLM 评审已在路线最前排（§2.3），不回避。
- **大厂"agent 写代码"路线竞争** → 我们不在同一条曲线上：他们赌模型无限强，我们赌**可审计 + 一致性 + 成本**；且引擎词汇表与数据资产随时间累积（每个游戏都是可 remix 的数据资产），是复利护城河。

### 3.7 终局护城河：数据飞轮 → 专用小模型

闭环 schema 给了一种自由代码路线**永远攒不出**的资产：每个生成的 manifest、每次人工修改的 diff、每局 ApolloBench 跑分与玩家留存，都是**同构、干净、可监督的结构化训练数据**。飞轮转起来之后的终局形态：

1. **专调"意图→manifest"的小模型（7B 级）**在封闭词汇表上胜过通用大模型——封闭 schema + 海量同构样本正是小模型微调的理想靶面（类比代码补全领域专用小模型的成立逻辑）；
2. 届时"弱模型可用"从营销命题变成**自家成本结构**：推理自托管，单位经济学对调 frontier API 的对手形成代差；
3. 模板/预设库被使用数据持续策展 → 新用户起点随生态变好，**内容网络效应**叠加在引擎之上。

> 命题的最终形态（见红队文档 §2 的修正）：**引擎负责"不坏"，生态负责"好玩"，模型只负责"翻译"。** 弱模型跑得通，是因为我们从没让它做难的事。
