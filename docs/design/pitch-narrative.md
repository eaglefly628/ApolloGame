## 0. 一页话术（电梯稿，可直接讲）

> "AI 视频模型生成的内容有一个行业级痛点：**只能看，不能玩**——华丽，但零交互、零留存。我们的引擎恰好是它的另一半：Apollo 把整个游戏变成纯数据（剧情分支、点击热区、数值、流程全是可校验的配置），最便宜的国产模型也能稳定生成和修改。**视频模型负责'每一帧都好看'，Apollo 负责'帧与帧连成你的故事'。**
> 我们用这条组合管线出了两个作品：一个女性向叙事游戏——剧情演出片段全部由爱诗视频模型生成，玩法骨架（分支/好感/结局）全部是引擎数据；一个梦核房间解谜——爱诗生成场景视频，玩家在视频上点击寻物解谜。两个品类，**同一台引擎、同一个视频管线、同一份资产协议**。
> 游戏是样品，团队是第一个用户，**这条'视频长出表现、数据长出玩法'的生产线才是公司。**"

## 2. 怎么融成一个故事：三层生产线

最怕的讲法是"我们有一个引擎、还有两个游戏、还用了股东的视频模型"——四件事并列 = 没有故事。正确结构是**一条生产线的三层**：

```
┌─ 表现层：爱诗视频模型 ───── 解决「好看」：场景/剧情演出/氛围，电影级表现力
├─ 玩法层：Apollo 数据引擎 ── 解决「好玩」：分支/数值/解谜/流程 = 可校验的纯数据，弱 LLM 可产可改
└─ 传播层：KB 级数据包 ────── 解决「传开」：manifest 几 KB 链接即玩（视频走 CDN 流式，同网页模型），
                              发朋友、改一句话 remix、seed/回放分享
```

两层互救对方的命门，这是故事的灵魂：

- **AI 视频的命门**：不可控、不可交互、不可重玩——纯视频"游戏"就是 FMV 老路，表现满分、游戏性零分。**Apollo 给视频装上玩法骨架**（确定性逻辑、状态、分支），视频从"一次性消费的片"变成"可交互、可重玩、可分享的内容"。
- **数据引擎的命门**（我们自审承认的最硬堡垒）：表现层天花板——占位方块和 2D 贴图撑不起商业卖相。**爱诗给引擎一张电影级的脸**，表现力一步跳代。

> 一句话：**爱诗给 Apollo 一张脸，Apollo 给爱诗一双手。**

## 3. 两个作品 = 两个品类探针（不是两个赌注）

| | 女性向叙事 | 梦核房间解谜 |
|---|---|---|
| 验证什么 | **视频演出 × 数据剧情逻辑**：每个剧情节点一段爱诗视频，引擎决定"播哪段、走哪条线、攒哪个结局" | **视频场景 × 数据交互逻辑**：视频上叠点击热区/线索/条件链，"可交互视频"新品类 |
| 品类逻辑 | 内容饥渴型（乙游玩家对新剧情/新演出的消耗是无底洞）→ **AI 量产内容价值最大化的品类** | 轻量、强氛围、天然传播（"你能找到这个房间的秘密吗"）→ **接传播故事的品类** |
| 对爱诗的展示价值 | 视频模型做"情感叙事演出"的标杆案例 | 视频模型做"可玩内容"的标杆案例 |

关键句：两个作品**共用同一台引擎、同一个视频 provider、同一份资产槽位协议**——第二个品类的边际成本断崖式低于第一个（我们引擎史上每个新品类拉动的新能力数：≈12 → ≈6 → 2，持续递减，git 历史可证）。**这证明它是生产线，不是两次手工作坊。**

## 4. 对爱诗的战略价值（你对投资方的话术）

视频模型行业集体卡在同一个问题上：**生成的视频是"工具产物"，不是"内容资产"**——用户生成完就走，无交互、无留存、无网络效应。所有视频模型公司都在找"从工具订阅到内容平台"的桥。

我们就是那座桥：**Apollo 把爱诗的视频变成可玩、可重玩、可分享、可 remix 的内容**。
- 每个用 Apollo 做的游戏都是爱诗视频的常驻消费场景（不是一次生成，是持续按剧情/解谜需求生成）；
- 可交互视频（梦核形态）是视频模型独有的新品类——文生图给不了，传统引擎也给不了；
- 传播层（数据包链接即玩）让爱诗的内容长出分发能力。

> 给爱诗的一句话：**"你们投的不是一个游戏团队，是视频模型的'可玩化'出口。"**

同时内部要清醒（红队习惯）：对外深度绑定爱诗讲协同，**架构上视频 provider 必须保持可替换**（资产槽位协议是通用的，爱诗是首选 provider 而非硬依赖）——引擎和数据资产才是我们的壁垒，不能把公司故事抵押在任何单一模型上。这条不进 deck，进我们自己的纪律。

## 5. Deck 页序建议（magic trick 结构）

1. **冷开场：直接放两支 PV**（女性向 30s + 梦核 30s）——先让人记住"这家公司的东西很好看"。
2. **翻牌页**："这两支片子来自同一条生产线——视频模型生成每一帧，数据引擎生成每一步。"（三层架构图）
3. **生产函数页**：传统团队 vs 我们（策划写数据 / 美术填资产槽 / 程序游戏层 **0 行代码**——乙游骨架已删光游戏代码，git 可证）。
4. **弱模型一致性页**：一句话生成演示 + "为什么 DeepSeek 级模型就够"（引擎承担质量下限，模型只做翻译）。
5. **品类探针页**：两个作品共用生产线 + 边际能力递减曲线（≈12→≈6→2）。
6. **传播页**：游戏=KB 级数据包，发朋友即玩、一句话 remix、seed/回放分享（Wordle 式裂变原语）。
7. **爱诗协同页**：视频模型的可玩化出口（§4 话术）。
8. **里程碑页**：PV → 本体 → 平台化（给出两个本体的明确档期）。

## 6. 给你底气的工程事实（被追问"PV 之后呢"时用）

1. **女性向本体不是从零开始**：引擎里 VN 能力已完整落地并测试（对话节点图/选项条件门控/属性/确定性掷骰/多结局），现有乙游切片的游戏层代码已删到趋零。本体开发 = 填剧情数据 + 接视频资产，**不是写游戏代码**。
2. **梦核本体的真实工程量**：逻辑层（点击热区→信号→条件链→线索/流程）在现有能力目录**零新增**；唯一缺口是表现层"视频片段"资产 kind + 播放器后端——资产层当初设计就预留了"预渲染序列"这类门（视频是它的同构物），属于顺延而非重构。
3. **两个作品的玩法数据都能被链接器/跑分器体检**（加载期校验 + 真引擎五轴跑分）——"AI 产的数据是受控的"这句话有工具链背书。
4. **确定性引擎的赠品**对两个品类都成立：存档/回放/seed 分享/未来联机，零额外成本。
