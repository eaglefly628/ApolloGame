# game108《拳律 / Rule of Three》· S1 立项卡 v1.0（Lead 记档 2026-08-04·owner 批）

> owner 2026-08-04 拍板三件：**编号 = 108**（104 仍属《世界猫牌馆》不动）· **方向 = A+B 混合** · **名字 = 《拳律》/ EN *Rule of Three*（全绿）**。
> 关联：`REQ-PIPESOFT` P3 试点写的「owner 自派 RPS 走全程」= 本项目（生产线软件的首个全程真机试点）。

## 一句话玩法

**一款打到一半，石头会开始克布的猜拳游戏**——手牌制猜拳爬塔 Roguelite：读对手性格与破绽出招，
局间捡到的遗物**直接凿改 3×3 判定表本身**；精英战与 Boss 战叠加「亮牌前加码/弃权」的押注变奏。

## 为什么做（Lead 评判结论·owner 已批）

1. **搜索位空白**：`rock paper scissors` 是长期高搜索量词，Steam 上供给几乎全是十年前的免费小玩具。
2. **引擎风险近乎为零**：猜拳的全部规则 = 一张判定表 + 一张收益表。本作是「游戏 = 数据」最纯粹的一次证明——
   **玩法核心 100% 数据表**，仅下沉一件通用引擎能力（见 §能力口径）。
3. **规模可控**：无 3D、无寻路、无物理，美术量小；竖切一个阶段内可跑出。

## 硬前提（写进立项卡防漂移）

**纯猜拳在数学上不是游戏**（零和·无信息·纳什均衡 = 均匀随机·任何策略期望胜率 50%）。
「猜拳」在本作只当**交互动词**，游戏性必须由四层供给，缺一层即退化为掷骰子：

| 层 | 供给什么 | 本作实现 |
|---|---|---|
| ① 有限手牌 | 出过即消失、弃牌区公开 → 可演绎 | 12 张牌库 / 5 张手牌 / 弃牌区全公开 |
| ② 非对称收益 | 均匀随机不再最优 → 真 EV 决策 | 石 6 / 剪 5+洞察 / 布 4+抽牌 |
| ③ 对手建模 | 玩家玩的是「读人」不是「猜数」 | 性格策略表 + 破绽 tell（含假 tell） |
| ④ 构筑 | 局与局不同 | 遗物凿改判定表本身（含增设第四手） |
| ⑤ 加码（B 线） | 亮牌前的心理博弈 | 精英/Boss 战启用押注与弃权 |

## 签名机制（卖点所在）

**判定表是数据，不是代码**——「加一个第四手」= 加一行一列，不是改代码。
别家引擎做这件事很贵，我们近乎免费；这也是本项目值得由我们做的核心理由。

## 原型竖切（验三个假设）

1 名对手（复读机）+ 12 张牌 + 3 个遗物（其中 1 个改判定表）+ 一场 5 回合对局 + 结算屏。
验三问：**读弃牌区有意思吗？石板被凿改那一下爽吗？打完想不想再来一把？**
——三问有一问为「否」，本案在纸面上死，不进 S3。

## 美术与风格意向

**暗调拳馆**（暗木·钢青·熔岩橙点睛）——house 主题起手 = apollo-kit `apolloOnyx`「玄铁」，不自写皮。
对手立绘 = 文生图（走风格包锚·如实披露）；牌面 / 规则石板 / UI = 程序化 + 风格包统一。
若 PA 风格锚最终落「织金拳馆」→ 换 `apolloBrocade` 一个参数即可，布局零返工。详见 `capability-plan.md` §4.5/§4.6。

## 红线

全年龄；押注变奏用体力/拳票，**零赌博语言与筹码观感**；判定表与猜拳规则 = 公有领域，零授权风险；
游戏层禁裸 `Math.random`（走引擎种子 PRNG）· 禁手写 DOM（LayoutNode 闭集）。

## 能力口径（S2 详见 capability-plan）

玩法面几乎全部落 **L0/L1**（现有能力重组）；**唯一缺口 = 「同时决策 × 收益矩阵结算」解释器**
（`matrix-duel`·已进引擎需求池）——因为判定表要在运行时被遗物改写、且维度可增（第四手），
静态条件→事件规则表达不了。该件通用（猜拳变体 / 蜥蜴斯波克 / 田忌赛马 / 押注对决同吃）。
