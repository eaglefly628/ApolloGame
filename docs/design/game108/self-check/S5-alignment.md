## 0. 复刻方式（先说清楚做法，再逐条对账）

稿子 README 自己写明：「this game's UI is a **closed-set, data-driven widget system** …
Everything in this design was drawn to map onto that widget set」——所以**不是移植 HTML，是照规格用控件搭**。

- **坐标与颜色**：逐字抄进 `games/game108/design-tokens.ts`（画布 1920×1080 的绝对 px + 颜色表）。
  屏文件只负责摆放，不在屏里就地写数字——数字一散开，「和稿子差多少」就再没人说得清。
- **手**：`hand-art.ts` 把稿子内联 SVG 的**每一个圆角矩形逐字搬过来**（含旋转角、描边 15、三段渐变）。
  右手用 `rotateY:180` 镜像（= 稿子的 `scaleX(-1)`）；前臂另出一张（稿子明写：手会摇、前臂不摇）。
- **面**：稿子的招牌是「墨描边 + 硬边平移投影 + 逐件渐变」，闭集 `Panel` **给不了投影**
  → `plate-art.ts` 生成一张画好了描边与投影的 SVG，走既有 `Panel.skin` 贴上（`REQ-PANELSKIN` 的原意）。
  缺口已开 **REQ-108-UI-03**（建议给 `Panel` 补 `shadow` 字段，把这件事下沉成通用件）。
- **动作**：稿子给的是 CSS 关键帧；我们**把那条曲线逐帧算出来**填 `layout` 标量
  （关键帧值一个没改）。理由见 `duel-screen.ts`：CSS 跑墙钟、与相位计时器必漂，而摇拳必须
  在 T2 那 3 秒里摇完。**副作用是好的：`REQ-108-UI-02` 那个缺口不再挡这次交付。**

## 3. 这一轮真渲染抓到的（只有看图才看得见的）

1. **生成图的源尺寸必须等于盒子尺寸**。终局蒙版用了 8×8 的占位源铺 1920×1080 →
   1280 视口下整块蒙版缩成 **1080×1080 正方形居中**盖住画面中段。`<img>` 有固有宽高比，
   某些缩放下浏览器会反过来按固有比例定尺寸。**凡生成图，源尺寸一律照盒子给。**
2. **SVG 内部 id 不能用自增计数器**。同一块面两帧之间 data-URI 不相等 ⇒ `mountUI` 判"props 变了"
   ⇒ 每帧把整屏面板全量 `outerHTML` 重建、连带把 PNG 重新请求 ⇒ **网络永远闲不下来**
   （`networkidle` 直接超时，试玩脚本连页面都进不去）。改成按内容取哈希。
3. **平移投影的起点是 `half + sh` 不是 `sh`**。写成后者等于只下移了 `sh - half`，
   4px 的投影实际只露 2px，整块牌"贴"在底上不浮——**owner 一眼看出**（「不是 3D 浮空的」）。
4. **一个 Label 塞不下两行**。稿子里「我的<br>蓄力」「赌徒<br>蓄力」是写死的两行；
   交给一个 Label 按 46px 宽自动折，折成了一字一行的四行。
5. **终局面板有 400ms 的 pop 入场**，探针到点立刻拍会拍到入场半途（半透明 + 未放到原大），
   看起来像"面板没画出来"。**是拍照时机不对，不是屏错了**——探针补 600ms 等待。

## 3b. 「再来一局」死键（owner 2026-08-07 报·已修）——**为什么全绿还是漏了**

- **现象**：终局屏点「再来一局」没反应。
- **根因**：`p1win/p2win` 是**终点态**（`blueprint.ts` 里两条 `{ id }` 不带任何 transition），
  而 `duel.next` 这个动作**没有任何消费者**——不是某个 sim 能力，也不是宿主 handler。
  信号入队之后没人取，于是"点了没事发生，且不报错"。
- **修法**：局的生命周期归宿主——**停掉旧引擎、按同一份蓝图起一台新的**。
  不做成 flow 转移的理由：回到开局要复位双方的血、六条槽、回合数、上一手，
  而按侧寻址在全局 id 路由上一直吃瘪（本仓第 5 例）；重新装载本来就是"新局"的定义，
  且与 mount 走同一条 `boot()`，不会长出"只有重开局才有的状态"。
  ⚠ `Engine.load()` 是**往现有世界里加**不是换一个世界（逐个 addSystem/createEntity），
  对同一台引擎二次 load 会把 system 加两遍 —— **是脏局不是新局**，所以必须换引擎。
  表现层记忆一并归零（不清的话，血量记忆停在 0 会让新局第一帧就判"掉血"，把上局的横幅和挨打音再放一遍）。
- **三层漏因**（已写进 `docs/playbooks/self-check.md` 成为常规环节）：
  ① 试玩走查**到"分出胜负"就收工**，从没人点过终局屏上的键——覆盖面正好在 bug 开始的地方结束；
  ② 终局屏是**另一屏**、只剩一个出口，点不动就是卡死，却最没人测；
  ③ **最该记住的一条**：`ui-inventory` 早先确实点名过 `duel.next`"够不着"。UI 重构把键摆上屏后，
     **检查从红转绿而 bug 一行没修**——那把尺子量的是「动作在屏上够得着吗」，不是「点下去有人管吗」。
     **检查转绿 ≠ 问题解决；先问它量的是不是同一件事。**
- **现在有守卫了**：试玩脚本走过终局，断言重开后双方满血 + 回到对局相位 + 槽清零 + **新局还能接着打**
  （断言数 30 → 35）。
