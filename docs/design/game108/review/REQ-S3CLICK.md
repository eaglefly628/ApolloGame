## 四、**三个我自己踩的坑**——这三处最值得你盯（也是本单最容易做假的地方）

施工过程中，**判据连错三版，三版都「看起来在检查、实测撤修照绿」**，全靠撤修验红逮出来。写在这里免得下一个人重踩：

1. **整页快照被时间驱动的东西污染**。第一版拿 `document.body.innerHTML` 当判据——倒计时环每帧都在动，整页永远"在变"，于是「输入接线整条断了」的撤修**照样判绿**。
2. **`textContent` 让噪声顺祖先链爬满全树**。第二版改成逐元素，但用了 `textContent`（含所有后代）——相位标签一跳，`app`/根屏/中区五个祖先集体误报"变了"，撤修**又判绿**。现在只取**自身直接文本节点**。
3. **注释里的 `resolveBindings` 被当成调用**。静态检查第一版没剥注释，撤修时我只删了 import 和调用、留着解释性注释，检查就被骗过去了。现在先剥注释再判。

**请核**：现在的判据是「**跑一趟全程不点的同节拍对照**，把世界自己跑出来的变化整批扣掉」。你认为这个对照实验站得住吗？有没有你能想到的、它仍然会误判的形态？（我最担心的是：**点击的效果恰好只体现在噪声元素上**的游戏，那样会假红。目前没有实例，但存量豁免名单正好挡住了大部分风险面。）
