# Game 113 · AI 量产工作流 v1

> 回应 owner 原文「七、技术落地核心要求」第 2 条：用大语言模型配合固定提示词模板，批量生成各领域的知识库与物品配置表。
> 产出格式 = [`collectible-spec.md`](./collectible-spec.md) 定义的爱好包；机器门 = [`data/check.mjs`](./data/check.mjs)。

## 0. 评判

**可行，而且是本作能做到上百门爱好的前提。** 但有三件事 LLM 做不了或做不好，流程必须把它们交给别人：

| 做不了 / 做不好 | 原因 | 交给谁 |
|---|---|---|
| **提供真实照片** | owner 要求真实照片；AI 生成的图不是真物件，也不能用来教鉴别 | 开放图库检索（大都会、史密森尼等 CC0 接口）+ 授权实拍 + 用户上传。LLM 只负责写检索词 |
| **保证知识正确** | 「硬核鉴伪」答错会伤害这群用户的信任；LLM 会编造年份、数字、出处 | ① 提示词强制「不确定就标 `uncertain`」② 第二遍自审（T5）③ **领域顾问人工签字**（`review.status: reviewed`）才能上线 |
| **精确标点** | 视觉模型给坐标只能大致准，常偏 5–10% | 视觉模型初标 → 人工在标点工具里拖准。圈大一点（`r` 0.05–0.08）也能容错 |

**尺子（数据驱动宣言）**：每个模板的输出都是 schema 里的一段闭集 JSON，最弱的模型也能按样例填；**任何一步都不生成代码**。

## 1. 流水线

```
 T1 领域骨架 ──▶ T2 藏品清单 ──▶ [人] 找真实照片 ──▶ T3 看图标点 ──▶ [人] 拖准坐标
                                                              │
      ┌───────────────────────────────────────────────────────┘
      ▼
 T4 本件知识 ──▶ 合并成 <hobby>.hobby.json ──▶ check.mjs 草稿门 ──▶ T5 自审
                                                                   │
      ┌────────────────────────────────────────────────────────────┘
      ▼
 [人] 领域顾问审校（改文、签字 review.status=reviewed）──▶ check.mjs --release 上线门 ──▶ 入库
```

| 步 | 输入 | 输出（schema 片段） | 模型 | 失败回路 |
|---|---|---|---|---|
| T1 领域骨架 | 爱好名 + 所属大类 + 大类已有字段 | `fields` · `spotTypes` · `knowledge` · `titles` · `zone` | 文本模型（强） | 校验器报错 → 带错误原文重跑 |
| T2 藏品清单 | T1 产出 | 12 件：名称、副标题、`attrs`、开放图库检索词、为什么值得收 | 文本模型 | 人工删掉找不到图的 |
| 找图 | T2 检索词 | `images[]`（key、宽高、sha256、授权、署名） | 人 / 脚本调开放图库接口 | 找不到 → 换一件 |
| T3 看图标点 | 照片 + T1 的 `spotTypes` | `spots[]`（优先套用门道模板） | 视觉模型 | 人工校准坐标 |
| T4 本件知识 | 藏品 + 照片 + 已套模板 | 0–2 张本件卡 + 模板门道的 `note` | 文本模型 | —— |
| T5 自审 | 整个爱好包 | 每张卡的「可疑论断清单」 | **另一个**模型或另一次独立调用 | 可疑项进顾问审校单 |

## 2. 固定提示词模板

所有模板共用的**系统提示词**：

```
你是「雅趣」的资深藏家编辑，也是一个懂行的老顽童。你为 55–75 岁、有钱有闲的玩家写小众爱好的门道。
硬规则：
1. 只输出一个 JSON 片段，严格符合给定的字段与闭集，不要解释，不要 Markdown。
2. 事实必须是你有把握的公认常识；任何具体年份、数字、人名、价格，没把握就不写，或在 review.notes 里写「uncertain: …」。
3. 不写健康功效（降三高、软化血管、养生之类），不写投资建议（升值、保值、必涨之类），不写价格。
4. 不涉及濒危物种材料（象牙、犀角、玳瑁、穿山甲等）的购买与使用。
5. 语气：老伙计聊天，懂行但不端着；每张知识卡正文 ≤ 180 字，一张卡只讲一个点。
6. 每张卡至少给一个出处（书名、机构说明或行业标准名），不要编造网址。
7. review.status 一律写 "draft"。
```

### T1 · 领域骨架

```
爱好：{{爱好名}}
所属大类：{{category id}}（{{大类名}}）
大类与全局已有字段（不得重复定义这些 key）：{{列出 global + 大类 fields 的 key 与 label}}

请输出：
{
  "zone": { "name": "<仓库里的分区名，≤8 字，如 酒窖 / 表柜>" },
  "titles": [ 4 档学识称号，minXp 依次为 0 / 30 / 90 / 200，称号 ≤6 字，最后一档要俏皮，如「酒痴」 ],
  "fields": [ ≤8 个这门爱好特有的规格字段；type 只能是 text/number/year/enum/multi/bool；enum/multi 必须给 options；key 用小写英文连字符 ],
  "spotTypes": [ 4–8 个这门爱好里反复出现的标准看点：{ id, label(≤8字), cardId, hint(≤20字，告诉老人去哪看), key(是否计入收藏) } ],
  "knowledge": [ 与每个 spotType 一一对应的知识卡：{ id, kind(craft/authenticity/story/jargon), title(≤16字), body(20–180字), xp(2–5), sources[{title}], review:{status:"draft"} }，其中 1–2 张可带 quiz { q, options(2–3个), answer, explain } ]
}
参考样例：{{贴一份已审校的爱好包里 spotTypes + knowledge 的前两条}}
```

### T2 · 藏品清单

```
爱好：{{爱好名}}；领域字段：{{T1 fields}}；门道模板：{{T1 spotTypes 的 id 与 label}}
请列 12 件适合收进仓库的代表性藏品，从入门到传奇排序，覆盖不同门道。每件输出：
{ "id", "name"(≤16字), "subtitle"(≤24字), "order", "tags"(≤3个),
  "attrs": { 只能用已声明字段的 key },
  "photoQuery": "<去大都会 / 史密森尼 / Wikimedia 检索真实照片的英文关键词>",
  "whyCollect": "<一句话：为什么老顽童想要它>",
  "expectedSpots": [ 预计能套用的 spotType id ] }
不要列出现代仿品，不要列出含濒危材料的物件。
```

`photoQuery`、`whyCollect`、`expectedSpots` 只供人工找图时参考，合并时丢弃，不进爱好包。

### T3 · 看图标点（视觉模型）

```
这是一张真实照片：{{图片}}，宽 {{w}} 高 {{h}}。藏品：{{name}}。
这门爱好的标准门道：{{spotTypes: id / label / hint}}
请在照片上找出 3–6 个门道点，优先套用标准门道；照片里看不到的门道不要硬标。
每个输出：{ "id", "type"(套用时写) 或 "cardId"(独有门道时写 "c-<id>"), "imageKey": "{{key}}",
  "shape": { "kind": "circle", "x": <圆心横向 0..1>, "y": <圆心纵向 0..1>, "r": <半径，相对宽度 0.03–0.1> },
  "revealZoom": <1–4，越小越显眼的地方越小> }
坐标以图片左上角为原点。整个圆必须在图片内。
```

### T4 · 本件知识

```
藏品：{{name}}（{{attrs}}）；已套用的标准门道：{{spots with type}}；T3 标出的独有门道：{{spots with cardId}}
① 为每个独有门道写一张知识卡（格式同 T1 knowledge）。
② 如果这件藏品在某个标准门道上有特别之处，给那个门道点写一句 note（≤60 字）。
没把握的事实不要写。
```

### T5 · 自审（换一个模型，或全新的独立调用）

```
下面是一份爱好包里的知识卡。逐张列出其中所有「可核查的事实论断」（年份、数字、人名、机构、工艺描述），
对每条给出：{ "cardId", "claim", "confidence": "high/medium/low", "why" }。
只要有一条 low，把该卡标记为需要顾问重点审。不要改写原文。
```

## 3. 人工环节

| 环节 | 谁 | 做什么 | 验收 |
|---|---|---|---|
| 找图 | 内容运营 | 按 T2 检索词在开放图库找图；记录授权与署名；算 sha256 | 每件至少 1 张主图，授权不是 TBD |
| 拖准坐标 | 内容运营 | 在标点工具里把 T3 的圈拖到准确位置 | 圈罩住门道本体 |
| 顾问审校 | 领域顾问（owner 原文：KOL / UP 主顾问） | 读 T5 可疑清单，改文、签字 | `review: { status: "reviewed", by: "<顾问>", at: "<日期>" }` |

**标点工具**（后续需要）：可以就是游戏的细看页加一个「编辑模式」：拖圈、改半径、导出 JSON。等 S2 通过后再做，不先写。

## 4. 产能估算（每门爱好）

| 项 | 数量 | 耗时（估） |
|---|---|---|
| T1 + 校验 | 1 次 | 10 分钟 |
| T2 + 找图 | 12 件 | 2–3 小时（找图是瓶颈） |
| T3 + 拖准 | 12 件 × 4 点 | 1 小时 |
| T4 + T5 | 12 件 | 20 分钟 |
| 顾问审校 | 约 60 张卡 | 顾问 2–3 小时 |
| **合计** | 12 件藏品、约 50 个门道点、约 60 张卡 | **约 1 人日 + 顾问半天** |

首批 6 门爱好 ≈ 6 人日 + 顾问 3 天。
