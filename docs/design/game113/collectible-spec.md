## 0. 版本与兼容规则

| 规则 | 内容 |
|---|---|
| 版本号 | 每个数据文件写 `"specVersion": "1.0"`。**大版本**（1、2…）同时体现在 `schema` 名里（`game113.hobby/1`）；**小版本**（1.0、1.1…）只写在 `specVersion` |
| 1.x 内只做加法 | 只允许**新增可选字段、新增枚举值、放宽限制**。所以任何 1.0 的文件在 1.1、1.2… 下永远有效，量产好的数据不用返工 |
| 需要破坏性修改时升 2.0 | 改名、删字段、改含义、收紧限制 → 升大版本，**必须同时提交迁移脚本**（1 → 2 自动转换），旧文件不手改 |
| 程序怎么读 | 运行时能读**当前大版本和上一个大版本**；读到不认识的新字段就忽略（向前兼容）；校验器遇到比自己新的小版本会报「请先升级校验器」，避免旧校验器误判新数据 |
| 弃用流程 | 要去掉的字段先在一个小版本里标「弃用」（照读、不再写），下一个大版本再删 |
| 预留字段 | `modules` 里的 `compare / process / breed / grade`，藏品上的 `care`：v1.0 只占位，校验器拒收，**等对应玩法立项时在小版本里定形** |
| 变更记录 | 见文末 §13，每次改版都要记 |

## 1. 一张卡片里有什么（全貌）

一件藏品 = 一张卡片。卡片上的每样东西都对应一个玩法或一笔经济：

| 卡片上的东西 | 字段 | 用在哪（玩法 / 经济） |
|---|---|---|
| 名字、副标题、标签 | `name` `subtitle` `tags` | 仓库、市集、爱好馆的卡面 |
| 真实照片（主图、特写） | `images[]` | 细看（放大）、三消棋子、所有卡面 |
| 门道点 | `spots[]` | **找门道**（学）；`key` 决定收藏条件 |
| 瑕疵点 | `spots[].flaw` | **找瑕疵**模式 |
| 知识卡（本件独有） | `cards[]` + 爱好的 `knowledge` | 读卡涨学识、首读得雅钱；带 `quiz` 的进**考级题库** |
| 规格 | `attrs` | 规格表、筛选、行情板块细分 |
| 品相维度 | `attrs` 里的分级字段 | 品级计算、**养护**（可养维度） |
| 品级 | `tier` | 卡角吊牌；决定雅钱价 |
| 雅钱价 | 爱好 `grading.values[品级]` × 行情指数 | **市集买卖**、仓库身价、持仓盈亏 |
| 行情板块 | 由 `market.segmentBy` + 品级推出 | **走势图**（日更指数） |
| 能不能在市集卖 | `listed` | 市集在售列表 |
| 获得途径 | `acquire` | 市集 / 新手礼 / 考级奖品 |
| 收藏条件 | `collect` | 待鉴区 → 正式入仓 |
| **档案** | `profile` | 藏品详情页：简介、来历、类比、对比、冷知识、轶事、挑法、养护小窍门、相关 |
| 来源与审校 | `images[].source` `review` | 版权与上线门 |

爱好层（一门爱好一份）给卡片提供共用的东西：字段字典、品相分级与雅钱档位、保养品、门道模板与知识库、行情设定。全局文件提供五大类、价位带、经济参数。

## 2. 三层结构

```
┌──────────────────────────────────────────────────────────────┐
│ ③ 行为模块 modules（开关·所有爱好共用同一份引擎实现）               │
│   v1.0 开放：quiz 小考                                          │
│   预留：compare 真仿对比 · process 工序 · breed 繁育 · grade 估品   │
├──────────────────────────────────────────────────────────────┤
│ ② 爱好层（只加描述与参数，不加行为）                               │
│   fields 字段字典 · grading 品相分级与雅钱 · careItems 保养品         │
│   spotTypes 门道模板 · knowledge 领域知识库 · market 准入与行情       │
├──────────────────────────────────────────────────────────────┤
│ ① 卡片（藏品）：核心最小集 + 档案 + 经济钩子                         │
└──────────────────────────────────────────────────────────────┘
全局：categories.json（大类、基础字段、雅钱、价位带）· economy.json（经济参数）
```

**铁律**：扩展一门新爱好**永远只填数据、不写代码**。爱好层只能加描述和参数；想要新行为，只能在全局打开一个通用模块，而且模块按五大类长出来，不按单个爱好长。

## 3. 字段字典（三层继承）

```
global（所有爱好）         maker 出品 · origin 产地 · era 年代
  └ 大类（categories.json）  aging：vintage 年份 · aged-years 陈化 · storage 仓储
      └ 本爱好（fields）      walnut：variety 品种 · edge-mm 尺寸 · pairing 配对 · patina 包浆 …
```

- 类型闭集：`text / number / year / enum / multi / bool`；不允许嵌套、不允许公式。
- 下层只能追加，**不能重定义**上层的 key。
- 字段标记：`filter` 作筛选项 · `ordered`（仅 enum）选项从低到高、可作品相维度 · `careable`（仅品相维度）可以被保养品提升。

## 4. 门道点与知识卡

```jsonc
"spotTypes": [{ "id": "yinpi", "label": "阴皮", "cardId": "k-yinpi", "hint": "表面发黑发暗的那块" }],
"knowledge": [{ "id": "k-yinpi", "kind": "authenticity", "title": "阴皮", "body": "…", "xp": 4, … }]
"spots": [{ "id": "dark", "type": "yinpi", "imageKey": "…", "shape": { "kind": "circle", "x": 0.72, "y": 0.6, "r": 0.06 },
            "revealZoom": 2.5, "flaw": true, "key": true, "note": "这就是它只算普品的原因。" }]
```

- 坐标 = 相对图片的归一化圆（0..1，左上原点）；半径相对图片宽度。与分辨率无关。
- 门道点写 `type` 就继承模板的知识卡、提示语和 `key`；本件独有的门道直接给 `cardId`。
- `note`：本件在通用知识之外补一句，叠在知识卡下方。
- `flaw: true`：瑕疵点，有瑕疵点的藏品出现「找瑕疵」模式（对应知识卡建议为 `authenticity` 鉴别类）。
- 知识卡 `xp`：同一张卡全局只加一次学识；首次读懂同时按 `economy.json` 发雅钱。
- 带 `quiz` 的知识卡自动进入该爱好的**考级题库**；每级考试抽 `economy.exam.questions` 题，题库不足时校验器提醒。

## 5. 品相分级与品级计算

```jsonc
"grading": { "dims": ["pairing", "skin", "edge-shape", "flaws", "patina"],
             "tiers": ["入门", "普品", "精品", "珍品"],
             "values": [10, 40, 150, 400] }
```

**品级计算规则（v1.0 定死，运行时与校验器同一公式）**：

```
每个维度：档位序号 ÷ (档位数 − 1)            → 0..1
品级序号 = round( 各维度平均值 × (品级数 − 1) )
```

- 藏品上的 `tier` 仍然要写（方便人读、AI 产出），但**必须等于计算结果**，校验器强制。
- 养护让某个维度升一档后，运行时按同一公式重算品级，雅钱价跟着变。
- 标了品级就必须填全所有维度；看不出品级的（未开皮的青皮核桃）不标 `tier`，也就没有雅钱价。

## 6. 雅钱、市集与行情

- **雅钱**（`categories.json` 的 `currency`）：游戏内唯一货币。不能用人民币买、不能提现、不能玩家间转账。来源与参数在 `economy.json`：考级奖励、首次读卡、学识兑换（汇率与每日上限）、看广告（奖励、每日上限、屏蔽类目）、卖出（手续费）、新手礼。
- **雅钱价** = `grading.values[品级序号]` × 所属板块当天的**行情指数**。
- **价位带**：爱好的 `market.priceBand` 决定最高品级雅钱的允许区间（刻意压缩真实价差，无法反推真实价格）。
- **行情板块**：`爱好/品级`；如果写了 `market.segmentBy`（例如核桃按 `variety` 品种），则为 `爱好/品种/品级`，例如 `walnut/狮子头/精品`。
- **每日指数文件**（`*.index.json`，`schema: game113.index/1`）：

```jsonc
{ "schema": "game113.index/1", "specVersion": "1.0", "hobby": "walnut",
  "series": [ { "date": "2026-09-27", "values": { "walnut/狮子头/精品": 1.03 } },
              { "date": "2026-09-28", "values": { "walnut/狮子头/精品": 1.05 } } ] }
```

  - 日期逐日连续；没有新数据的日子**沿用前值写一条**（不编造波动，也不断档）。
  - 单日变动不超过 `economy.market.dailyChangeCap`（初版 ±3%）。
  - 板块必须是该爱好推得出的板块；出现过的板块之后每天都要有值。
  - 游戏逻辑把当天的指数当作外部输入读取，自身仍然确定、可重放。
- `market` 的其余字段（流通性、渠道、价位量级、合规）是内部运营数据，不在玩家界面显示。

## 7. 养护与保养品（三消产出）

```jsonc
{ "key": "patina", "label": "包浆", "type": "enum", "ordered": true, "careable": true,
  "options": ["生核", "初上色", "红润", "包浆厚"] }
"careItems": [{ "id": "walnut-brush", "name": "核桃刷", "iconKey": "g113.walnut.care.brush",
                "raises": ["patina"], "perStep": 3 }]
```

- 三消「擦擦亮」里，某门爱好的棋子消除后产出这门爱好的保养品。
- 在藏品上用 `perStep` 个保养品，可以把 `raises` 里的一个可养维度提升一档；每件每天最多养 `economy.care.perItemPerDay` 次；到顶封顶。
- 不是每门爱好都能养：红酒的分级、液位、酒标都养不回来，所以红酒没有可养维度、没有保养品，它的藏品不进三消棋盘。这是数据决定的，不是特例代码。

## 8. 档案（owner 2026-09-28：「每件物品像一张卡片，除了描述、细节，还有历史、类比、对比……」）

```jsonc
"profile": {
  "summary": "四座楼是狮子头里的名品种……（20–120 字）",
  "sections": [
    { "kind": "history",  "title": "狮子头的来历", "body": "……" },                  // 或 timeline
    { "kind": "history",  "title": "拉菲的几个年份", "timeline": [ { "when": "1855", "text": "……" } ] },
    { "kind": "analogy",  "title": "挑核桃像挑双胞胎", "body": "……" },
    { "kind": "compare",  "title": "和生官帽比一比", "with": "guanmao-raw",
      "points": [ { "aspect": "尖", "self": "闷尖", "other": "尖挺" } ] },
    { "kind": "trivia",   "title": "……", "body": "……" },
    { "kind": "story",    "title": "……", "body": "……" },
    { "kind": "pick",     "title": "挑狮子头看四样", "body": "……" },
    { "kind": "care-tip", "title": "先刷后盘", "body": "……" },
    { "kind": "related",  "title": "同一匣里的", "refs": ["guanmao-raw", "qingpi"] }
  ],
  "review": { "status": "draft" }
}
```

| 段落类型 `kind` | 必需字段 | 说明 |
|---|---|---|
| `history` 来历 | `body` 或 `timeline`（2–8 条「时间 + 一句话」） | 名字由来、发展历史、这件东西的年份节点 |
| `analogy` 类比 | `body` | 用老人熟悉的东西打比方 |
| `compare` 对比 | `with` + `points`（2–6 行「方面 / 这件 / 那件」） | 对比对象必须是本爱好的**另一件真实藏品**（跨爱好写「爱好id/藏品id」）；界面画成对比表 |
| `trivia` 冷知识 | `body` | |
| `story` 轶事 | `body` | 行里的故事、人物 |
| `pick` 挑法 | `body` | 怎么看、怎么挑；**不写价格、不写投资建议** |
| `care-tip` 养护小窍门 | `body` | 与养护玩法呼应 |
| `related` 相关 | `refs`（1–6 个藏品 id） | 卡片之间互相串门 |

- 官方藏品**必须**有档案；建议至少 3 段，且有「来历」。
- 每段可带 `sources`；整份档案有一个 `review`，和知识卡一样过顾问审校才能上线。
- 档案全文同样过内容红线（不写健康功效、不做投资承诺）。
- 段落类型是闭集：以后要加新类型（比如「名家」「产地地图」），在 1.x 小版本里**追加**枚举值即可，老卡片不受影响。

## 11. 开一门新爱好：扩展步骤

| 步 | 做什么 | 产出 | 谁来做 |
|---|---|---|---|
| 0 | 过准入：有合法可买的市场吗？品相能分级吗？ | `market` + 分级草案 | T0 + 人工复核 |
| 1 | 选大类 | 自动继承大类字段 | 人 |
| 2 | 领域字段（含 ordered 分级维度、careable 可养维度） | `fields` `grading`（含雅钱档位） | T1 |
| 3 | 保养品（有可养维度才需要） | `careItems` | T1 |
| 4 | 门道模板 + 领域知识卡（带小考，凑够考级题库） | `spotTypes` `knowledge` | T1 → 顾问审校 |
| 5 | 藏品清单与找图 | 12 件、真实照片 | T2 + 人工 |
| 6 | 标门道点（含瑕疵点） | `spots` | T3 + 人工校准 |
| 7 | 本件知识与**档案** | `cards` `profile` | T4 → 顾问审校 |
| 8 | 行情 | 板块设定 + 每日指数文件 | 运营 + AI 抽样 |
| 9 | 过门 | 草稿门 → 顾问审校 → `--release` 上线门 | 机器 + 人 |

## 12. 校验器（机器门）

```bash
node docs/design/game113/data/check.mjs                          # 校验 examples/ 下全部爱好包与行情文件
node docs/design/game113/data/check.mjs a.hobby.json b.index.json # 指定文件（草稿门）
node docs/design/game113/data/check.mjs --release a.hobby.json    # 上线门
```

schema 结构校验之外的语义检查：
- **版本**：缺 `specVersion`、文件小版本比校验器新。
- **准入与雅钱**：缺 `market` / `grading`、流通性越界、`values` 与品级不对应 / 不递增 / 超出价位带。
- **品相与品级**：维度不是 ordered enum、`ordered` 或 `careable` 标错位置、品级不在列表、缺维度、**品级与计算结果不一致**。
- **养护**：保养品提升的不是可养维度；有可养维度却没保养品（提醒）。
- **行情**：`segmentBy` 不是 enum 或用了品相维度、藏品缺细分字段；指数文件日期断档、单日变动超封顶、板块不存在、板块中途缺值。
- **字段字典**：未声明的 attrs、重定义上层字段、枚举 / 数值越界。
- **跨引用**：门道模板、门道点、图片、特写、对比对象、相关藏品是否都对得上。
- **坐标**：热区圆超出图片。**收藏条件**：key 门道点够不够。
- **档案**：官方藏品缺档案、各段落类型缺必需字段或误用字段；少于 3 段、缺来历（提醒）。
- **考级**：称号档数不够最高级考试；题库不足（提醒）。
- **来源与审校**：真藏的图与卡状态、CC-BY 署名；上线门下的未审校卡、未审校档案、TBD 图。
- **内容红线**：知识卡与档案里的健康功效、投资承诺说法。

**自证（2026-09-28，v1.0）**：
- 四份爱好包 + 一份行情文件通过草稿门；`--release` 按预期拦截（内容仍是 draft、图片仍是 TBD）。
- 构造 **43 种坏数据**：基础 11 · 准入与分级 7 · 雅钱 5 · v1.0 新规则 16（版本 2、可养 2、品级计算 1、行情细分 2、档案 7、考级 1、段落闭集 1）· 行情文件 4。**每一种都报出预期的那条 ERROR、退出码 1**（逐条按错误原文锚点核对，不只看退出码）。
