## 0. 对原文第 1 条的评判

原文要求每件物品包含四样：多状态高清贴图路径、交互热点坐标、鉴赏知识文案、演化时间条件。**方向对，而且这是本作最重要的一份接口**：玩法是一个通用解释器，所有内容都是这份数据。落地时改了四处：

| 原文 | 改成 | 理由 |
|---|---|---|
| 贴图**路径** | 资产 **key** + 图片宽高 + `sha256` + 授权来源 | 热点坐标和某一张具体的图强绑定，换了图坐标就全错。钉死哈希，换图时校验器能发现。路径也违反仓库的皮肤槽铁律 |
| 热点坐标 | **归一化圆形热区**（0..1，相对图片） | 与图片分辨率无关，手机、平板、高清特写都能用同一套坐标。引擎的点击命中本来就只支持到包围盒，圆形足够，不需要补多边形拾取 |
| 鉴赏知识文案 | 拆成**领域知识库**（可复用）+ **本件卡**（独有） | 「液位」这条知识对每一瓶老酒都成立。写一次、处处引用，AI 量产省大半，口径也一致 |
| 多状态 + 演化时间条件 | 收进**可选模块 `care`**，首期不开 | owner 已定首期只做「收藏 + 看细节」。演化还依赖引擎目前没有的「离线天数」能力。字段位置先留好，不影响后续扩展 |

## 1. 三层结构

```
┌──────────────────────────────────────────────────────────────┐
│ ③ 可选模块 modules（行为开关）                                   │
│   quiz 小考（首期开）· compare 真仿对比 · care 养 · process 工序   │
│   · breed 繁育 · grade 品相评级                                  │
│   → 每个模块是引擎里的一份通用实现，所有爱好共用；爱好只填参数         │
├──────────────────────────────────────────────────────────────┤
│ ② 领域扩展（只加「描述」，不加「行为」）                            │
│   fields     字段字典：这门爱好特有的规格（红酒的分级、雪茄的环径）     │
│   spotTypes  门道模板：这门爱好反复出现的标准看点（液位、木塞、封条）   │
│   knowledge  领域知识库：模板指向的通用知识卡                         │
├──────────────────────────────────────────────────────────────┤
│ ① 核心最小集（解释器唯一消费面·所有爱好完全相同）                     │
│   item = id + name + images[] + spots[] + cards[] + collect       │
└──────────────────────────────────────────────────────────────┘
```

**铁律**：
- **解释器只认第 ① 层。** 第 ② 层对游戏逻辑而言只是「多几行展示用的数据」和「引用的简写」，所以扩展一门新领域**永远不需要改代码**。
- **第 ② 层只能加描述，不能加行为。** 字段类型是闭集（`text / number / year / enum / multi / bool`），不允许嵌套对象、不允许公式。领域想要「行为」（比如雪茄要养），只能打开第 ③ 层的通用模块。
- **第 ③ 层的模块只按大类长出来，不按爱好长出来。** owner 的五大类恰好对应四个模块（见 `hobby-catalog.md` 总览），一共就这么多。

### 1.1 字段字典三层继承

```
global（所有爱好）   maker 出品 · origin 产地 · era 年代
  └ 大类（categories.json）  aging：vintage 年份 · aged-years 陈化 · storage 仓储
      └ 本爱好（hobby.fields） wine-bordeaux：appellation 产区 · classification 分级 · grapes 葡萄 · volume 容量
```

- 下层**只能追加，不能重定义**上层已有的 key（校验器拦）。「年份」在所有岁月沉淀类爱好里都叫 `vintage`，将来做跨爱好筛选和搜索时是同一个口径。
- 只有一层继承链（全局 → 大类 → 爱好），不做更深的继承，保证最弱的模型也能看懂。
- `filter: true` 的字段会成为爱好馆里的筛选项（例如按「分级」筛红酒）。

### 1.2 门道模板与知识复用

```jsonc
// 领域层写一次
"spotTypes": [{ "id": "ullage", "label": "液位", "cardId": "k-ullage", "hint": "看瓶肩的酒液", "key": true }],
"knowledge": [{ "id": "k-ullage", "kind": "authenticity", "title": "瓶肩的酒液高度", "body": "…", ... }]

// 每件藏品只需要标位置
"spots": [{ "id": "level", "type": "ullage", "imageKey": "…main", "shape": { "kind": "circle", "x": 0.5, "y": 0.3, "r": 0.07 } }]
```

- 门道点写了 `type`，就继承模板的知识卡、提示语和「是否计入收藏」。
- 这件藏品有额外的讲究时，用 `note` 补一句（叠在通用知识卡下面显示），不必另写一张卡。
- 真正独有的门道（这件东西的典故），不写 `type`，直接给 `cardId` 指向本件 `cards`。

### 1.3 品相分级（`grading` + 藏品 `tier`）

owner 认可的流通性标准里有一半是「存在明确品相分级」。这正好给了藏品**天然的等级**，不需要编造稀有度：

```jsonc
"fields": [
  { "key": "pairing", "label": "配对", "type": "enum", "ordered": true, "options": ["不配对", "基本配对", "天生配对"] },
  { "key": "flaws",   "label": "瑕疵", "type": "enum", "ordered": true, "options": ["明显", "轻微", "无"] }
],
"grading": { "dims": ["pairing", "skin", "edge-shape", "flaws", "patina"], "tiers": ["入门", "普品", "精品", "珍品"] }
// 藏品上：
"tier": "精品", "attrs": { "pairing": "基本配对", "flaws": "无", ... }
```

- **分级维度就是字段**：`ordered: true` 的 enum 字段，选项从低到高排。不新增任何概念，AI 和人都只是在填字段。
- **品级由编辑标注**（`tier`），不用公式算。校验器按维度估算一个参考品级，差两档以上报警，提醒复核。
- 标了品级就必须填全所有分级维度。看不出品级的（未开皮的青皮核桃）可以不标。
- 这组维度也是未来 `grade` 模块（看图判品级、给自己的真藏估品）的全部输入，届时不需要改数据。

### 1.4 流通性准入（`market`）

🟢 owner 硬规则：收藏物必须有合法的、能用钱买到的市场，玩家买不买得起不影响。数据上：

- 每个爱好包**必须**有 `market`（流通性 1–5 + 渠道，1–5 都算合格，只决定开馆先后）和 `grading`，缺一个校验器就拒收。
- `market` 是**内部运营元数据，不在玩家界面显示**。只写价位量级（「几十元」「数万元级」），不写具体价格。面向中老年，不在界面上展示行情，避免引导炒作。**玩家是否看得到价格，是一个待 owner 定的产品问题**（见 `brief.md`）。
- `market.compliance` 写销售合规限制（例如中国禁止网上销售烟草，雪茄不做任何购买导流）。

## 2. 核心最小集

一件合法藏品最少只要这些（在已有门道模板的爱好里）：

```json
{
  "id": "latour-2005",
  "name": "拉图古堡 2005",
  "images": [{ "key": "g113.wine-bordeaux.latour-2005.main", "w": 3000, "h": 4000, "sha256": "TBD",
               "source": { "license": "TBD", "credit": "待授权" } }],
  "spots": [{ "id": "level", "type": "ullage", "imageKey": "g113.wine-bordeaux.latour-2005.main",
              "shape": { "kind": "circle", "x": 0.5, "y": 0.3, "r": 0.07 } }],
  "collect": { "keySpots": "all" }
}
```

**加一件藏品 = 一张照片 + 在照片上点几个圈。** 知识来自领域知识库。

### 2.1 字段语义（解释器行为）

| 字段 | 含义 |
|---|---|
| `images[].role` | `main` 主图（至少一张）· `closeup` 放大到某处时淡入的特写 · `compare` 真仿对比图（预留） |
| `spots[].shape` | 圆心 `x, y` 相对图片宽高；半径 `r` 相对图片宽度。校验器保证圆不出图 |
| `spots[].revealZoom` | 放大到该倍数以上门道点才浮现（缺省 1 = 一开始就能找到） |
| `spots[].key` | 是否计入收藏条件；缺省继承门道模板，模板也没写则为否 |
| `collect.keySpots` | `"all"` = 找齐全部 key 门道点才能收藏；数字 = 找到 N 个即可 |
| 知识卡 `xp` | 读完一张卡给这门爱好加的学识。**同一张卡全局只加一次**：在第二瓶酒上再读「液位」，门道点照样算找到（计入收藏），但不再加学识。防止刷分，也符合「学过就是学过」 |
| `titles` | 学识称号阶梯，`minXp` 严格升序，第一档为 0 |
| `tier` | 品级，取自本爱好 `grading.tiers`；界面在藏品卡角上显示 |
| `origin: "user"` | 用户上传的「我的真藏」。图片授权必须是 `user-upload`，卡片审校状态必须是 `owner-claim`（界面显示「藏家自述」） |
| `review.status` | `draft` → `ai-checked` → `reviewed`（官方）；上线门只放行 `reviewed` / `owner-claim` |

## 3. 开一门新爱好：扩展步骤

以「古董复杂机械表」为例，从零到可上线：

| 步 | 做什么 | 产出 | 谁来做 |
|---|---|---|---|
| 0 | 过准入：有没有合法的、能用钱买到的市场？品相能不能分级？ | `market` + 分级维度草案 | 人（提示词 T0 辅助） |
| 1 | 选大类 | `category: "mechanics"`，自动继承 model 型号 / serial 编号 / condition 状态 | 人（查 `hobby-catalog.md`） |
| 2 | 补领域字段（≤ 8 个） | `brand-caliber` 机芯型号、`complications` 复杂功能（multi：三问 / 陀飞轮 / 万年历…）、`case` 表壳材质 | LLM（提示词 T1） |
| 3 | 写门道模板（4–8 个）+ 领域知识卡 | 游丝、红宝石轴承、日内瓦纹、表背编号、三问音锤…… 每个配一张通用知识卡 | LLM 起草（T1）→ 顾问审校 |
| 4 | 称号阶梯 | 入门 / 懂行 / 行家 / 表痴 | LLM（T1） |
| 5 | 选藏品清单 | 12 件，每件给开放图库检索词 | LLM（T2）+ 人工找图 |

**不需要**：新代码、新 UI、新玩法设计。

## 4. 版本与演进

- `schema: "game113.hobby/1"`：在 /1 内只做**加法**（新增可选字段、新增枚举值）。
- 改名、删字段、改语义 → 升到 /2，同时提供迁移脚本，旧文件不手改。
- 预留模块（`care / process / breed / grade / compare`）的数据形状，**在该模块立项时再定稿**。现在只占位，不写死，避免提前设计错误的结构。校验器在引擎实现之前拒收这些模块。

## 5. 校验器（机器门）

```bash
node docs/design/game113/data/check.mjs                 # 校验 data/examples/ 全部
node docs/design/game113/data/check.mjs a.hobby.json    # 校验指定文件（草稿门）
node docs/design/game113/data/check.mjs --release a.hobby.json   # 上线门
```

schema 结构校验之外，还拦这些 schema 表达不了的问题：

- 准入：缺 `market` 或 `grading`、流通性不在 1–5。
- 品相分级：维度不是 ordered enum、`ordered` 用在非 enum 上、品级不在列表、标了品级却缺维度；品级与维度估算差两档以上报警。
- 字段字典三层合并：未声明的 attrs、重定义上层字段、枚举值越界、数值越界。
- 跨引用：门道模板指向的知识卡、门道点的 type / cardId / imageKey / closeupKey 是否存在。
- 坐标：热区圆超出图片边界（按宽高比折算）。
- 收藏条件可达：key 门道点数量 ≥ keySpots。
- 模块：开了引擎未实现的模块、带小考却没开 quiz、出现预留的 care 块。
- 来源与审校：用户真藏的图与卡状态、CC-BY 署名、上线门下的未审校卡和 TBD 图。
- **内容红线**（面向中老年）：健康功效（「降三高」「软化血管」）与投资承诺（「必涨」「保值增值」）一律拦截。

**自证**（2026-09-28）：三份样例（红酒、雪茄、文玩核桃）通过草稿门，`--release` 按预期拦截（卡片仍是 draft、图片仍是 TBD）。另构造 18 种坏数据：
- 11 种基础错误：坏引用、重定义字段、枚举越界、未声明字段、热区越界、收藏不可达、开 care 模块、健康功效、真藏卡状态、未知字段、旧大类 id。
- 7 种准入与分级错误：缺 market、缺 grading、流通性 0、维度非 ordered、品级缺维度、未知品级、ordered 用在文本字段。

**每一种都报出预期的那条 ERROR，退出码为 1**（按错误原文锚点核对，不只看退出码）；品级与维度不一致的样例按设计只报警、不失败。
