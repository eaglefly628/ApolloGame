## 1. 一句话

> 🟢 老顽童的百宝仓库：从上百门小众爱好里挑你感兴趣的入坑，每门爱好都是一套**真实物件**的收藏。点开细看、找到门道，学识就涨一截；再把仓库晒给同好看。

## 2. 定位（v2 与 v1 的区别）

| | v1（废弃） | v2（当前） |
|---|---|---|
| 是什么 | 古玩收藏 / 博古斋 | 🟢 **小众爱好大集合**：酒、雪茄、表、茶、车、钓鱼、鸣虫……（全表约 115 门） |
| 入口 | 书房 | 🟢 **首页 = 爱好广场**（挑爱好）；**我的东西都在「仓库」** |
| 玩家 | 静斋主人（文人） | 🟢 **老顽童**：什么都想玩两下，爱显摆、爱串门、不端着 |
| 玩法 | 每个领域一套养护、修复机制 | 🟢 **所有爱好通用两件事**：**收藏** + **点细节学知识**（不按品类单独设计） |
| 图片 | 实拍级 | 🟢 **必须是真实照片** |
| 社交 | 后期可选 | 🟢 **社交为底座** |

### 2.1 准入硬规则（🟢 owner 2026-09-28）

**商品流通性**：一门爱好的收藏物必须有合法的、能用钱买到的真实市场，并能分出品相等级；玩家买不买得起不影响（名种马照收），钱买不到或不许买的不收。逐条审查见 `hobby-catalog.md` 文末，数据上由校验器强制（`market` + `grading` 必填）。品相分级同时成为藏品的**品级**（入门 / 普品 / 精品 / 珍品），不需要编造稀有度。

**🟢 owner 已定（2026-09-28）：不显示真实价格，折算成我们自己的货币「雅钱」（工作名）。** 每门爱好给每个品级定一个雅钱值，藏品的雅钱 = 它的品级对应值；真实价差按价位带大幅压缩（老爷车最高档与核桃最高档只差约 5 倍），反推不出真实价格。~~首发雅钱只作估值与仓库身价~~ → **owner 同日更新：雅钱是私有货币，用于收藏品的流通和购买，价格跟随真实行情并有走势图，知识（考级）可换雅钱**，详见 `gameplay.md`。仍坚持：不能提现、不能玩家间转账。规则见 `collectible-spec.md` §1.5。

## 3. 核心循环（🟡 推荐）

```
  爱好广场 ──入坑──▶ 这门爱好的「馆」（图鉴：全部藏品，已收的亮、没收的是剪影）
                          │
                          ▼ 点开一件
                   细看（真实照片 · 双指放大）
                          │ 找到隐藏的「门道点」→ 读知识卡 → 学识 +N
                          ▼
              看懂了（找齐关键门道点）──▶ 收入我的仓库 ✚
                          │
                          ▼
     仓库 ──晒──▶ 同好圈（点赞 · 评论 · 串门看别人的仓库 · 关注）
                          │
                          └─ 在别人的藏品上也能找门道点 → 学识 + 社交双收
```

**关键设计（🟡 待 owner 确认）**：**「看懂一件，才收一件」**。收藏不是花钱买，是把这件东西的门道找齐。收藏和学知识因此合成**同一个动作**，也不需要为任何品类单独设计玩法。

### 3.1 藏品从哪来（🟡 推荐两个来源）

1. **官方馆藏**：每门爱好一份图鉴（真实照片 + 专业标注的门道点 + 知识卡）。首批来自博物馆开放图库（大都会、史密森尼等，CC0）加合作藏家、商家授权实拍。
2. **我的真藏**（🟡 强烈推荐，也是社交的发动机）：老登手里本来就有真东西——酒柜里的酒、抽屉里的表、茶仓里的饼。让他**拍照上传，自己在图上点出门道、写一句讲究**，就成了仓库里的一件「真藏」。别人来串门时，可以在他的真藏上找点、点赞、请教。
   - 这正好满足 owner 的三条要求：真实照片、挖掘老登的爱好、社交为底座。
   - 代价：UGC 需要审核（图片、文字），真藏的知识准确性由主人负责，界面上要标明「藏家自述」，与「官方审校」区分。

### 3.2 成长

- 每门爱好一条**学识**（找到门道点、答对小考就涨）。
- 学识到一定程度获得该门的**称号**，例如红酒「入门 → 懂行 → 行家 → 酒痴」，由老顽童风格的俏皮称号组成。
- 全局看**「玩过几门」**：老顽童的荣誉是「杂」，不只是「精」。

## 4. 社交底座（🟢 owner：社交是很重的重点 · ⏸ owner 2026-09-28 定：往后放，先做好产品本身）

完整设计见 **[`social.md`](./social.md)**。要点：
- 七根支柱：晒真藏 · **掌眼**（同好按该爱好的品相维度投票估品级，得出雅钱）· 串门 · 同好圈 · 请教问答 · 提名偏门 · 雅集 / 以物易物 / 师徒（后续）。
- 声望核心是**眼力**（掌眼与多数一致的比例），不是财富；不做全服财富榜。
- 老年人安全红线：拦截联系方式和收款码、不撮合真实交易、私信仅限老伙计、防荐股与保健品、实名与内容审核。

## 5. 目标人群硬约束（适老 · 不变）

- 正文 ≥ 18pt、关键数字 ≥ 28pt，支持大字模式（×1.25）。
- 点击热区 ≥ 56pt；手势只用单击、双指缩放、单指拖动。
- 高对比；每屏一个主操作；文案用完整中文短句。
- 不做红点轰炸、倒计时逼迫。

## 6. 首个竖切范围（🟡 推荐）

- **爱好广场**：流通性准入合格的约 50 门爱好都能看到；**只有 6 门有内容**（红酒、雪茄、威士忌、机械表、普洱茶、文玩核桃 —— 见 `hobby-catalog.md` 首屏建议），其余显示「即将开馆 · 想看的点一下」（顺便收集需求，决定下一批开哪门）。
- 每门首发 **12 件官方藏品**，每件 3–6 个门道点，共约 70 件、约 300 张知识卡。
- 仓库、细看、知识卡、收藏时刻、同好圈、串门、我的真藏上传。

## 7. Lead 评判（v2 更新）

> 实查底稿（2026-09-27）：`src/assembly/capability-registry.ts` 全部能力 + `src/net` + `src/services`。

### 7.1 v2 让工程**变简单**的部分

- 去掉按领域的养护、修复、蜕变机制，也去掉真实时间依赖（v1 风险第 2 条的「每日养护 / 漆干」随之消失）。首期只剩「每日精力」一处（**我建议首期连精力也不做**：收藏靠看懂，不需要体力来限速）。
- 玩法收敛为**一个通用解释器**：照片 + 门道点坐标 + 知识卡 + 收藏条件。加一门爱好 = 加一份数据，完全符合数据驱动宣言。
- 知识卡由 LLM 批量起草 + 顾问审校，这条不变。

### 7.2 v2 让工程**变重**的部分：社交底座

**这是一个需要 owner 先想清楚的产品问题，不只是引擎缺口。** 实查结论：

- 引擎**没有任何后端**：`src/net` 只有联机对战用的 lockstep/state-sync（`mp-client.ts` 原文：「没有服务器」）；`PlatformPort` 的排行榜只能上传；玩家档案 `getPlayerProfile()` 是只读的本地资料，没有账号体系。
- 社交底座需要的**账号、信息流、关注、点赞评论、图片上传与存储、内容审核**，全部是服务端 + App 能力，**不属于游戏引擎这台确定性解释器**。

所以更准确地说：v2 更像一个**「带游戏化收藏的兴趣社区 App」**，而不是一个游戏。游戏引擎能覆盖的是其中的**细看 / 找点 / 收藏 / 学识**这一块（单机确定性部分），社区部分需要另一套技术栈。

**A / B 的白话说明与推荐见 `social.md` §7**：A = 游戏部分用我们的引擎，社交部分租用现成的云后端，中间做一个通用接口；B = 整个做成普通社区 App，不用我们的引擎。Lead 推荐 **A**。⏸ owner 2026-09-28 定社交往后放，此项**不再阻塞 v1**；v1 先做单机的收藏与游戏元素（`gameplay.md`），做社交时再判。

### 7.3 其余风险（沿用 v1 实查）

| 议题 | 实查结论 | 看法 |
|---|---|---|
| 双指缩放 | 有相机 zoom（`l5-camera`），**无捏合输入**（`input-capture` 只有单指针）、无瓦片金字塔 | 放大上限定为 6–8×，局部换高分辨率特写图；捏合输入是通用缺口，补在引擎层 |
| 门道点（热点） | `t2-clickable` 可用，多边形按包围盒命中 | 圆形热区足够，不补多边形拾取 |
| 真实照片版权 | 引擎可显示任意 JPEG/WebP | 博物馆 CC0 图可直接用；品牌酒标、表盘是商标，教育性展示问题不大，拿去做宣传图需法务确认；UGC 真藏需要审核 |
| 知识准确性 | —— | LLM 起草 + 领域顾问审校，数据里带 `reviewedBy`；真藏标「藏家自述」 |
| 敏感品类 | —— | 濒危材料不做；烟草、酒类在部分应用商店有年龄分级要求（首屏就是红酒、雪茄，**上架需按 17+/18+ 分级**） |

## 8. 明确不做（首期）

- 不为任何品类单独设计玩法。
- 不做养护、蜕变、实时计时（列为后续可选的通用「养」）。
- 不做交易、不做金币、不卖藏品。
- 不做 3D。
