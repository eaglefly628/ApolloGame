## 1. 一句话

> 在自己的私人书房里，用时间和耐心把一枚生核桃盘出包浆、把一只破建盏金缮复原。每一处放大的细节都有一段真知识。养成的藏品署上你的名字，拿去雅集展出、以物易物，换来圈内的声望。

## 2. 我对这个游戏的理解

### 2.1 它不是什么

- 不是网游式的「打怪升级」，没有战斗，数值也不是乐趣来源。
- 不是交易所游戏，没有全服金币，也不做 P2W。
- 不是 3D 游戏，画面是实拍级静态图，交互在图上发生。

### 2.2 玩家的一天（核心循环）

```
  精力(每日自然恢复)
        │ 消耗
        ▼
 ┌─ ① 把玩·启蒙 ──────────────┐   放大看细节 → 点热点 → 读知识卡 → 答题/辨伪
 │     涨「鉴赏力」「熟练度」   │
 └──────────┬────────────────┘
            ▼ 解锁/获得初级藏品（生核桃、散件表、残盏…）
 ┌─ ② 保养·沉淀 ──────────────┐   每天一次：控温湿度 / 盘玩 / 洗油 / 上漆…
 │     物品状态 生涩→进阶→极品  │   变化 = 高清图层透明度渐变（前后对比）
 └──────────┬────────────────┘
            ▼ 达到蜕变条件
 ┌─ ③ 蜕变·确权 ──────────────┐   盖印署名 → 写入传承日志 → 全服唯一
 └──────────┬────────────────┘
            ▼
 ┌─ ④ 社群·声望 ──────────────┐   雅集展出获赞 · 以物易物 · 悬赏代工/掌眼 · 答疑带徒
 │     声望 → 头衔 → 圈层地位   │
 └───────────────────────────┘
```

### 2.3 这个品类的真正卖点（设计要守住的三件事）

1. **「凑近看」本身就是奖励**：双指放大后发现开片、棕眼、游丝，这一刻要惊艳。所以图的质量是核心资产，UI 必须让位给图。
2. **时间是唯一的货币**：包浆不能用钱买快，只能按天养。这是「有尊严、去铜臭」的机制根基。所以加速类广告和 VIP 都**不能缩短蜕变本身**（见 §4 第 5 条）。
3. **署名的藏品是社交货币**：「这是我盘了 90 天的狮子头」。传承日志要像一份证书，值得截图分享。

### 2.4 目标人群决定的硬约束（中老年·手机）

这一条在美术风格之前，UI 需求单必须优先满足：

- 正文字号 ≥ 18pt，关键数字 ≥ 28pt；支持「大字模式」一键再放大 1.25×。
- 点击热区 ≥ 56pt；手势只用「单击 / 双指缩放 / 单指拖动」三种，不设长按、滑动删除这类隐藏手势。
- 高对比（正文对比度 ≥ 7:1），不靠颜色单独传递信息。
- 每屏只放一个主操作，文案用完整中文短句，少用图标谜语。
- 不做倒计时逼迫、红点轰炸或弹窗连环，节奏要慢。

## 3. 首个竖切范围（🟡 推荐）

原文首期列了 5 大类 11 个领域。按「标准化数据结构、可无限扩充」的原则，**竖切只做 2 个领域，把闭环跑通**，其余领域靠复制数据扩：

| 领域 | 选它的理由 |
|---|---|
| **文玩核桃包浆** | 「时间 → 包浆」最直观，保养动作简单（盘玩 / 刷 / 控湿），图层演变最有说服力 |
| **金缮修复（建盏）** | 另一种演变形态「残 → 修」，包含多步工序与等待（漆干），能验证数据结构的通用性 |

竖切内容：书房主页一屏 · 2 个领域各 3 件藏品 × 3 状态 · 热点知识卡约 30 张 · 每日保养 · 蜕变署名 · 传承日志 · 一个**单机模拟**的雅集与集市（NPC 藏家，见 §4 第 1 条）。

## 4. Lead 初步评判（待 S2 正式摆 A/B，此处先把风险摆出来）

> 已对 `src/assembly/capability-registry.ts` 全部能力及 `src/net`、`src/services` 做实查（2026-09-27）。结论：**单机核心大部分可以用现有能力组合出来；联网社交、真实时间、商业化三块引擎完全没有。**

| # | 议题 | 实查结论 | 初步看法 |
|---|---|---|---|
| 1 | **联网社交与经济**（易物、代工、全服点赞、唯一确权、邀请码） | 引擎无后端。`src/net` 只有 lockstep/state-sync（`mp-client.ts`:「没有服务器」）；`PlatformPort` 排行榜只能上传；无账号、无签名 | 这是本作最大的缺口，也是一个**产品级**决定，不只是引擎问题。🟡 推荐竖切先做**单机 + NPC 藏家社群**（集市和雅集由数据驱动的 NPC 发帖、点赞），验证核心循环好不好玩，再决定是否上服务端。UI 按联网形态设计，不受影响 |
| 2 | **真实时间**（每日精力恢复、按天包浆、漆干 N 小时） | sim 禁墙钟（`timeline.ts`「绝不走墙钟」）；只有 tick 计时（`e1-timer`/`t2-cooldown`/`t2-over-time`）；宿主可注入时间戳（存档 `savedAt` 先例），但**无「离线追帧 / 日历日」能力** | 真缺口，大概率要下沉一个通用能力（宿主把「过了几天」作为输入喂给 sim，确定性可重放）。放置类、养成类游戏都会用到，适合进引擎 |
| 3 | **深度缩放** | 有相机 zoom（`l5-camera`），但**无双指捏合输入**（input-capture 只有单指针）、**无瓦片金字塔**，「无限放大」对实拍大图做不到 | 「无限」要改成「放大到 4–8×，到微距层自动换一张特写图」。这样资产成本可控，体验也一样。捏合输入是通用缺口 |
| 4 | **图上热点** | `t2-clickable` 可用，但多边形按包围盒命中；UI 层没有图像热区控件 | 基本可组合（热点做成世界实体，跟随相机缩放）；形状不规则的热点改用圆形热区即可，不必补多边形拾取 |
| 5 | **商业化**（订阅、激励视频） | 引擎没有任何 IAP / 广告端口 | 平台接入问题，不急。**产品建议**：「缩短大漆晾干」这类广告直接破坏第 2.3 条的卖点，建议广告只用于「求助老专家」「多一次掌眼」这类**知识服务**，不能买时间 |
| 6 | **唯一藏品与传承日志** | `t2-inventory` 只有「种类+数量」，无单件元数据；`EventLog` 是旁路观测、不进 hash | 单件藏品需要「实例 + 元数据 + 历史」。可能用 prefab + state + 变量拼出来，S2 实查后再定是否算缺口 |
| 7 | **鉴赏力 / 熟练度等级** | 无 XP 能力；有 `f1-resource` + `f2-flag` + `t2-craft-recipe` | 按领域一条 resource，门槛解锁用 flag。大概率可重组，不立缺口 |
| 8 | **AI 量产知识库** | —— | 可行，但「鉴伪线索」答错会伤害这群用户的信任。🟡 要求**顾问审校**流程：LLM 出初稿，领域顾问签字后才入库；数据里带 `reviewedBy` 字段 |
| 9 | **实拍资产** | 引擎可显示任意 JPEG/WebP 精灵；无大图压缩或瓦片管线 | 最大的**生产**成本在拍摄，不在代码。每件藏品 × 每个状态 × 若干微距特写，都要实拍（或授权）。AI 生成的「实拍」图不能用于鉴伪教学 |
| 10 | **斗蟋蟀 / 活体** | —— | 活体繁育和对战是另一套系统（遗传、对战），首期不做。另外要注意斗虫题材在部分海外平台的审核口径 |

## 5. 明确不做（首期）

- 不做 3D、不做自由镜头。
- 不做全服金币交易所，也不出售「加速包浆」。
- 竖切不上真服务端；社交由 NPC 模拟（待 owner 判 §4 第 1 条）。
- 竖切不做活体领域（蟋蟀、锦鲤）。
