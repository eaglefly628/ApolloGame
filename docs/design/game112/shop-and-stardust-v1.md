# Game112 · 星砂铺与游戏内货币（2026-10-07）

## S1 · 范围

星砂铺仍是猫馆里的货架，不是外置应用商店。玩家先看商品，账页说明它会怎样改变与猫的互动，再确认交换。星砂只换玩具、猫用摆设和牌具外观；不卖好感、心光、回忆，不接真实货币支付、限时折扣或连续弹窗。

## S2 · 能力与数据

- 四件商品与价格只在 `games/game112/world-data.ts` 的 `SHOP_ITEMS` 定义。购买仍由 `CraftRecipe` 原子扣星砂、扣唯一库存并发物件；不足时世界不变。
- 一次性货币来源在同文件 `STARDUST_GRANTS` 白名单中定义。当前只有 `welcome: 20`，即掌柜见面星砂。`currency.grant.welcome` 通过 `KeyBinding → CraftRecipe` 消耗一格一次性库存、增加星砂、写已领 Flag；存档记录已领来源，旧档按未领处理。
- `STARDUST_MAX = 9999` 是余额上限。接近上限时 UI 显示实际可得额度，满额时提示稍后再领；资源能力会钳住余额。这个本地客户端存档不是防作弊账本，未来若要真实充值，必须另做服务器订单验证、幂等发放和退款规则，不能复用可由客户端触发的赠送信号作支付入口。

## S3–S6 · 画内流程

```text
进星砂铺 → 在四格货架点「看看详情」 → 账页读用途/摆放位置/价格
                                                  │
                    星砂不足且未领 → 领见面星砂 ────┤
                    星砂不足且已领 → 回主厅陪猫攒星砂 │
                    星砂足够       → 账页确认交换 ──┤
                    已拥有         → 放进馆里 / 回主厅一起用
```

商品选择是宿主的纯 UI 状态，不改 sim；确认交换、领星砂才向世界发具名动作。货架商品没有直接购买按钮，避免误触。余额、已领状态、已拥有与已摆放状态均来自世界投影；购买后账页原位变成布置入口。掌柜文案随余额与拥有状态变化，保持温和、无催促。

## 怎样再加一种星砂奖励

1. 在 `STARDUST_GRANTS` 加一条固定来源，如 `{ id: 'chapterGift', label: '章节纪念星砂', amount: 10 }`。蓝图会自动为它装配一次性库存、已领 Flag 与结算配方；`claimedGrants` 会随存档保存。
2. 在完成该章节的**受控游戏事件**中发 `grantKey('chapterGift')`，或在宿主会话调用 `session.claimStardustGrant('chapterGift')`。两者都只排队一个具名输入；金额不从按钮参数或任意字符串读取。同一来源重复发不会重复加钱。
3. 若要在 UI 里显示该奖励，再给相应画内入口加已领/可领投影。不要做一个玩家可反复点击的“加钱”按钮。若设计需要可重复每日奖励，必须先确定以何处可信日期、重置与存档冲突为准；本版不冒充已解决。

现有可重复来源仍是陪伴动作：轻声叫它 +1，陪它坐坐 +2。数值均是当前试玩平衡，可在 L0 表中调；没有“必须每日领取”的压力机制。

## S7–S8 · 验收与交付边界

单测覆盖一次性发放、重复与读档重放、余额上限、购买原子性、旧档默认值；真实宿主测试覆盖空档领星砂 → 交换纸袋 → 读档不可重领，以及既有物件摆放/互动闭环。LayoutNode 校验、双尺寸 Chrome UI 审计和真实画面预览用于查防重叠、对比与素材加载。全仓提交/上传须等工作区其他游戏的门禁也通过；不能为了本商店绕过红旗。
