## 0. 一句话与四个承诺（设计要服务的东西）

**在喵星的星尾会客厅遇见、收养并陪伴拥有往昔记忆的猫；也可以上传爱猫照片，让它成为能陪你打牌、玩耍、继续留下回忆的数字陪伴化身。**

设计每一屏时对照 GDD §2.2 四种安全感：**识别感**（一眼是我的猫）· **回应感**（它对我做的事有带性格的反应）· **连续感**（昨天的痕迹今天还在）· **保存感**（我讲的故事不会被改写）。

红线（GDD §2.3·ui-visual-handoff §10 文案表）：不用「复活」「灵魂」「它回来了」；不做断签/饥饿/欠账；删除确认不情绪勒索；不用付费或登录压迫。

## 2. 画布与响应式基线

- 桌面横屏 **1440 × 900** 为主稿；最小 **1024 × 640** 须可用。
- 游戏场景保持 16:9 安全区；菜单可占左右抽屉或底部托盘。
- 大字号与 200% 缩放下主要操作仍可完成。
- **壳层保留区**：右上角有启动器的 ⚙ 菜单（工程实测会吃掉那一角的点击）。**任何屏的右上角 ≈ 120×56 px 不放本游戏的按钮**；本游戏的「设置」入口放底部导航或左上。
- 移动端第一轮只画：上传（S33/S36）、通知托盘（S13）、相册（S65）三屏的关键态。

## 3. 引擎硬约束（画在这个词汇表里，稿子才能 1:1 复刻）

### 3.1 控件闭集（41 个·只能用这些搭）

| 类 | 控件（引擎名） | 设计时怎么用 |
|---|---|---|
| 布局与展示 | Screen 全屏根 · Panel 容器/分组（可 bare 无框 · glass 磨砂 · skin 贴图皮 · shape 8 种异形 · action 整块可点）· Label 文本 · Image · Divider · Avatar 头像（可带进度环）· **Video** 视频 | 猫的画面 = 一块 Image/Video 区域（见 §3.4） |
| 华丽与定位 | Particles 粒子 · LevelPath 蛇形路径 · Float 锚定浮层 · Connector 连线 | 相认/章节完成的克制星光；回忆廊的「不规则光带」可用 LevelPath 变体表达 |
| 交互 | Button（primary/ghost/quiet/**hero** 金 CTA · 可异形 · 可贴图皮 · 可副标 sub）· Input（text/number）· Dropdown · Combobox · Checkbox · Toggle · RadioGroup · Segmented · Slider · Stepper · Rating | **每个按钮标注 action 名**（§5 词表）|
| 标记与数据 | Badge · Tag（可作货币药丸 size lg）· ProgressBar（bar / **ring** 环 / liquid 液面）· Table · VirtualList · Card · **PlayingCard**（faceArt 整面插画·翻面） | 心光/亲近只在详情页用柔和 ring；主厅不放数值仪表 |
| 浮层与结构 | Modal · Drawer（左/右/底）· Tooltip · ContextMenu · Toast · Accordion · Tabs | 分级删除确认 = Modal；一级页面 = 场景可见 + 一侧 Drawer |
| 演出与叙事 | CoinFlip · Versus · **dialog** 台词框 · **choiceList** 选项列 · **portrait** 立绘槽 | 回忆章节 = dialog + choiceList；猫立绘可占 portrait |

**没有的东西**（画了也复刻不了，须标「缺口」）：文件/相机上传控件（已立单 REQ-112-UI-07，可先画占位并注明）；视频「播完发信号 / 按状态换片不黑帧」（已立单 REQ-112-ENG-11）；自由 SVG 动画、任意 CSS 动效、拖拽轨迹跟手（逗猫拖羽毛棒已撤）。

### 3.2 布局约束闭集（Panel/子项能用的排布参数）

`direction: row|column|grid` · `gap` · `padding` · `margin` · `align: start|center|end|stretch` · `justify: start|center|end|between|around|evenly` · `width/height/maxWidth/flex` · grid 用 `minCol`（自适应换行）或 `cols` · `x/y` 绝对定位 · 3D 感 `rotateX/rotateY/perspective/tilt3d/press3d` · 特效 `fx`（如悬停流光 `sheen-hover`）。**没有 flex-wrap**——自适应网格一律 grid+minCol。**Screen 本身不接排布参数**，页面内容放在内层 Panel 上。

### 3.3 主题令牌（house 主题 `apolloBrocade`「锦霞」起手·S5 再精修）

| 令牌 | 值 | 用途 |
|---|---|---|
| bg0 / bg1 / bg2 / bg3 | #ecd6cf / #f3e2dc / #fffaf3 / #ffffff | 页底 → 面板 → 抬升面 → 最亮 |
| text / sub / dim | #5a3f44 / #a98b8f / #bfa0a4 | 正文 / 次文 / 弱文（dim 在浅面上对比不足，少用） |
| jade（主色）/ gold | #d8607b 胭脂玫瑰 / #cf9a3f 金 | 强调 / 心光·星砂 |
| ok / warn / danger | #54ad8e / #e0a94e / #d65668 | 只做语义，不做装饰 |
| 字体槽 | 正文 Noto Serif SC；标题可用 `cnround`（中文卡通粗圆）或 `serif`；数字 `mono` | 敏感说明不用小浅灰字 |

设计稿**只用上述令牌与语义色**（面填充：panel/raised/sunken/jade/gold/ok/warn/danger/ink/transparent），不自由取色。GDD 的「燕麦旧木暖光 × 灰蓝雾青喵星冷光」在 S5 精修阶段以主题纹理（磨砂晶片 / 旧纸卡 `texture/panelTexture` + `Panel.glass`）实现，**本轮稿子标出「哪块是暖光面、哪块是冷光面」即可**。

### 3.4 猫的画面层与 UI 的分离（必须画清）

```
前景遮挡：桌沿 / 椅脚 / 纸袋 / 窗帘          ← 高层 Image（可挡住猫）
实时交互：卡牌 / 点击反馈 / 字幕 / 菜单        ← UI 控件（独立安全区）
猫画面层：一块矩形区域（Image 占位 → 将来 Video 按状态换片）
空间轻动态：灯光 / 尘埃 / 晶球微光            ← Particles(sparkle) 克制
静态背景：可布置的星尾馆                       ← Screen 背景图
```

- 猫画面是**一块矩形区域**，标注它在每个镜头里的位置/尺寸/锚点；**按钮不插进猫的像素里**。
- 猫身上的「触摸分区」（头/脸颊/下巴/背/前爪）画成猫区域内的**矩形热区**（引擎命中只有 AABB），首版只按区判，不按方向/速度。
- 猫画面的四档回退必须各有一张稿态：个性片 → 通用片 → 基础活照片 → **静态锚图 + 轻微光效**（断网态）。

### 3.5 交互铁律

- 每个可点元素**标注 action 名**（§5 词表）；没有 action 的装饰不做成按钮形。
- 一次只做一件事：牌局/逗猫/回忆/布置各自独立固定镜头，不在一屏堆面板。
- UI 默认低透明小面积，几秒无操作淡出；「隐藏 UI」后边缘轻触可恢复。
- 无红点绑架、无倒计时、无稀缺额度。

## 6. 每屏交稿必附（工程侧据此复刻与复查）

1. **组件映射表**：屏上每个元素 → §3.1 的控件名（如「星砂药丸 → Tag(size lg)」「心光环 → ProgressBar(ring)」「章节 → dialog + choiceList」）。
2. **动作标注**：每个可点元素的 action 名（§5）。
3. **状态矩阵**：默认 / 聚焦 / 禁用 / 加载 / 离线 / 错误回退 / 大字号 / 减少动态。
4. **安全区图**：猫画面矩形、前景遮挡层、UI 安全区、右上角壳层保留区。
5. **令牌标注**：用的是哪个语义色 / 面填充 / 字体槽；标出暖光面与冷光面。
6. **缺口清单**：用现有控件表达不了的点，逐条列（不要自造控件）。

命名：`cloud-design/S10-hall.dc.html`、`S20-orbs.dc.html`、… 一屏一文件；多状态可在同一文件内切换。

## 7. 审稿问题（交稿前自问·`ui-visual-handoff` §12）

1. 关闭所有 UI 后，玩家是否仍愿意看着猫待一会儿？
2. 主厅像共同生活空间，还是功能入口大厅？
3. 第一次上传照片的人清楚素材用途和删除权吗？
4. 「这不像它」够容易点吗？
5. 生成失败后仍能陪伴与打牌吗？
6. 牌局中猫的脸和爪始终可见吗？
7. 回忆页允许今天不面对悲伤内容吗？
8. 商店把奖励送回共同空间了吗？
9. 有没有利用失去猫的情绪促付费或促登录？
10. 是否避免了「过度完美、完全对称、统一软装」的 AI 感？
11. **每一屏能否只用 §3.1 的 41 个控件 + §3.2 的排布参数表达？表达不了的点列缺口了吗？**
