# Game112 · 2D 猫角色生产方案

日期：2026-09-30  
状态：方向确定，等待首个分层绑定样片

## 结论

Game112 的常驻猫不采用“图片模型直接生成序列帧”，也不要求玩家运行高成本写实 3D。正式路线是：

> 同一张身份母图 → 分层角色件 → 2D 骨骼/网格绑定 → 确定性循环；爱诗视频负责高保真近景互动。

3D 仍可作为幕后制作工具或动作参考，但不是必须随游戏发布的运行时资产。

## 为什么这一版能闭环

- 外观来自一套母图，毛色、脸和体型不会逐帧漂移。
- 运动来自骨骼曲线，循环首尾使用同一组参数，天然无跳帧。
- 头、耳、眼、尾巴和四肢分别受控，可以按情绪组合，而不是为每种情绪重新生成整只猫。
- 每个房间只保存猫位、缩放、方向和可用动作 key；sim 不保存像素或云端生成状态。

## 第一只猫的分层

雪团至少拆成：

1. 远侧后腿；
2. 远侧前腿；
3. 尾巴；
4. 躯干与长毛遮罩；
5. 近侧后腿；
6. 近侧前腿；
7. 颈毛遮罩；
8. 头；
9. 左耳、右耳；
10. 左眼、右眼与眼睑；
11. 鼻口微表情层。

腿根、颈部和尾根必须藏在长毛遮罩下，避免纸偶关节。所有层使用同一画布、同一原点和同一色彩空间导出。

## 动作范围

首个可交付样片只做三段：

- `idle`：呼吸、眨眼、耳朵转动、尾尖小摆；3–5 秒无缝循环。
- `notice`：从中性姿势抬头看玩家，再回到中性姿势。
- `step-and-settle`：向一个方向走两至三步后坐下，不做无限往返。

完整 180° 转身不使用单张侧面图强行变形。需要换方向时只允许三种方式：

1. 在桌腿、门洞、纸箱或前景遮挡后切换左右方向稿；
2. 播放经过审核的专用转身片段；
3. 猫走出镜头后，从另一侧方向稿重新进入。

## AI 的职责边界

GPT 图像能力用于：身份母图、左右方向稿、缺失毛发补全、遮罩层与纹理修复、分层后统一画风。

GPT 图像能力不用于：逐帧猜步态、自动拼序列条、凭四张独立图片伪造转身。

爱诗视频用于：撸猫、扑玩具、压牌、回忆等近景表演。片段带身份参考、首尾帧和角色 id；只在中性姿势或遮挡点切入。

## 验收门槛

- 透明背景没有整幅半透明残留、矩形边或杂点。
- 每个关节在最大运动角度下不露缝、不拉断毛发。
- `idle` 连续播放五分钟，首尾无可见跳动。
- 猫脸、眼睛、面罩与鞍状花纹不随动作变化。
- 任何方向切换都不能在无遮挡状态下镜像整只猫。
- 通过 1×、0.75×、0.5× 三档房间缩放实测。
