# Game112 · 高保真二维动态猫样机

日期：2026-09-30
状态：第二版方向动画已撤下；单图局部网格待机样片已进入运行时

## 当前结论

直接生成的四帧行走与转身无法稳定保持骨架、重心、轮廓、落脚点和严格分格，因此运行时已撤下这套巡游。现以同一张 `rest` / `notice` 透明锚图做局部网格变形：胸口呼吸、耳朵微动、尾尖摆动；脚掌固定，4.3–4.6 秒数学闭环。引擎 `Image.meshMotion` 负责绘制，WebGL 或图片失败时保留原图。

## 失败样本（已禁用）

- 三条四帧素材仍留在仓库供复盘：右行、左行和转身。
- 问题不在播放顺序：生成图中的猫越过固定帧格，播放时被窗口裁切或串入相邻帧；独立姿态的身体比例与脚掌锚点也不连续，第四帧无法真实接回第一帧。
- `Image.sprite.directedPatrol` 通用能力保留，但 Game112 不再消费这些失败素材。
- 玩家呼唤猫时，身份锚从 `rest` 切换到 `notice`；两个姿态分别有局部网格标定。sim 仍只负责姿态状态，像素始终只在投影层。

## 视觉回退

当前链路为 `notice/rest` 锚图 + 可选网格待机 → 原图静态海报 → 程序化 SVG。网格配置只绑定雪团两张准确的图，换图或换猫不会沿用旧标定。

## 与真正 Live2D 的差别

当前网格样片只能在同一张画的轮廓内做柔性微动。真正 Cubism 方案还需要分层源文件与绑定数据：头、耳、眼睑、瞳孔、嘴、躯干、前后腿、尾巴、毛发遮罩。眨眼、抬爪、走路和跨视角转身仍需新增画稿和绑定，不能由一张扁平 PNG 无损推得。

后续路线是：单张母图 → 人工/半自动分层 → 2D 骨骼与网格绑定 → 更多动作。大幅转身通过专门方向稿、家具遮挡或动作片段切换完成；高保真撸猫与回忆仍交给爱诗视频。详见 `2d-cat-production-pipeline.md`。
