# Game112 · 高保真二维动态猫样机

日期：2026-09-30
状态：第二版方向动画已撤下；仅保留为失败样本

## 当前结论

本试验验证了一个明确的反结论：**不能让图片生成模型直接承担连续角色动画**。它可以画出单张高质量猫图，但四帧行走与转身无法稳定保持骨架、重心、轮廓、落脚点和严格分格。运行时已撤下这套巡游，恢复为 `rest / notice` 两张静态身份锚图，避免继续向玩家展示残影、裁切和断裂循环。

## 失败样本（已禁用）

- 三条四帧素材仍留在仓库供复盘：右行、左行和转身。
- 问题不在播放顺序：生成图中的猫越过固定帧格，播放时被窗口裁切或串入相邻帧；独立姿态的身体比例与脚掌锚点也不连续，第四帧无法真实接回第一帧。
- `Image.sprite.directedPatrol` 通用能力保留，但 Game112 不再消费这些失败素材。
- 玩家呼唤猫时，静态身份锚从 `rest` 切换到 `notice`；sim 仍只负责姿态状态，像素始终只在投影层。

## 视觉回退

当前链路为 `notice/rest` 静态身份锚图 → 程序化 SVG。任何动态方案未通过逐帧审核前，都不得自动顶替静态锚图。

## 与真正 Live2D 的差别

真正 Cubism 方案还需要一套分层源文件与绑定数据：头、耳、眼睑、瞳孔、嘴、躯干、前后腿、尾巴、毛发遮罩，以及呼吸/眨眼/耳动/尾摆参数。当前 AI 生成的扁平 PNG 不能无损地自动变成可信的骨骼模型。

下一阶段不再增加 AI 序列帧数量。路线改为：单张母图 → 人工/半自动分层 → 2D 骨骼或网格绑定 → 数学闭环动画。大幅转身通过专门方向稿、家具遮挡或动作片段切换完成；高保真撸猫与回忆仍交给爱诗视频。详见 `2d-cat-production-pipeline.md`。
