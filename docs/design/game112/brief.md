# Game 112《星尾会客厅》·立项卡

> 状态：S1 策划整理中，尚未进入 capability plan 与实现阶段。
> 工作名：《星尾会客厅》；最终名称待 owner 确认。
> 详细策划见 [`gdd.md`](./gdd.md)，页面与菜单流程见 [`menu-flow.md`](./menu-flow.md)。

## 一句话

> 在喵星的星尾会客厅里，遇见、收养并陪伴拥有往昔记忆的猫；也可以上传自己爱猫的照片，让它成为能够陪你打牌、玩耍和继续留下新回忆的数字陪伴化身。

## 玩家承诺

- **它仍然是它**：保留真实猫的毛色、花纹、眼睛与独特小特征，而不是生成一只相似的通用猫。
- **它有自己的生活**：玩家离开后，猫会睡觉、玩耍、整理或弄乱东西，并留下可以回看的生活片段。
- **关系不是数值皮肤**：陪伴会改变猫对玩家的信任、动作、牌桌习惯和愿意分享的回忆。
- **这里不制造第二次失去**：不设死亡、饥饿惩罚、断签退化或限时告别。

## 核心体验

1. **相遇与相认**：遇见官方喵星猫，或上传爱猫照片建立专属数字化身。
2. **日常陪伴**：在固定镜头的会客空间中问候、安静相处、逗猫与使用玩具。
3. **猫猫牌**：和猫进行轻量但可长期扩展的卡牌游戏，从牌桌行为认识它的性格。
4. **回忆探索**：修复猫的回忆片段，了解它与从前主人的故事；上传猫的回忆只由主人提供并确认。
5. **布置共同空间**：通过无压力经济循环获得玩具、牌面、家具和喵星装饰。
6. **照片变活**：以稳定身份锚为基础，用爱诗视频生成陪伴、玩耍和回忆演出。

## 产品形态

| 项目 | 定义 |
|---|---|
| 类型 | 数字宠物陪伴 × 轻卡牌 × 回忆叙事 × 收藏布置 |
| 核心场所 | 喵星上的“星尾会客厅”，兼具会客、娱乐、休息和记忆展陈功能，不是经营咖啡馆 |
| 活跃猫 | 一个场景通常只有一只当前陪伴猫；猫咪名册可持续扩充 |
| 镜头 | 各活动使用固定镜头：牌桌、逗猫角、回忆观影等 |
| 视觉 | 高保真照片转活视频为主，2D UI 与实时交互层叠加；不以自由视角 3D 为目标 |
| 平台方向 | 首先按桌面/网页横屏设计；桌面悬浮猫作为后续独立形态 |

## 首个竖切范围

- 星尾会客厅主场景一间。
- 一只官方布偶猫与一个用户上传猫槽位。
- 上传、生成、身份确认、失败回退与删除流程。
- 问候、安静陪伴、逗猫棒互动。
- 一套最小猫猫牌闭环。
- 一条三段式官方猫回忆故事。
- 星砂、心光两条经济/关系进度。
- 爱诗生成视频的缓存播放与基础素材回退。

## 明确不做

- 不做餐厅流水线经营、员工排班或顾客翻台。
- 不宣称复活、复原意识或替代现实中的猫。
- 不让 AI 擅自编造上传猫的死亡原因、经历或主人关系。
- 不以抽卡出售上传猫、回忆章节或关系等级。
- 不让网络生成等待阻塞基础陪伴与牌局。
- 首版不做自由镜头、开放世界和实时多人。

## 视觉方向

- 喵星装饰：星轨、月相、猫爪星座、旧木材、磨砂晶体与被猫使用过的生活痕迹。
- 避免过度完美的“AI 豪华咖啡厅”：允许不成套杯子、磨损、歪斜、遮挡和猫的微妙怪表情。
- 猫必须高保真且身份稳定；空间可以带绘本式轻度风格化。
- 所有菜单/HUD 最终仍走 LayoutNode 数据闭集；猫与视频属于 play-field/媒体表现层。
