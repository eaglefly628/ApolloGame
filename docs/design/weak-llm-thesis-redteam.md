# 「数据驱动 + 弱 LLM 落地」可行性红队自审

> 2026-06-10 · Lead 专家评审 · 性质：**融资叙事的反方压力测试**（与 `engine-assessment-and-roadmap.md` 配对阅读：那篇是正方陈述，本篇是红队推演 + 命题修正 + 可证伪化）。
> 结论先行：**故事可行。但有一个命题必须改写、三场战役必须打赢。** 死法不在技术，在自我失误。

---

## 0. 被审的命题

> 整个游戏是数据；引擎是固定确定性解释器 + 能力词汇表；创作 = 按 schema 填空 + 从目录组合；
> 因此最弱 LLM 与最强 LLM 产出一致；因此成本降 1–2 个数量级、可审计、可回滚、lockstep 免费。

---

## 1. 底层逻辑为什么成立（四个支柱）

### 1.1 历史先例：用"约束"换"大众创作"是被反复验证的范式
RPG Maker 四十年长青、Mario Maker 上亿张关卡、PuzzleScript 用极小 DSL 表达了惊人多的解谜游戏。共同证明：**把创作空间约束成"填模板 + 拼积木"，非专业者就能产出可玩内容，且表达力天花板远比直觉高**。ZeroCraft 只是把"填模板的人"换成 LLM——约束没变，填空者的成本变了。

### 1.2 技术潮流恰好压在论点这边
Constrained decoding / JSON schema 强制输出已从论文变成推理基础设施。"按 schema 填空"对弱模型是**语法 100% 合法保底、只剩语义选择**的任务形态——分类/抽取/结构化填空正是弱模型能力曲线的甜点，长程序合成才是死穴。**这是顺着模型能力分布做产品，不是逆着做。**

### 1.3 校验-修复闭环把质量从"模型性质"变成"系统性质"
仓库已有完整链：schema 校验（R12）→ 资产硬校验（assetKey）→ 引用链接器（validate-references）→ ZeroCraftBench 五轴跑分。关键洞察：**封闭 DSL 的错误空间是有限可枚举的**——每个错误都能给出机读、可定位的修复指引，喂回模型重试。"弱模型 + 精准报错 + 两轮重试"逼近"强模型一次过"；这在自由代码上收敛极慢（错误空间无限），在封闭 schema 上收敛极快。**这是与"让 AI 写代码"路线在数学结构上的差别，不只是工程品味的差别。**

### 1.4 游戏领域可枚举，且我们自己的数据已显示收敛
通用低代码平台的死法是"业务逻辑无限发散 → 逃生舱泛滥 → 变成更烂的编程环境"。游戏不同：品类机制高度聚类（周期表即此洞察的产物）。看自家边际能力曲线：

| 新品类 | 拉动的新 capability | 趋势 |
|---|---|---|
| Game D（暗黑 ARPG） | ≈12（hitbox/over-time/mortal/steering/keybind/tilemap/anim-state/facing/aggro/caster/prefab/launch/stats） | — |
| Game E（卡牌 rogue） | ≈6（poker-hand/card-scoring/card-pile/card-play/flow + 若干既有能力扩展） | ↓ 一半 |
| Game F（自走棋） | **2**（self-rule/group-count；第 3 条 group-effect 被重组裁掉） | ↓ 再砍 |

**每个新品类的边际引擎需求在递减**——词汇表会封顶的早期实证，不是 PPT 推演。此曲线可直接从 git 历史绘出，是融资 deck 最便宜也最硬的图之一。

## 2. 必须改写的一个命题（故事的命门）

> ❌ 危险讲法："弱模型能做出**好玩**的游戏。"——不可证，也守不住。

schema + 校验器保证的是**合法性**（必然能跑、不坏、确定性），不保证**好玩**（数值曲线、关卡张力、机制新意）。游戏设计的难点恰在语义层，弱模型在创意语义上就是弱——它会产出合法但平庸的数据。拿"每个产出都好玩"当验收标准，故事必破。

> ✅ 正确命题：**引擎承担质量下限，模型只做语义填空；"最弱模型"是一致性的最严苛测试仪，不是创意来源。**

- 对标质量分布是 RPG Maker / Mario Maker 式的：**海量合格 + 长尾精品**。精品来自人 + 模板生态 + 强模型；弱模型保证"人人到合格线"。
- 这个改写让论点**对模型进步免疫**：模型越强，同一套 schema 产出越好，引擎全接得住。
- 顺带回应"窗口论"（模型变强变便宜后优势是否消失）：**即使 frontier 能力免费，自由代码的方差与不可维护性也不消失**——强模型两次生成也不一致，产出的代码 diff 不可读、改一处要重 roll 全盘。我们卖的从来不是"省模型钱"（那是副产品 + 证明手段），是 **AI 产物第一次变得可控、可改、可协作、可累积**。

## 3. 三场必须打赢的战役（真实风险所在）

### 战役 1 · 词汇表规模化 vs 弱模型选择力
能力目录 70 → 200 时，"选哪个能力"的方差会回来——选择空间膨胀恰好杀死核心命题。
**对策**（升格为主线）：结构化意图层 + **能力目录检索**（按意图召回相关子集喂模型，不再全目录灌 prompt）。
**量化哨兵**：能力数 × 各档模型选对率曲线；弱模型一掉线，就是检索/分层该上的信号。

### 战役 2 · 表现层的剩余 30%
玩家感知的"好"一半在 UI/动效/打击感，这块仍是手写 React。@ui/vn 已证明正确路径：**UI 不是无限自由的，是"品类演出模板 + 主题数据"**。
**诚实承认其商业含义**：每个新品类需工程师先铺模板（人力先行）→ 正确产品形态是 **N 个品类深耕**，不是"任意游戏一句话"。Deck 里这样讲反而更可信。

### 战役 3 · 质量语义层的生态化（终局护城河）
"合格线"由引擎保证之后，"精品"从哪来？**模板/预设/remix 生态 + 数据飞轮**：
- 每个生成的 manifest、每次人工修改的 diff、每局跑分与留存，都是**干净的结构化训练数据**——自由代码路线永远攒不出这种数据；
- 终局形态：**一个专调"意图→manifest"的小模型（7B 级）在封闭 schema 上胜过通用大模型**（封闭词汇表 + 海量同构样本 = 小模型微调的理想靶面）；
- 届时"弱模型可用"从营销命题变成自家成本结构：推理自托管、单位经济学碾压调用 frontier API 的对手。

## 4. 可证伪化：三个可测假设 + 降级安全网

| 假设 | 内容 | 怎么测 | 状态 |
|---|---|---|---|
| **H1 合法性** | 弱模型产 manifest 加载通过率 ≥95%（带链接器修复循环） | zerocraft.py 批跑 × parseManifest 通过率 | 积木全齐，随时可测 |
| **H2 一致性** | 同意图 × {DeepSeek,Qwen,GPT,Claude} 的 ZeroCraftBench 方差比"自由代码对照组"小一个数量级 | 模型方差矩阵 harness（路线 P2） | harness 待建，一周内可出基线 |
| **H3 可玩性** | 人类盲评「弱模型+ZeroCraft」vs「强模型+自由代码」可玩分 | 盲评协议（后置） | 现在设计、后置执行 |

**降级安全网**：即使 H3 不及预期，H1+H2 成立即支撑"模板 remix + 人在环"产品形态——RPG Maker 验证过的成立生意。**这个故事不是 binary bet，是带安全垫的非对称下注。**

---

## 5. 结论与行动含义

**可行。** 四个支柱（约束换创作 / 顺应模型能力分布 / 闭环工程 / 领域可枚举 + 收敛实证）都站得住，且证据在仓库里而非 PPT 里。真正的死法是三种自我失误：

1. 把弱模型当**创意来源**来承诺（→ 用 §2 的命题改写防住）；
2. 词汇表失控膨胀（→ 战役 1 的检索 + 哨兵防住）；
3. 品类铺太宽、表现层模板跟不上（→ 战役 2 的"N 品类深耕"形态防住）。

**给融资叙事的两张最硬图**：① 多模型方差收敛图（H2）；② 品类边际能力递减曲线（D≈12 → E≈6 → F=2，git 历史今天就能画）。

> 复诵（与宪法对仗）：**引擎负责"不坏"，生态负责"好玩"，模型只负责"翻译"。** 弱模型跑得通，是因为我们从没让它做难的事。
