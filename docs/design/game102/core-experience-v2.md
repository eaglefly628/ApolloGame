> **重大校正**：v1（gdd/prototype 里的「单条左右传送带·左端单发射位·打任意同色」）**是简化错的**。真机是**环形轨道 + 多炮绕行 + 过位侧向开火**。本文件为准，PE 据此重做核心；gdd 对应段同步改。

## 1. 真机核心机制（照三图）

1. **环形轨道（Track·轨道）= 单一 360° 闭环传送带**（owner 2026-07-24 强调）：**一条连续的、环绕整幅像素画一周**的跑道（圆角矩形闭环·箭头同向流转·三图皆有）。
   **不是左右直线传送带、也不是四条分开的边带——是一条闭合环带**。**色炮上带后沿环带绕整整一圈跑**（一圈=经过上/右/下/左四条边），**每经过一条边就对该边外沿的同色像素过位剥离**；跑满一圈回到入口（未打完可继续下一圈或回收，按数值定）。
2. **色炮（打蛋器）= 颜色 + 弹药数**（图上 21/18/40/50…=弹药）。绕行时**当它经过某条边、该边外沿露出它同色的像素 → 它向内侧射击、剥掉那些像素**（ref-01 黄炮"21"在右边喷黄格、紫炮"18"喷紫格）。
3. **剥离周边（perimeter→inward）**：炮只能打**它当前经过那条边的、外沿暴露的同色像素**——从外向里一层层啃（不是"全场任意同色秒清"）。
4. **多炮同时绕行 + 时间差（核心乐趣）**：轨道上**同时跑很多炮**（ref-02 右边 0/16/30/33 四炮排队绕），每炮有自己的位置/节奏/弹药。**管理这群炮的时机 = 爽感与技巧天花板**。
5. **选错 = 空转一圈（关键风险）**：若部署的炮，其同色像素不在它将经过的边（或已被啃光）→ **它绕一整圈什么也没打下来**（owner 原话）。→ **部署时机 + 颜色选择 = 核心决策**。
6. **待命槽 ×5**（三图轨道下方一排 5 槽）：待部署的炮。
7. **部署池（下方大网格）**：一堆待用色炮（色+弹药）——含：
   - **🔒 锁定炮（解锁·ref-03 黄锁炮）**：锁着·需解锁才能用（进度/钥匙）。
   - **盲盒炮（owner「盲盒」·ref-02 黑炮群）**：颜色/内容待揭（黑=未知或特殊·部署才知）。*（黑是否=背景色炮 待与实机再核）*
8. **画内特殊件**：🔑钥匙 / 🔒锁块 嵌在像素画里（ref-03 仙人掌两侧）——目标/解锁元素。
9. **关卡分段 `x/5`**（三图左下 3/5·2/5·5/5）：每关 5 段推进。
10. 顶部：设置 / LEVEL N / 金币。

## 1.5 我们的差异化：3D 旋转核心（owner 2026-07-24 · **不完全复刻**）

- 原作中央 = **静止 2D 像素图**。**我们改成：中央 = 3D 像素结构（每像素 = 3D 方块 / voxel），核心方块在那里持续旋转**——立体、会转，作本作**签名视觉差异化**。
- 与 360° 环轨天然契合：环轨绕着这个**旋转的 3D 核心**跑，炮从环上过位剥离它外沿的方块；剥掉的方块走 `fx-3d-debris.md` 真物理碎片落平台。→ **强化选 B「全 3D 盒庭」**（核心/环轨/炮/碎片同一 3D 空间）。
- **⚠ 必须拍板的架构决策（owner/Lead）——旋转是「装饰」还是「玩法」？**
  | | 方案 | 含义 | 代价 |
  |---|---|---|---|
  | **A** | **装饰旋转（render-only）** | sim 仍把核心当**固定网格**判定消除；3D 旋转纯视觉（`Anim3D spin` / `Pivot3D`）。炮打固定格，转只为好看。 | 省·安全·**不碰 determinism**（旋转 render-only·3d.md 铁律）|
  | **B** | **玩法旋转（sim 确定性）** | 旋转角进 **sim（确定性）**，**转动改变「哪些面/边的方块暴露给环轨哪条边」**——须**掐准某色转到你炮将经过的边时**再部署（环轨时机 × 旋转时机 **双层博弈**）。 | 差异化最强·但旋转状态须进 sim（非纯 render·须确定性方案·Lead 裁）|
  > **GD 倾向**：先 **A** 出 MVP（视觉差异化即得·零回放风险），**B** 作进阶（若做，Lead 裁「sim 持旋转角·确定性」）。owner 定。

## 2. ⚠ 与当前 build 的 DELTA（PE 必看·要改的地方）

| 维度 | 当前 build（v1·错） | 真机 v2（要做） |
|---|---|---|
| 轨道 | 单条左→右直线传送带 | **环形轨道绕画四边** |
| 发射 | 队首到左端「发射位」打**任意**同色 | **绕行中·打当前所经边的·外沿暴露同色**（位置/侧向相关） |
| 炮数 | 队列排队·单发射位 | **多炮同时绕圈跑·各自时间差** |
| 失败感 | — | **选错色/时机→空转一圈啥也没打**（核心风险乐趣） |
| 部署池 | 补给区 4 色按钮 | **大网格池 + 🔒解锁 + 盲盒** |
| 分段 | 无 | **每关 x/5 段** |
| **中央核心** | 静止 2D 像素格 | **3D 像素方块结构·持续旋转**（差异化·见 §1.5·旋转装饰 vs 玩法待 owner 裁）|

> 结论：**核心循环要重做**——从「线性队列 + 单发射」改为「**环形轨道 + 多炮绕行 + 过位侧向剥离 + 部署时机博弈**」。已通过的验收剧本 01/02/05（消色/入槽/判负的**结果层**）语义大体仍成立（同色消除、弹尽入槽、判负），但**触发方式**（绕行过位而非到达单点）要改；剧本待随新机制更新。

## 2.1 运动 + 平台/弹库 细化（owner 口述 2026-07-25·三图 IMG_6061/6063/6064·PE 记录·**待 GD 并入 gdd + 出验收剧本**）

> owner 连续口述细化「最基本的运动」与平台/弹库规则。以下为 PE 逐条记录，数值/边界待 GD 校准、Lead 裁能力路线。

### A. 运动模型（**最基本·先做好**）
1. **出发点 = 弹簧（左侧·约 7 点·轨道与平台衔接口）**——所有炮从弹簧上轨（IMG_6064 左边弹簧圈）。
2. 沿**带箭头的宽轨道**跑**恰好一圈**（start→end 固定路径）——**不是每次飞向目标**，而是每次都 start→end 绕一整圈。
3. 绕行中对**当前所经边外沿暴露的同色**过位剥离（外→内·外层消失后内层才暴露·见 §D 主玩法）。
4. **一圈跑完（回到 end≈弹簧/平台区）的两种去向**：
   - **还有子弹 → 落回 5 个待命平台之一**（IMG_6064 平台上那门 yellow「10」即返回态）。
   - **子弹中途打光 → 中途消失（放消失特效）·不回平台**。
5. **可同时 N 门炮在轨**（各自时间差绕圈）；每门炮面上画**动态剩余子弹数**。

### B. 平台 / 弹库（池）+ **失败条件**（owner 2026-07-25 定清·前「待裁」张力已解=下述 B 方案）
6. **待命平台 ×5 = 存放「绕完一圈仍剩子弹」的返回炮**（IMG_6064 平台上 yellow「10」即返回态）。**平台数（5）也 = 同时最多在轨炮数**。
7. 部署来源：待命平台上的炮 **或** 下方弹库（池）的炮。
8. **队列前推（补位）**：选中待命平台上一门 → 排在其**后面的依次往前推进一格**；选中弹库中一门 → 其正下方的**上浮一格补位**（平台与弹库都是「取走→后补上顶」的队列）。
9. **⭐ 失败条件（游戏规则·owner 定）**：5 个平台**全满**、你又**不把它们重新派出去**，此时**新派出的炮绕完一圈返回、却没有空平台承载它 → 判负（lose）**。→ 平台占用是**必须主动管理的输局风险**（这就是难点，非 bug）。
   - 推论：炮要么**把子弹在轨上打光→中途消失**（不占平台·§A.4），要么**带弹返回占一格平台**（占用风险）。**把平台上的返回炮再派出去打光**是解占用的唯一手段。

### D. 主玩法目标 + **⭐ 核心经济（owner 强调「希望你理解」）**
10. **选对颜色先清外圈**；外层格消失后内层才暴露 → 再清内层（**层层向内啃**·IMG_6064 外圈绿/紫、内层黄）。选错色 = 空转一圈、**满弹返回**（不误伤别色·不减弹）。
11. **⭐ 弹药守恒（核心逻辑）**：**全部炮的 ammo 之和 == 像素画全部体素格数**（出的子弹总数 == 要消的格子总数·**精确相等·零冗余**）。⇒ 必须**合理选出场顺序 + 颜色 + 时机**，让每一发都打在暴露的同色格上（不空过、不带弹堵平台），才能把全盘清完且不因平台占满判负。**这是本作的谜题内核**（确定性资源调度·非手速）——PE/引擎须把它当**精确经济**实现（守恒进 hash·可复算）。

### E. 炮台图标（打蛋器·IMG_6063 特写）
11. **圆角方体 + 顶部两个小竖柱（打蛋器）+ 面上动态子弹数**（白字·粗黑描边·卡通）。替换现「圆盘+炮口」。
12. **颜色 = 每关配置为该关像素图实有的颜色**（IMG_6061 洋红+青、IMG_6064 绿/紫/黄）·tint 可调（非固定花园 9 色）。

### F. ⚠ 子弹数语义 = 引擎缺口（per-shot 扣弹·PE 实证）
13. ammo = **发数**·**每命中一发才 -1**（选错色/空过**不减**·故满弹返回平台；打光则中途消失）。这是 §A.4 两去向、§D 选错色满弹返回、面上数字「还剩几发」三者成立的**前提**。
14. **撞墙实证**：`ResourceModify` 仅 `local`/`global` 作用域，**无「子弹扣其发射源炮 ammo」的 source 路由** → N 门炮共享 `ammo` id 时 global 会**串扣错炮**、per-cannon per-shot 当前**组合表达不了**。`self-rule` 条件也无「有目标才触发」门（无 relation 条件）→ 扣弹动作与开火动作无法绑定。**⇒ 候选下沉**（Lead 裁）：① `ResourceModify` 加 `source` 作用域（改 `PrefabOrigin.source` 的资源）；或 ② 「消耗式发射」原语（命中即扣发射源一发）。**裁前 PE 不游戏层自写**。
