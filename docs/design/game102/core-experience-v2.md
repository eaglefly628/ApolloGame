## 1. 真机核心机制（照三图）

1. **环形轨道（Track·轨道）= 单一 360° 闭环传送带**（owner 2026-07-24 强调）：**一条连续的、环绕整幅像素画一周**的跑道（圆角矩形闭环·箭头同向流转·三图皆有）。
   **不是左右直线传送带、也不是四条分开的边带——是一条闭合环带**。**色炮上带后沿环带绕整整一圈跑**（一圈=经过上/右/下/左四条边），**每经过一条边就对该边外沿的同色像素过位剥离**；跑满一圈回到入口（未打完可继续下一圈或回收，按数值定）。
2. **色炮（打蛋器）= 颜色 + 弹药数**（图上 21/18/40/50…=弹药）。绕行时**当它经过某条边、该边外沿露出它同色的像素 → 它向内侧射击、剥掉那些像素**（ref-01 黄炮"21"在右边喷黄格、紫炮"18"喷紫格）。
3. **剥离周边（perimeter→inward）**：炮只能打**它当前经过那条边的、外沿暴露的同色像素**——从外向里一层层啃（不是"全场任意同色秒清"）。
4. **多炮同时绕行 + 时间差（核心乐趣）**：轨道上**同时跑很多炮**（ref-02 右边 0/16/30/33 四炮排队绕），每炮有自己的位置/节奏/弹药。**管理这群炮的时机 = 爽感与技巧天花板**。
5. **选错 = 空转一圈（关键风险）**：若部署的炮，其同色像素不在它将经过的边（或已被啃光）→ **它绕一整圈什么也没打下来**（owner 原话）。→ **部署时机 + 颜色选择 = 核心决策**。
6. **待命槽 ×5**（三图轨道下方一排 5 槽）：待部署的炮。
7. **部署池（下方大网格）**：一堆待用色炮（色+弹药）——含：
   - **🔒 锁定炮（解锁·ref-03 黄锁炮）**：锁着·需解锁才能用（进度/钥匙）。
   - **盲盒炮（owner「盲盒」·ref-02 黑炮群）**：颜色/内容待揭（黑=未知或特殊·部署才知）。*（黑是否=背景色炮 待与实机再核）*
8. **画内特殊件**：🔑钥匙 / 🔒锁块 嵌在像素画里（ref-03 仙人掌两侧）——目标/解锁元素。
9. **关卡分段 `x/5`**（三图左下 3/5·2/5·5/5）：每关 5 段推进。
10. 顶部：设置 / LEVEL N / 金币。

## 1.5 我们的差异化：3D 旋转核心（owner 2026-07-24 · **不完全复刻**）

- 原作中央 = **静止 2D 像素图**。**我们改成：中央 = 3D 像素结构（每像素 = 3D 方块 / voxel），核心方块在那里持续旋转**——立体、会转，作本作**签名视觉差异化**。
- 与 360° 环轨天然契合：环轨绕着这个**旋转的 3D 核心**跑，炮从环上过位剥离它外沿的方块；剥掉的方块走 `fx-3d-debris.md` 真物理碎片落平台。→ **强化选 B「全 3D 盒庭」**（核心/环轨/炮/碎片同一 3D 空间）。
- **⚠ 必须拍板的架构决策（owner/Lead）——旋转是「装饰」还是「玩法」？**
  | | 方案 | 含义 | 代价 |
  |---|---|---|---|
  | **A** | **装饰旋转（render-only）** | sim 仍把核心当**固定网格**判定消除；3D 旋转纯视觉（`Anim3D spin` / `Pivot3D`）。炮打固定格，转只为好看。 | 省·安全·**不碰 determinism**（旋转 render-only·3d.md 铁律）|
  | **B** | **玩法旋转（sim 确定性）** | 旋转角进 **sim（确定性）**，**转动改变「哪些面/边的方块暴露给环轨哪条边」**——须**掐准某色转到你炮将经过的边时**再部署（环轨时机 × 旋转时机 **双层博弈**）。 | 差异化最强·但旋转状态须进 sim（非纯 render·须确定性方案·Lead 裁）|
  > **GD 倾向**：先 **A** 出 MVP（视觉差异化即得·零回放风险），**B** 作进阶（若做，Lead 裁「sim 持旋转角·确定性」）。owner 定。

## 2. ⚠ 与当前 build 的 DELTA（PE 必看·要改的地方）

| 维度 | 当前 build（v1·错） | 真机 v2（要做） |
|---|---|---|
| 轨道 | 单条左→右直线传送带 | **环形轨道绕画四边** |
| 发射 | 队首到左端「发射位」打**任意**同色 | **绕行中·打当前所经边的·外沿暴露同色**（位置/侧向相关） |
| 炮数 | 队列排队·单发射位 | **多炮同时绕圈跑·各自时间差** |
| 失败感 | — | **选错色/时机→空转一圈啥也没打**（核心风险乐趣） |
| 部署池 | 补给区 4 色按钮 | **大网格池 + 🔒解锁 + 盲盒** |
| 分段 | 无 | **每关 x/5 段** |
| **中央核心** | 静止 2D 像素格 | **3D 像素方块结构·持续旋转**（差异化·见 §1.5·旋转装饰 vs 玩法待 owner 裁）|

> 结论：**核心循环要重做**——从「线性队列 + 单发射」改为「**环形轨道 + 多炮绕行 + 过位侧向剥离 + 部署时机博弈**」。已通过的验收剧本 01/02/05（消色/入槽/判负的**结果层**）语义大体仍成立（同色消除、弹尽入槽、判负），但**触发方式**（绕行过位而非到达单点）要改；剧本待随新机制更新。

## 3. 能力实现再评估（请 PE 先试组合·撞墙回 requests·Lead 裁）

- **环形轨道绕行** = `Path3D`（闭环 loop·faceDir·三图轨道是矩形闭环）或 2D 等价环路移动；**多炮** = 多实体各挂路径进度。
- **过位侧向开火** = 关键难点：炮沿轨道位置 → 判定它当前对着哪条边/哪条 lane → 对该 lane 外沿**暴露的**同色 BoardCell 开火（`event-when` 位置/邻接条件 + `launch`/`hitbox`）。**这是比 v1 线性远更复杂的目标模型**。
- **✅ 撞墙已发生并已解（2026-07-25 更新）**：PE 实证 `t2-orbit-motion`+索敌簇成拓扑死环（`aggro→motion-apply→orbit-motion→aggro`·真圆环绕+逐格索敌当时无法共存·REQ-G102-VISCANNON），已下沉 **`REQ-PATHFOLLOW`（写 Velocity 的轨道跟随·与索敌共存）· 引擎团队已 done（commit daae3c3a）**。→ **真环轨现在可做**：game102 挂 `PathFollow{waypoints: 管道环采样}` 让炮**绕轨一圈**，配 `aggro`(锁当前边暴露同色)+`launch` 过位开火，换掉 VISCANNON 的 steering 折中。若「过位判定当前边暴露同色」仍有表达不了处，再回 `requests.md` 报缺口（Lead 裁·裁前不游戏层自写编排）。
- **解锁/盲盒/分段/画内锁块** = `gauge`/`flag`/`event-when`/`effect-apply` + 关卡数据（多为数据层·非新缺口）。
