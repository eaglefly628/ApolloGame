# game111 · 局外集换层（第一期 spec）

> **owner 2026-09-22**（与君白对齐后）：先做局外集换，让新同学在局内玩法之外接一部分。
> 第一期三件：① 单局带出 NPC 卡（编号 / 稀有度 / 文本唯一，随故事情节生成）
> ② 局外展柜可观察带出的卡 ③ 宏观 market 层交易，结算钻石。
> owner 先 vibe demo，再细化。
>
> **本文用途**：给 demo 一份能直接照着做的 spec + 我作为策划必须提的风险。
> 不阻挠进度——**§7 明确划了第一期该做什么、不该做什么**。

---

## 0. 先说清楚：这一步换了游戏的品类

不是加一个功能，是**换一个品类**：

| | 之前 | 加上局外集换之后 |
|---|---|---|
| 形态 | 单机种田 RPG | **带资产与交易市场的服务型游戏** |
| 存档 | 本地就够 | **必须服务端权威**（本地存档 = 可改 = 可造假卡） |
| 平衡 | 只对玩家负责 | **要对经济负责**（通胀 / 刷 / 价格崩） |
| 内容 | 做完就完 | **持续运营**（市场要有人在） |

**这不是反对，是提醒：这三件的工程量与风险，主要不在前端，在服务端与经济。**
demo 阶段可以全本地先跑通手感（§7），但**别让 demo 的本地实现直接长成正式版**。

## 1. ⭐ 核心设计判断：卡的价值从哪来

这是整个局外层成败的那一件事。

### 1.1 陷阱

如果**稀有度是掷骰掉的**，那么：

- 玩家立刻会找出「最快刷卡法」，游戏变成刷卡机。
- 「文本唯一」就成了**装饰**——玩家只看稀有度数字，没人读文本。
- 市场上同稀有度的卡互相替代，价格趋同，收藏欲消失。

### 1.2 ✅ 答案：**卡的价值 = 那次相遇的不可复现性**

> **一张卡不是掉落物，是一次相遇的凭证。**
> 它记录的是**你和这个 NPC 之间真的发生过的事**，别人拿不到一模一样的。
> **它更像一张照片，不像一件装备。**

于是：

| | 怎么做 |
|---|---|
| **稀有度不掷骰** | **由相遇质量算出**（§3），可解释、可追溯 |
| **文本不是装饰** | 它就是价值本体——写的是那次相遇本身 |
| **刷卡自然失效** | 刷出来的都是**低质量的重复相遇**，稀有度自然低 |

### 1.3 为什么这条对我们特别顺

**111 已经做好的东西，正好就是「相遇质量」的记录仪**：

```
记忆系统（谁在何时对谁做了什么·强度·来源）
好感度（这段关系到哪一步了）
对话（你说过什么，它记住了什么）
        ↓
    这三样就是卡面文本的原料，也是稀有度的算料
```

**一行不用重做。** 之前那套 AI 活世界代码，到这里第一次有了**商业价值**。

## 2. 卡牌规格（数据结构 · demo 可直接用）

```
NpcCard {
  cardId        全局唯一（建议 "<npcId>-<铸造序号>"，如 nao-000137）
  mintNo        铸造序号（全服第几张·⭐ 真正的稀缺来源，见 §3.3）
  npcId         谁
  npcName       显示名
  rarity        稀有度档（由 §3 算出，不随机）
  title         卡名（可由文本首句提炼）
  body          ⭐ 唯一文本（那次相遇的记述·LLM 生成）
  art           立绘（NPC 图 + 稀有度边框）
  mintedAt      铸造时间
  runId         哪一局带出的
  ownerId       当前持有者
  provenance    ⭐ 流转记录（谁→谁·成交价）——收藏品的「出身」
}
```

**两个字段值得特别说**：

- **`mintNo` 铸造序号**：全服第几张。**#0001 永远只有一张**。
  这是**不用随机也能产生稀缺**的最干净的办法，而且首发玩家有真实价值。
- **`provenance` 流转记录**：这张卡从谁手里来的。
  收藏品市场的价值有很大一块来自「出身」——**这个字段几乎不花成本，但让市场有故事**。

## 3. 稀有度怎么算（不掷骰 · 可解释）

### 3.1 算料（全部来自局内真实记录）

| 因子 | 说明 | 数据来源 |
|---|---|---|
| **好感度档** | 这段关系到哪一步 | 已有 `Resource aff.<npc>` |
| **是否首次** | 第一次遇见 / 第一次深聊 | 记忆系统 |
| **事件层级** | 普通闲聊 vs 剧情节点 vs 危机时刻 | 局内事件标记 |
| **相遇条件** | 那天发生了什么（罕见天气 / 特殊夜 / 高阶妖怪在场） | 局内状态 |
| **对话深度** | 你和它说过多少、它记住了多少 | 记忆条目强度与数量 |

### 3.2 档位（建议五档，具体阈值 demo 阶段随便定，先跑手感）

```
普通 → 少见 → 稀有 → 珍稀 → 唯一
```

**唯一档**建议**只给剧情节点**（全服所有玩家在那个节点都能拿，但**文本各不相同**）。

### 3.3 ⭐ 稀缺性的三个来源（都不靠随机）

| 来源 | 机制 | 为什么好 |
|---|---|---|
| **铸造序号** | #0001 只有一张 | 天然稀缺，零平衡成本 |
| **相遇质量** | 高档位难达成 | 反刷（刷 = 低质量） |
| **时限窗口** | 某些相遇只在特定时期可能发生 | 制造「当时在场」的价值 |

> ⚠ **别加「全服铸造量越少越稀有」这一条**——它会诱导玩家**囤卡不交易**，
> 正好和 market 层的目标相反。

## 4. 展柜（第二件）

**要做的**：

- 按 NPC / 稀有度 / 获得时间 分组浏览
- 点开看**卡面全文**（⭐ 文本是价值本体，**必须给它足够的展示空间**，别缩成一行）
- 展示 `mintNo` 与 `provenance`（出身）
- 收集进度（这个 NPC 我有几张 / 全服有多少张）

**别做的**（第一期）：

- 自定义排布 / 装饰展柜 —— 好玩但不是核心，第二期
- 分享到社交 —— 需要出图管线，第二期

> **展柜的核心体验是「读」，不是「摆」。** 第一期把「读」做透就够了。

## 5. Market 层（第三件）

### 5.1 最小可用集

| 功能 | 说明 |
|---|---|
| 挂单 | 选一张卡，定价（钻石），上架 |
| 浏览 / 筛选 | 按 NPC / 稀有度 / 价格 / 铸造序号 |
| 成交 | 买 → 钻石转移 + 卡权属转移 + **写一条 provenance** |
| 成交历史 | ⭐ 每张卡 / 每个 NPC 的历史成交价 —— **这是市场的信息层，必须有** |
| 我的挂单 | 撤单 / 改价 |

### 5.2 ⭐ 经济红线（三条 · 缺一必出事）

1. **必须有钻石回收口（sink）。** 建议成交抽成（5–10%）。
   **没有 sink 的经济一定通胀**，这是铁律不是风险。
2. **钻石从哪来必须先定清楚。** 局内产出？充值？两者都有？
   — 这决定了整个经济的性质，**demo 前就要定**。
3. **卡的总量必须可控。** 每局能带出几张？有没有上限？
   **不设限 = 无限通胀 = 市场归零。**

### 5.3 一个必须先回答的问题

> **别人的卡，对我有什么用？**

- ✅ **收藏欲**（集齐某 NPC / 某编号段 / 某时期）
- ✅ **炫耀**（展柜 + 出身）
- ❌ **玩法收益** —— **第一期绝不要给**（见 §7）

---

## 6. ⭐ 为什么第一期「卡不进局内玩法」是对的

owner 已经定了「卡牌主要用于收藏、交易」。**这个判断是对的，值得写下来为什么**：

一旦卡有局内玩法作用：

1. **交易市场立刻变成 Pay-to-Win** —— 有钱的直接买强卡。
2. **局内平衡被市场绑架** —— 你想调一张卡的强度，就是在动别人的资产价格。
3. **刷卡动机暴涨** —— 卡从「纪念品」变成「装备」，§1 那套价值观全塌。

> **收藏品与战斗资源必须是两种东西。** 这条一旦破了就回不来了。

## 7. 第一期范围（demo 该做 / 不该做）

### ✅ 做

| # | 事项 | 验收 |
|---|---|---|
| 1 | 单局结束**铸出一张卡**（含编号 · 稀有度 · 唯一文本） | 跑一局能拿到一张卡，文本与这局真的相关 |
| 2 | **展柜**：列表 + 详情（全文 + 编号 + 出身） | 能翻、能读 |
| 3 | **Market**：挂单 / 浏览 / 成交 / 成交历史 | 两个账号能互相买卖（demo 可造假数据模拟） |
| 4 | **钻石**：余额 + 成交抽成 | 抽成真的扣了 |

### ❌ 不做（第一期）

- 卡进局内玩法（§6）
- 真实支付 / 提现（§9 合规）
- 服务端权威 / 反作弊（demo 阶段本地跑，**但代码结构要留出口**）
- 展柜装饰 / 社交分享
- 卡牌合成 / 升级 / 销毁

### ⚠ demo 阶段可以本地，但**这三处要留接口**

1. **卡的铸造**必须走一个函数（将来换成服务端签发）。
2. **成交**必须走一个函数（将来换成服务端事务）。
3. **钻石余额**不要直接读写本地变量（将来是服务端账本）。

> 留这三个口几乎不花时间，但不留的话，正式版等于重写。

## 8. 工程落点（给接手的新同学）

引擎已有的局外面（**别自造**，`docs/playbooks/save-platform.md` 是手册）：

| 要什么 | 用什么 | 位置 |
|---|---|---|
| 带 schema 与**迁移链**的存档 | `SavePort` + `sealEnvelope`/`openEnvelope` | `src/services/save/` |
| 存储后端（内存 / 本地 / IndexedDB / 云） | `StoragePort` + `select-storage` | `src/services/storage/` |
| 局外小态（偏好 / 进度 / 本地榜） | `localStore` + codec 闭集 | `src/services/persist/` |
| 玩家身份 | `ProfilePort` | `src/services/profile/` |
| 成就 / 排行 / 云存档 | `PlatformPort` | `src/services/platform/` |
| 卡面文本生成 | **`NpcAgentPort`**（已做好） | `src/services/npc-agent/` |
| 相遇质量的算料 | **`t2-memory` + 好感度 Resource**（已做好） | `src/skills/tier2/memory.ts` |

**UI 一律走 `ui/components` 的 LayoutNode 闭集**（展柜列表 `VirtualList` · 卡面 `Card`/`PlayingCard.faceArt` ·
稀有度角标 `Badge` · 筛选 `Tag`/`Combobox` · 价格 `Label.format`）。
**禁手写 React 屏 / 自由 DOM**；查件用 `node scripts/ui-find.mjs <大白话>`；交付前跑 `/check-ui`。

> ⚠ **`SavePort` 的信封自带 schema 校验与迁移链**——卡牌资产是会长期演进的数据，
> **一定用它，别拿裸 JSON 存**。否则第一次改字段就炸档。

## 9. 风险台账（策划必须提的）

| # | 风险 | 说明 | 建议 |
|---|---|---|---|
| 1 | **⚠ 合规** | 「卡牌交易 + 钻石结算」在多数地区触及虚拟财产 / 开箱 / 支付监管，**尤其是涉及提现或真钱定价时** | **demo 不碰真实支付**；正式化之前**必须过一次法务** |
| 2 | **经济通胀** | 无 sink 必崩 | §5.2 三条 |
| 3 | **刷卡** | 局内产出可带出 = 强刷动机 | §1.2 的「稀有度由相遇质量算」是主要防线 |
| 4 | **文本质量不稳定** | LLM 生成的卡面文本，好的很好、差的很差。**而文本是价值本体** | 需要**质量闸**：低分文本不铸卡，或降档。**这条 demo 阶段就要试** |
| 5 | **市场冷启动** | 没人挂单 = 没有市场 | demo 阶段用**造假数据**模拟活跃市场，先验手感 |
| 6 | **与局内设计脱节** | 局外先行，局内还在策划中 | §6 的「卡不进局内」正好**让两边解耦**，可以并行 |

> 第 4 条我认为是**最被低估的**：整个局外层的价值建立在「文本值得读」上。
> 如果玩家发现卡面文本千篇一律，收藏欲和市场会同时崩掉。**这件事值得在 demo 里先验。**

## 10. 待 owner 拍板

1. **钻石从哪来？** 局内产出 / 充值 / 两者。**这决定经济性质，demo 前就得定。**
2. **每局能带出几张卡？** 固定一张，还是按表现给多张？（影响总量与通胀）
3. **「唯一档」给不给全服同节点玩家？**（我建议给，但文本各不相同——
   这样既有仪式感又不制造不可得的焦虑）
4. **§9.4 的文本质量闸**要不要在 demo 里就试？**我建议要**，它是整层的地基。
5. **新同学的边界**：局外层（铸卡 / 展柜 / market / 钻石）归他，
   局内玩法仍在策划中——**两边靠「卡不进局内」解耦，可以并行不打架**。这样分对吗？
