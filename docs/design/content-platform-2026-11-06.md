## 1. owner 定调（2026-11-06）

- **AI 时代玩法和精细设定容易被抄，内容产出才是壁垒。**新创作平台的目标是**产出内容**，不是一句话生成游戏。
- **旧创作平台留给专业游戏开发者**（不再假设普通创作者在旧平台上开发游戏）。
- 编辑器外形向 Unity / Unreal 靠拢，开发方式保持 AI 原生。

## 2. 判断：玩法做成模板，内容做成项目

| | 玩法 | 内容 |
|---|---|---|
| 是什么 | 规则、操作、数值循环 | 故事、角色、世界、镜头表演、台词、音乐、美术 |
| 可复制性 | 高（看一眼就能抄） | 低（量大、风格化、需要持续生产） |
| 在本引擎里 | 已是数据 + 能力（manifest + capability） | 散在各条线，**没有统一的项目结构和生产流程** |
| 新平台对它的姿态 | **选用模板**，不在新平台里新写玩法 | **项目的主体**，编辑器围绕它组织 |

所以 `new<n>` 项目 = **一份内容包 + 选用的玩法模板**。编辑器的资产树、缺口视图、AI 助手都以内容为中心。

## 4. 建议的生产流程（编辑器里怎么做）

1. **剧本**：策划和 AI 对话写剧本（`story` 资产·.md）。
2. **拆镜头**：AI 把剧本拆成镜头表（`sequence` 资产·JSON：每镜 = 角色 + 动作意图 + 台词 + 机位 + 场景）。
3. **缺口视图**：编辑器按镜头列出每样素材的状态——已链接 / 平台里有候选 / 缺。这一步复用动画平台现成的故事补全接口思路，未命中只说「没找到」，不假装库里没有。
4. **补齐**：缺的去动画平台 / 3D 平台找并链接（I1 已通）、或交 AI 生成、或记进美术台账。
5. **预览**：按镜头表在预览区连播（复用导演工作台 / 镜头 / 表演能力）。
6. **可玩化**：选一个玩法模板（叙事、点选冒险、对话选择……）把内容装进去，产出可玩版本。

项目索引只需加内容类资产类型（`story`、`character`、`sequence`），仍走 B（编辑器侧索引，引擎格式不动）。
