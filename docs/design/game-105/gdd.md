## 1. 体验目标

一句话：**让两个人为了一根木头屏住呼吸。**

- 输赢是借口，**任务卡才是目的**——赢的人也想抽到大冒险。
- 塔的每一次晃动都是反馈：手上拖得动/拖不动，眼睛看得见塔在抖。**不需要任何数值提示就知道自己在冒险**。
- 一局 5–15 分钟，随时可以停下来聊天，塔就摆在那里。

## 2. 场地与塔

| 项 | 值 | 备注 |
|---|---|---|
| 层数 × 每层 | 18 × 3 = **54 块** | 标准叠叠乐 |
| 积木长宽高比 | 5 : 1.667 : 1 | 实物 75 × 25 × 15 mm 同比 |
| 逐层朝向 | 交替旋转 90° | 偶数层长轴沿 X·奇数层沿 Z |
| 相机 | 绕塔环视，可俯仰 | `Camera3D`·限制俯角避免穿地 |

### 2.1 ⚠ 尺寸公差 = 玩法成立的前提（非美术细节）

**完全等大的积木，这个游戏不成立**：每层三块均匀承载 → 每一根都被上方压死 → 拔不动或一拔就把整塔带走。
真实叠叠乐好玩，正是因为木块有制造公差，**总有几根是松的**——找出松的那根就是玩法本身。

因此 `TOWER_LAYOUT` 必须为每块附**种子化的尺寸公差**（高 ±1%·宽 ±1.5%·长 ±0.7% 量级，随 `w1-random` 生成
→ 同种子同塔，可复现）。这是规则的一部分，请勿在实现时当作噪声优化掉。

> 实证：等大塔 + 强拉力下，抽出成功率 100% 但**倒塌率 87%**（54 根逐一试拔的离线复现）——即第一回合几乎必输，游戏不成立。

### 2.2 ⚠ 物理世界配置前提

54 块刚体堆叠对求解器的要求远高于掷骰/碎片。实测见 `capability-plan.md §4` 与
`docs/workflow/requests-3d.md → REQ-3D-TOWER-STACK`。**塔立不住则本作全部规则无从谈起**，此为 S3 骨架关的前置。

## 3. 回合流程（状态机 · 对齐 `t3-flow`）

```
        ┌──────────────────────────────────────────────┐
        ▼                                              │ 半途收手（未抽离）
   ┌─────────┐  拾取积木   ┌─────────┐  松手   ┌──────────┐
   │  idle   │───────────▶│ pulling │────────▶│ settling │
   │ 等选积木 │            │  拖拽中  │         │ 等塔落定  │
   └─────────┘            └─────────┘         └────┬─────┘
        ▲                                          │ 落定信号
        │ 确认完成                                  ▼
   ┌─────────┐   已抽离且未塌    ┌──────────────────────┐
   │ handover│◀─────────────────│      judge 判定       │
   │  交手   │                  └──────────┬───────────┘
   └─────────┘                             │ 塔塌了
        │                                  ▼
        └──────▶ idle（对方）          ┌────────┐
                                      │  over  │ 结算
                                      └────────┘
```

| 状态 | 进入条件 | 允许操作 | 离开 |
|---|---|---|---|
| `idle` | 回合开始 | 悬停查看 / 按下选积木 | 拾取信号 → `pulling` |
| `pulling` | 已选中一块 | 拖拽（改 `Joint3D.anchor`）/ 随时松手 | 松手 → `settling` |
| `settling` | 松手 | 无（观赏塔晃） | 落定信号 → `judge` |
| `judge` | 落定 | 无 | 塌→`over`；抽离且未塌→任务卡→`handover`；未抽离且未塌→`idle`（**不换手**） |
| `handover` | 判定通过 | 确认任务卡 | → 对方 `idle`，回合数 +1 |
| `over` | 判定塌 | 看结算 | 重开 |

> **半途收手合法**：拉出一半觉得不妙可以松手，积木留在半抽位置（真实叠叠乐允许）。
> 不换手、不得分、**但塔已经被你动过了**——风险自负。这是本作最重要的博弈点，务必保留。

## 4. 抽积木交互

| 步 | 玩家动作 | 系统 |
|---|---|---|
| 1 | 指针悬停积木 | `Pickable3D.hover` → `WorldUI3D` 在积木头顶浮出颜色名 + 分值 |
| 2 | 按下 | 建「手」：`Joint3D{kind:'point'}`，`pivotA`=积木长轴朝外端，`anchor`=当前世界位，`maxForce`=`PULL_FEEL.maxForce` |
| 3 | 拖拽 | 每帧把 `anchor` 沿**该积木长轴**移动（拖拽量投影到长轴屏幕方向）→ 拉不拉得动**全交给物理** |
| 4 | — | 阻力表：`anchor` 与积木实际抓握点的距离 → `ProgressBar.shape:'ring'`。**拉不动 = 环满 = 别硬来** |
| 5 | 继续拖到底 | 行程 ≥ 92% 积木长度 → 判定抽离 → 拆约束 → 积木飞出（`Impulse3D` 脱手） |
| 6 | 中途松手 | 拆约束，积木停在原位 → `settling` |

**设计要点**：全程**不做任何"能不能抽"的预判提示**。玩家唯一的信息来源是手感（拖不动）与眼睛（塔在抖）。
任何"安全度百分比"式的 UI 都会杀死这个游戏，明确不做。

## 5. 判负

`settling` 落定后，与**本回合开始时记录的基准位姿**比较（排除本回合抽走的那块）：

| 判据 | 阈值 |
|---|---|
| 任一残留块下沉 | > 1.1 × 积木高 |
| 水平位移 > 0.5 单位的块数 | ≥ 3 块 |
| 任一残留块相对基准的倾角 | > 30° |

**任一条命中即判塌**，当前执手方判负。塌塔瞬间：`Camera3D.shake` + 全场变暗 + 结算屏。

> 基准位姿每回合刷新，所以判的是「**这一抽**让塔动了多少」，而不是累积形变——否则打到后期必然误判。

## 6. 计分

### 6.1 四色频道

| 色 | 名 | 频道 | 分值 | 数量 |
|---|---|---|---|---|
| 🌸 | 樱粉 | 甜蜜 | 1 | 20 |
| 💜 | 星紫 | 心动 | 2 | 16 |
| 💙 | 夜蓝 | 默契 | 3 | 12 |
| 🌟 | 流金 | 大冒险 | 5 | 6 |

合计 54。**越高分的越少、也越可能藏在难抽的位置**（颜色分布由 `w1-random` 种子化洗牌，不做位置偏置——
难抽与否交给公差与物理，不人为设计）。

### 6.2 得分

```
成功抽出一块 →  抽出者亲密度 += 颜色分值 × 轮次档
轮次档 = 1 + floor((当前轮次 - 1) / 4)          // 1-4轮×1，5-8轮×2，9-12轮×3 …
共同亲密度 = 双方之和                            // Gauge 显示，是本局的"成果"
```

### 6.3 惩罚分（输家结算）

```
惩罚分 = Σ(输家抽过的所有积木颜色分值) + 当前轮次 × 3
```

语义：**抽得越多、撑得越久，输的时候越惨**——鼓励见好就收，但见好就收又拿不到分。

| 惩罚分 | 等级 | 内容基调 |
|---|---|---|
| ≤ 12 | 轻羽级 🪶 | 一句夸奖 / 额头吻 |
| 13–26 | 微甜级 🍬 | 一天的称呼权 + 一杯奶茶 |
| 27–44 | 心跳级 💗 | 三个必须诚实回答的问题 + 包办下次约会 |
| ≥ 45 | 沦陷级 🔥 | 一周早晚安 + 一分钟当场告白 |

> 惩罚内容全部落 `PENALTY_TIERS` 数据表，由 `t3-dialogue` 呈现，**便于按受众整套替换**（不同人群一套文案包）。

## 7. 任务卡

- 每成功抽出一块 → 按其**颜色频道**从对应卡组抽一张（`t2-dice-roll` 种子化·**抽空前不重复**）。
- 卡片用 VN 三件呈现：`dialog`（逐字打出卡面）+ `portrait`（男女主立绘）+ `choiceList`（「完成了」/「换一张」）。
- 「换一张」每人每局限 1 次（`f1-resource` 计数），换来的卡不能再换。
- 「默契」频道是**双人同答题**：两人各选一次，答案一致则双方各 +2 额外亲密度。

卡组规模初稿：甜蜜 12 / 心动 12 / 默契 12 / 大冒险 6 = 42 张（`TASK_DECKS`）。

## 8. 边界情况

| 情况 | 规则 |
|---|---|
| 塔上只剩 ≤ 3 块 | 直接进结算，判**双赢**（共同亲密度结算，无人受罚） |
| 抽的过程中塔就塌了（没松手） | 照塌处理，当前执手方负 |
| 半抽状态的积木被后续回合碰掉 | 算**碰掉它的那个人**的责任（判负逻辑不区分是谁半抽的） |
| 顶层积木 | 可抽（真实规则通常禁抽最顶层，本作**不禁**——顶层本就不危险，禁了只是加规则不加乐趣） |
| 同时命中多块（射线） | 取最近者（`Pickable3D` 既有语义） |

## 9. 里程碑

| 里程碑 | 内容 |
|---|---|
| **M1（S3–S4 闭环竖切）** | 塔立得住 + 能抽 + 判塌 + 计分 + 交手 + 结算。任务卡先用占位单卡。**目标=最小循环跑通** |
| **M2** | 四色卡组全量 + VN 三件呈现 + 惩罚分级 + 华丽 UI（`apolloBrocade` + `@ui/starters`） |
| **M3** | 抽出的积木**放回塔顶**（真实叠叠乐规则·塔越来越高越危险）。M1/M2 不做——交互复杂度翻倍，先证明核心循环好玩 |
| **M4** | 文案包切换（不同受众整套替换）、局外共同亲密度累计 |

## 10. 明确不做

- **不做单人模式**：这是约会游戏，一个人玩没有意义。
- **不做联机**：本地 hot-seat 同屏轮流即产品形态（确定性取舍见 plan §5）。
- **不做安全度提示 / 抽取成功率预测**：见 §4 设计要点。
- **不做时间限制**：想聊多久聊多久，塔不会跑。
