> 状态：**VISION / 待续想**（owner 2026-07-01 口述 → Claude 整理落地）。
> 用途：owner 说「我可能让别人继续思考下去」——这份文档把 owner 的原始意图完整落地，
> 供下一位设计者/程序员接着推演。**它描述的是「未来的对决核」**，不是当前已实装的核。
> 当前实装（过渡态）见文末 §7「与现行实装的关系」。

## 0. 一句话

对决时**双方各自掷出自己的「战力骰」**——我战力 17 就掷 `1~17`、他战力 9 就掷 `1~9`，**比大小、大者胜**；
掷之前**可以用手牌/技能改这一掷**（方片×2、意大利降临×1.2…），于是「凑人物牌、攒战力」第一次真正变成战略核心。
**各自掷各自的**（你掷你的、我掷我的）——这是刻意的，为**以后 PvP 对战**留结构空间。

## 1. 为什么要这个（爽感诊断）

owner 原话（2026-06-30）：

> 「我突然知道我们这个问题的爽感在哪里了……我们各自有战力对不对？那么各自应该掷出自己的战力。
> 比如我的战力范围是 17，那我掷出的值就应该是 0~17。他战力是 9，掷出来数字就 0~9。就是再比较这个数字大小……
> 有一些局外的情况，可以帮助你去改变你这个掷出来的骰子的结果……战力是带入战场的……
> 掷战力的时候，是不是要发动一些技能？比如说手上有一些牌可以使用的，比如说方片乘双倍啊，
> 或者说意大利降临什么之类的，1.2 倍啊……就把这个人物牌的收集变成了很重要了。」

痛点：此前的对决只是「有效战力比大小 / logistic 胜率骰」，**玩家的能动性只在放牌前**；
一旦两军相邻，结果基本注定，掷骰只是走过场——「战斗的时候我又没看清楚 / 没意思」。

爽感来源（本策划案要兑现的）：

1. **临掷可翻盘**：即便战力低，掷出高值 + 一张方片×2，也能以弱胜强 → 每一次对决都有悬念、都值得盯着看。
2. **收集有回报**：人物牌（方片系、意大利降临…）不再只是数值，而是「改掷」的资源 → 攒牌 = 攒翻盘手段。
3. **战力仍是王道**：战力越高，掷出高值的**期望**越高、地板越高 → 经营（天罡/附魔/协同）依然是主线，骰子只是加了「敢不敢赌」这一层。
4. **PvP 就绪**：各掷各的 → 两个玩家可以同时、独立地做「掷前决策」，天然是对称对局的原子。

## 2. 核心机制

### 2.1 战力骰（范围校正）

- 每方前锋进入对决时，各自掷一个整数：`roll ∈ [1, P]`（**含 1、含 P**）。
  - ⚠️ **owner 校正（2026-07-01）**：「我战力 0~17，是不存在 0~17 的，1~17，1~9。掷不出 0 的。」
    → **下界是 1，不是 0**。战力为 P 的兵，最差也能掷出 1，绝不空手。
  - 退化：`P = 0` 视为无战斗力（理论上不该出现，兵最低点数 2 → P≥2）；实现里 clamp `P = max(1, P)`。
- **大者胜**。`rollA > rollB → A 胜`；`rollA < rollB → B 胜`；`rollA == rollB → 平局阶梯`（见 §2.4）。

### 2.2 掷前改命（roll-modifier hook · 收集变重要）

掷之前，持有方可发动**改掷技能/手牌**，改这一掷的结果。两类算子（沿用 `{op, value}` 心智，**不建统一 Buff 引擎**）：

| 类型 | 例 | 作用 | 备注 |
|---|---|---|---|
| `mul`（乘） | 方片×2、意大利降临×1.2 | `roll *= value` | 期望翻倍/放大，最能翻盘 |
| `add`（加） | 某功能牌 +3 | `roll += value` | 稳定小幅，保底 |

- **发动时机**：进入「掷前决策」窗口 → 玩家选发动哪些（消耗手牌/源泉/次数）→ 锁定 → 双方同时掷 → 应用算子 → 比大小。
- **AI 同权**：AI 也在自己的掷前窗口决定发动哪些 buff（见 §5）。
- **收集回报**：这些改掷牌就是「人物牌收集」的兑现口——攒到方片×2 = 攒到一次「战力翻倍掷」。

### 2.3 ⚠️ 防数据爆炸（owner 反复强调的红线）

owner 原话：「这上面我们要特别小心，防止一些数据爆炸。」

失控路径：`mul` 叠乘（×2 ×1.2 ×1.2…）→ 掷值指数膨胀 → 战力体系失去意义、UI 数字爆表、平衡崩。
护栏（建议初值，待仿真台扫）：

1. **改掷后夹界**：`rollFinal = clamp(applyMods(roll), 1, ROLL_CAP)`，`ROLL_CAP = 2 × P_MAX = 60`（P_MAX 现为 30）。
   → 任何一掷的绝对上限锁死，乘算子再多也顶到 CAP。
2. **每场改掷预算**：一场对决每方**最多发动 N 张改掷牌**（建议 N=2），且**乘算子每场至多一个**（×2 与 ×1.2 不叠乘，取其一）。
   → 从源头禁止 `mul` 链式叠乘。
3. **加算子封顶**：`Σadd ≤ ADD_CAP`（建议 = P，即最多把掷值抬高一个自身战力身位）。
4. **稀缺**：改掷牌是消耗品（用完回牌库需重抽 / 有冷却），不是常驻被动 → 天然限流。

> 复诵红线：**乘不叠、每场限张、掷后夹 CAP**。任何新改掷牌先过这三关，过不了就回驳。

### 2.4 平局与确定性

- 平局（`rollFinal` 相等）走既有阶梯：**点数 → 续航 staminaLeft → 先手(地煞 firstStrike)/默认**。
- 全流程**种子化**（复用引擎 PRNG `nextRandom`、lockstep 顺序消费）→ 可回放、可做平衡回归、镜像同步不裂。
  - 每场消费固定次数的 rng（A 掷 1 次、B 掷 1 次、平局兜底 0~1 次）→ 顺序写死，hash 稳。

### 2.5 预报数学（UI「掷命预报」要显示的胜率）

两个独立均匀分布 `a ~ U{1..A}`、`b ~ U{1..B}`（改掷后的等效范围），A 胜（`a>b`）的概率：

```
连续近似（A,B 较大时够用）：
  P(a>b) = A ≥ B ?  1 − B/(2A)          // 我战力不低于敌：稳超一半
                  :  A/(2B)              // 我战力低于敌：靠掷+翻盘
P(平) ≈ 0（离散下 = 交叠区/(A·B)，小，计入平局阶梯）
```

- 例：`A=17, B=9 → P≈1−9/34≈0.735`（≈73% 胜，但**不是碾压**——弱兵仍有 ~26% 翻盘窗口 → 悬念）。
- 例：`A=9, B=17 → P≈9/34≈0.265`（弱势方仍有 ~26% 逆袭 → 敢赌就有戏）。
- **这正是 owner 要的手感**：战力差决定期望，但绝不封死。UI 预报直接显示这个 `P` + 双方 `[1,P]` 范围 + 已挂的改掷算子。

## 3. 战力 = 带进战场的资源（不是每场重算的临时值）

owner：「战力是带入战场的。」

- 一张兵的战力 `P` = 基础点数 + 经营 buff（天罡/附魔/相邻协同/士气/路 buff）→ **在它上场那一刻定档、随场携带**。
- 对决只改「这一掷」，**不永久改战力**（除非战损疲劳，见 §4）。
- 含义：掷命是「消费当前战力去赌一个结果」，不是「重新结算战力」。战力的养成价值稳定、可预期。

---

## 4. 战损疲劳（与掷骰结合 · 弱兵车轮磨强兵）

（此层**已在过渡态实装**，未来向保留并与战力骰结合。）

- 胜者**永远留场**（战场不空、心流不断），但**每胜一场，战力对折**（`P → P/2 → P/4 …`）。
- 连胜满 `WIN_CAP=3` → **必须光荣离场**（回牌库 + 全额返还源泉；重抽出场即满血、疲劳清零）。
- 战略意义：强兵连胜越打越弱 → **弱兵车轮战能磨死强兵**。这是本作核心策略深度之一。
- **与战力骰结合**：疲劳先把 `P` 打折 → 再进 §2 的 `roll ∈ [1, P_疲劳后]`。天罡类可设计成「延缓疲劳 / 抗对折」的改命牌。

## 5. AI（各自掷 · 对称结构）

- AI 前锋进对决时，**AI 也掷自己的 `[1, P_ai]`**，并在自己的掷前窗口决定发动哪些改掷 buff。
- AI 决策维度（沿用现有 utility-greedy + AiProfile）：
  - 期望增益：`ΔP(a>b)` 发动某改掷牌后胜率提升多少 → 值不值得消耗。
  - 稀缺权衡：把方片×2 留给关键对决还是现在就用（economy/risk profile）。
  - tier 门控：低 tier AI 少发动/发动次优；高 tier 会把改掷牌留给「一发定生死」的路。
- **对称性**：玩家与 AI 走**同一套掷+改掷 API** → 直接就是 PvP 的两个 seat。这是「各自掷各自的」的落点。

## 6. 重排所有策略数值（holistic re-plan · owner 委托）

owner：「我需要重新想一下这个整个的数值的一个规划……好在你是个 AI，你可以把我所有定好的这些策略数值都可以重新的去编排和算。」

引入战力骰后，很多旧旋钮的语义变了，**建议整体重算**（下一位接手者的核心工作）：

| 旋钮 | 现值 | 战力骰下的新语义 / 待定 |
|---|---|---|
| `P_MIN / P_MAX` | 0 / 30 | 掷值范围的地板/天花；`ROLL_CAP` 应 = k×P_MAX |
| `CLASH_K`（logistic 软硬度） | 5 | **可能废弃**——胜率改由 `[1,P]` 比大小天然产生，不再需要 logistic |
| `WR_MIN/MAX`（爆冷缝 0.03/0.97） | — | **天然内建**：战力骰本身就给弱者留翻盘缝，可能不再单列 |
| 改掷算子 CAP（新） | — | `ROLL_CAP=60`、每场限 2 张、乘不叠、`ADD_CAP=P` —— 待仿真扫 |
| `WIN_CAP` | 3 | 保留（连胜上限） |
| 疲劳对折率 | 0.5/胜 | 保留；可做成可调（天罡改命） |
| 各牌基础点数 baselineFavor | pip-base | 战力骰下点数=掷值上限，直接影响期望 → 需连带重算 |

- **方法**：用 `simulate-balance.ts` 仿真台，把「思考型玩家（会算期望、会留改掷牌）」建模进去，
  扫 `ROLL_CAP / 改掷预算 / 疲劳率 / baselineFavor`，目标关卡胜率（第一关 ~70-80%）。
  - ⚠️ 现仿真台是 greedy 玩家，是「思考型玩家」的差代理（owner:「动点脑子就能赢」）——重排前**先升级仿真台玩家模型**，否则扫出来的数值对真人不准。

## 7. 与现行实装的关系（过渡态 · 别搞混）

**当前 game-g 实装的对决核（2026-07-01 owner 拍板的过渡态）**：

- **确定制**：无战力骰、无掷币——**有效战力高者直接胜**（平局走阶梯）。owner:「掷骰子那个环节、掷硬币那个环节好像没有意义了，太繁琐了」→ 掷币代码**降为死代码**保留（`coin-flip.ts` 不再进主流程），战力骰是**未来**才接。
- **疲劳对折**：§4 已实装（每胜战力对折、WIN_CAP=3 光荣回库）。
- **碰撞才战斗**：兵按 speed 逐格推进，**前锋撞到敌前锋相邻格才对决**（确定可预测）。
- **一步步结算演出**：滑到位 → 弹「谁打谁 + 双方战力」→ 先演败者阵亡（谁死清楚）→ 幸存者头顶 UI 标「战力对折 −N」→ 该步结束。

**从过渡态 → 本策划案（战力骰）的迁移路线**（给接手者）：

1. 在 `clash-resolve.ts` 加 `fateRoll(P, rng)` 与 `applyRollMods(roll, mods)`（含 §2.3 三道护栏）。
2. `resolveClash` 的「确定制比大小」替换为「双方各掷 → 应用改掷 → 比大小」（平局阶梯不变；rng 顺序写死）。
3. `clashOdds` 预报改用 §2.5 的 `P(a>b)` 公式。
4. UI：掷命特写从「确定展示战力」升级为「双掷动画 + 掷前改掷选择窗口」；掷币死代码可复用为掷骰动画骨架。
5. AI：`aiDecide` 增「掷前发动哪些改掷牌」子决策（§5）。
6. 数值：走 §6 整体重排，先升级仿真台玩家模型再扫参。

## 8. 待续想的开放问题（留给下一位）

1. **改掷窗口的操作量**：每场都弹「要不要发动改掷牌」会不会太繁琐？是否只在「关键路 / 玩家主动点」才开窗？（owner 很反感繁琐——「太繁琐了」是他砍掉掷币的直接理由。）
2. **改掷牌从哪来**：是手牌里的功能牌，还是独立的「战术牌」资源池？（关联未实装的 REQ-G-即时法术/功能牌：「功能牌大于战斗牌」。）
3. **信息公开度（PvP）**：各自掷各自的——对手挂了哪些改掷算子，是明牌还是暗牌？暗牌更有心理博弈，但更难做平衡与反作弊。
4. **平局频率**：小战力兵（P=2、P=3）之间掷值撞车概率高 → 平局阶梯会被频繁触发，需确认阶梯手感。
5. **疲劳与掷的先后**：对折先于掷（现设计）还是改掷能「抗对折」？后者让天罡改命牌更有戏，但更易数据爆炸。
6. **数据爆炸的仿真验证**：§2.3 的护栏初值必须过仿真台的「极端 build」压测（全方片×2 流）才敢定。
