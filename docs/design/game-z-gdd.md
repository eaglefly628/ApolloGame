# Game Z ·《盒庭寻宝》游戏设计文档（GDD v0 草案）

> **作者**：P3D（3D 渲染线工程师 + Game Z 主策划/程序）· 2026-06-28
> **状态**：🟡 方向待 owner 拍板。本文是设计纲领 + 能力缺口的架构评判，不是已批准的工单。
> **定位一句话**：任天堂《奇诺比奥队长：寻宝大冒险》(Captain Toad: Treasure Tracker) 式的 **3D 盒庭旋转解谜**——把立体微缩模型当谜题，转动它找出通往终点的路。

---

## 0. 为什么是「盒庭旋转解谜」（主策的选型理由，不是因为现成才选）

owner 要的是**任天堂系列的设计感**。任天堂设计哲学的第一性原则是宫本茂的「**一个机制，挖到底**」——不堆系统，把一个核心动词玩出花。

我们这条 3D 线**天生的核心动词就是「旋转盒庭」**（`Camera3D` 轨道相机已完工）。Captain Toad 的天才约束是：**主角不能跳**。这一个约束同时成全三件事：

1. **把「旋转视角找路」逼成唯一核心玩法** —— 纯粹，任天堂味。
2. **正好避开我们还没有的 Y 轴跳跃/重力物理** —— 不用现在去长这块能力（YAGNI）。
3. **让每个盒庭变成一个可把玩的立体谜题玩具**，而非动作关卡。

> 结论：**「任天堂感 × 最小能力缺口」的最优交集就是 Captain Toad 式。** 这不是将就现成，是设计与技术约束刚好同向。

## 1. 四条任天堂设计铁律（烤进每一关）

| 铁律 | 来源 | 在本作怎么落地 |
|---|---|---|
| **一关一个新玩具** | 任天堂关卡结构 | 每个盒庭引入**一个**新交互元素（开关、移动平台、矿车、可拔的萝卜、追你的敌人…），不堆叠 |
| **起承转结的关卡曲线** | 起承転結（无人工难度墙） | 每关：引入机制(起)→ 练熟(承)→ 一个意外转折(転)→ 收束通关(結) |
| **关卡即教学·零文字** | 超级马里奥 1-1 哲学 | 不写「按住拖拽旋转」；用关卡布局**逼**玩家自己发现「转到背面才看见的路」 |
| **世界有玩具感·处处有反馈** | 任天堂的「可触摸的世界」 | 宝石会闪、踩开关门会开、收集物「叮」一声消失、敌人有预告动作 |

**收集驱动**（Captain Toad 经典三件套）：每关 = **终点星 1 颗（主目标）+ 隐藏钻石 3 颗（副目标）**。钻石逼玩家转遍盒庭每个死角，给「精通」留空间——**易上手、难全收**。

## 2. 核心循环（Core Loop）

```
       ┌─────────────────────────────────────────────┐
       │  观察盒庭  →  旋转视角（核心动词）            │
       │     ↑              ↓                          │
       │  发现新路  ←  看见被挡住的路/钻石/机关        │
       │     ↓                                         │
       │  走过去（WASD·不能跳）→ 踩机关/拾宝/避敌      │
       │     ↓                                         │
       │  抵达终点星 + 集齐钻石  →  通关 → 下一盒庭    │
       └─────────────────────────────────────────────┘
```

一局 = 一串盒庭，难度温柔爬升，每关一个新玩具。

## 3. 玩法元素清单（v1 词汇表）

> 全部用**现有引擎能力 + 纯数据**表达（见 §5 评判）。下面是「设计意图」，不是最终数据 schema。

| 元素 | 玩法作用 | 数据表达（指示性） |
|---|---|---|
| **小黄鸭（主角）** | 玩家走动的载体·不能跳 | `Transform` + `Velocity` + `Model3D` + `Collider3D`(胶囊) |
| **终点星** | 主目标·碰到通关 | `Mesh3D`/`Model3D` + `Collider3D`(trigger) |
| **隐藏钻石 ×3** | 副目标·收集计数 | 同上 + 拾取规则（`Effect{destroy}` + `Resource +1`） |
| **踩踏开关 → 门/桥** | 解谜·开路 | 触发 → 信号 → `Effect`(移动/销毁门实体) |
| **移动平台** | 时机·动态路径 | `Tween` `loop:'pingpong'`（往复） |
| **简单敌人** | 威胁·绕路 | 沿固定路线 `Tween`/巡逻；碰到 = 重置本关位置（不死亡，温柔） |
| **可旋转门/转盘** | 旋转视角的谜题强化 | 数据驱动旋转（Tween rotY 或开关触发） |

**刻意不做（v1·YAGNI）**：跳跃、布娃娃物理、复杂战斗、背包/装备、对话剧情。这些都不是 Captain Toad 的核心，且会拉进我们还没有的能力。

## 4. 样板关卡：第 1 关《初见盒庭》（演示起承转结 + 零文字教学）

> 目的：玩家**不读任何字**，自己学会「旋转能看见被挡住的路」。

- **起（引入旋转）**：开场视角下，终点星明晃晃在对面高台上，但通往它的路被一面**前墙挡死**——直走是断头路。玩家自然会去拖拽旋转 → **转到侧面，发现墙后有一条绕行的窄道**。这就是无字教学：旋转 = 找路。
- **承（练熟）**：窄道上摆 1 颗钻石（顺手可得）+ 一个**踩踏开关**，踩下去升起一座桥接到高台第二段。让玩家把「旋转观察 + 走 + 踩机关」练成肌肉记忆。
- **転（转折）**：第二颗钻石放在一个**只有从盒庭正后方 180° 才看得见的凹龛**里——逼玩家把盒庭转一整圈。第三颗钻石放在一座**移动平台**尽头，要算准 pingpong 时机走上去。
- **結（收束）**：集齐 3 钻 + 走上终点星 → 盒庭轻微庆祝（星星放光/泛光脉冲）→ 通关，进第 2 关。

后续关卡按「每关一个新玩具」继续：第 2 关引入敌人巡逻，第 3 关引入矿车/导轨，第 4 关多开关组合谜题……

## 5. ⭐ 能力缺口架构评判（CLAUDE.md 核心规则 #2 —— 本文最重要的一节）

> 尺子：**能用现有 capability 重组表达？→ 回驳成「摆数据」**；已被覆盖？→ 回驳；**真表达不了的缺口？→ 才下沉成通用能力 / 报主程**。

### 5.1 回驳栏：这些「看似要新建的系统」全是现成能力 + 数据（不立新需求）

调研（探子盘 `skills/` + game-e/f 蓝图）证实，引擎玩法层早已造好。以下一律**用数据表达，不写新 system、不提新需求**：

| 设计需要 | 现成能力（证据） | 判定 |
|---|---|---|
| 胜利/失败/通关/关卡推进 | `GameFlow` 声明式状态机（`logic.ts:189`·game-f 跑完整局流程） | ✅ 摆数据 |
| 规则「条件 → 动作」 | `EventWhen`(条件树→信号) + `Effect`(信号→动作) | ✅ 摆数据 |
| 拾取计数 / 分数 / 进度变量 | `Resource` / `Flag` / `StringVar` + `GroupCount` | ✅ 摆数据 |
| 拾取后宝石消失 | `Effect{kind:'destroy', targetEntity:'@signal-source'}` | ✅ 摆数据 |
| 踩开关开门 / 钥匙开门 | 触发信号 → 条件门 `EventWhen` → `Effect` 移动/销毁门 | ✅ 摆数据 |
| 移动平台往复 | `Tween` `target:'Transform.x' loop:'pingpong'` | ✅ 摆数据 |
| 敌人生成 / 清场 | `Caster` + `PrefabLibrary` + `destroy-tagged` | ✅ 摆数据 |
| 条件组合（集齐3钻**且**到终点才通关） | `ConditionExpr` 布尔树（and/or/not + flag/resource/timer/state 叶子） | ✅ 摆数据 |

**含义**：做一个**单关卡** Captain Toad 盒庭，**逼近零新引擎能力**——几乎纯数据创作。这正是数据驱动宣言要的样子。

### 5.2 真缺口栏：现有数据/能力**表达不了**的（才需下沉/报主程）

下面是诚实盘出的、单靠摆数据绕不过去的缺口。**注意：均待我在实现时二次核验**（探子的部分 API 细节未经我亲验）；确认是真缺口的，按契约 §0.1 走 `requests-3d.md` 或报主程评审，**绝不在游戏层手写 system 逃生**。

1. **【最关键·可能真缺口】Overlap3D → 信号 的桥**
   Captain Toad 的拾取/触发是「**走过去**」（`Overlap3D` 重叠），不是「点一下」（`Clickable`）。需要确认：3D 逻辑碰撞产出的 `Overlap3D` 事件，能不能像 2D `Overlap` 那样**被 `EventWhen`/`Effect` 当信号消费**（走进钻石 → 触发拾取）。
   - 若 2D 有「overlap→effect」桥而 3D 没接通 → **这是唯一卡住 MVP 的真缺口**，报主程（sim 域）补一个 `Overlap3D` → 信号的解释（镜像 2D 先例·确定性·进 hash）。
   - 这块属主程域（碰撞 sim 在 `engine/spatial`+`skills`），**我不直接改**，写 `requests-3d.md` 报评审。

2. **【结构问题·可推迟】多盒庭 / 关卡切换（卸载旧蓝图·装载新蓝图）**
   现在 game-z 是单蓝图。多关卡有两条路：(A) `GameFlow` 状态机内用 `set-state` 切「当前关」+ Assembly 层监听换蓝图（需主程在装配层加 scene-load/unload seam）；(B) 单蓝图参数化 `dioramaBlueprint(levelId)` + 全关实体共存只切激活。
   - **MVP 决策：先做单关卡，多关卡推迟**。等单关玩法跑通、owner 确认方向，再评估 A/B 并报主程定装配层 seam。

3. **【可推迟·YAGNI】非线性路径补间（waypoint 平台）**
   `Tween` 只支持线性 `from→to`。直线往复平台够覆盖 Captain Toad 80% 平台。要「沿折线/导轨跑的矿车」才需要 `PathTween`/waypoint 能力。
   - **MVP 决策：用直线 pingpong，矿车/折线路推迟**；真要时报主程评估（可能是 `Tween` 的小扩增或新 tier1 能力）。

4. **【可推迟】3D 寻路**
   现 `Pathfind` 是 2D planar。敌人 v1 走固定 `Tween` 巡逻即可，不需要寻路。**推迟**。

### 5.3 P3D 自己域内能顺手做的（不出 3D 渲染线，自己落）

- 终点星/钻石/开关的**视觉与反馈**（闪光、泛光脉冲、踩下动画）——render-only，`Mesh3D`/`Model3D`/`Post3D` + `Tween`，我的渲染线域。
- HUD：钻石计数「💎 1/3」、通关提示——`LayoutNode` 纯数据（UI 铁律），读 `Resource`。
- 盒庭关卡数据本体（`diorama.ts` 那样摆实体）——game-z 我独占。

## 7. MVP 分期路线（按性价比，全程 tsc+vitest+build 全绿才推）

- **M0 · 验缺口（先做·阻塞项）**：核验 §5.2#1「Overlap3D→信号」是否通。通 → MVP 全数据可做；不通 → 写 `requests-3d.md` 报主程补桥。**这一步决定 MVP 是不是纯数据。**
- **M1 · 单关 MVP（核心可玩）**：在现有盒庭上做第 1 关《初见盒庭》——终点星 + 3 钻石 + 1 踩踏开关 + 1 移动平台 + 胜利条件（`GameFlow`）。HUD 显示钻石计数 + 通关。**目标：能从头玩到通关。**
- **M2 · 任天堂打磨（juice）**：拾取/通关反馈、星星放光、零文字教学的关卡布局校准、敌人巡逻。
- **M3 · 多关卡（待 owner + 主程）**：评估 §5.2#2 装配层 seam，做 2–3 关串联。
