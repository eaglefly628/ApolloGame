# Game H —《二十一点》Blackjack

## 概述

传统 21 点（Blackjack）纸牌游戏。

**特点**：最小化数据驱动实现，玩家与庄家对赌，目标是手牌总和尽可能接近 21 且不超 21。

## 玩法规则

### 基本规则
- 玩家和庄家各得 2 张初始卡牌
- 卡牌点数：2-10 为面值，J/Q/K 为 10 点，A 为 1 或 11 点（灵活选择）
- 目标：手牌总和最接近 21（不超过）

### 玩家回合
- 可选"要牌"（Hit）：从牌堆抽 1 张
- 可选"停牌"（Stand）：确认当前点数，进入庄家回合
- 若点数超过 21，立即"爆牌"（Bust），游戏结束，庄家胜

### 庄家回合（自动）
- 庄家按固定规则行动：点数 < 17 时持续要牌，≥ 17 时停牌
- 若庄家点数超过 21，庄家爆牌，玩家胜

### 胜负判定
| 场景 | 结果 |
|------|------|
| 玩家爆牌 | 庄家胜 |
| 庄家爆牌，玩家未爆 | 玩家胜 |
| 都未爆，玩家点数 > 庄家点数 | 玩家胜 |
| 都未爆，点数相同 | 平局 |
| 都未爆，玩家点数 < 庄家点数 | 庄家胜 |

## 数据架构（纯数据驱动）

### 游戏状态
```
初始化 (INIT) → 玩家回合 (PLAYER_TURN) → 庄家回合 (DEALER_TURN) → 游戏结束 (GAME_OVER)
```

### 核心资源
| 资源 ID | 含义 | 初值 |
|--------|------|------|
| `deck` | 牌堆剩余卡数 | 52 |
| `player_cards` | 玩家手牌张数 | 2 |
| `player_score` | 玩家点数 | 0 |
| `dealer_cards` | 庄家手牌张数 | 2 |
| `dealer_score` | 庄家点数 | 0 |

### 交互实体（clickable）
| 按钮 | 动作 | 效果 |
|------|------|------|
| 要牌 (hit) | 玩家抽牌 | `player_cards +1`, `deck -1` → 重算 `player_score` |
| 停牌 (stand) | 进入庄家回合 | 状态 → `DEALER_TURN` |
| 重新开始 (restart) | 重置游戏 | 状态 → `INIT`, 资源重置 |

## 实现方案

### 文件结构
```
game-h/
├── blueprint.ts       # 能力装配 + 实体定义（纯数据）
├── theme.ts          # 卡牌定义 + 游戏常量（纯数据）
├── index.ts          # 导出接口
└── README.md         # 本文件
```

### 关键设计决策

#### 1. **点数计算在 UI 层**
- 点数计算（A 计 1 或 11）是最小的"逻辑"
- 当前版本由 UI 层 React 组件处理（不在引擎/蓝图侧）
- **技术债**：若要完全数据化，应下沉成 `card-scoring` capability（已在 `@skills/tier2` 中）

#### 2. **庄家 AI 自动化**
- 庄家规则固定：17 点站住，< 17 时要牌
- 由 UI 组件中的 `applyDealerLogic()` 自动执行
- 完全确定性，无随机性（仅依赖卡牌序列）

#### 3. **最小化能力集**
- 使用 4 个原子能力：`resource` + `clickable` + `state` + `text`
- 无需引入 Tier2/3 的复杂机制
- 游戏规则全部由 UI 层的声明式数据驱动

## 与数据驱动宣言的对应

✅ **符合**：
- 游戏实体 = 纯 JSON 数据（blueprint + theme）
- 玩家和 AI 永不接触代码，只操作数据

⚠️ **技术债**：
- 点数计算 + 胜负判定 = React 组件中的自由代码
- 未来可下沉成 `card-scoring` 和 `game-outcome` capability

## UI 集成

游戏的呈现层（React 组件）负责：
1. 读取蓝图数据，初始化世界
2. 订阅资源变化，更新视图
3. 执行点数计算和胜负判定
4. 响应按钮点击，更新资源和状态
