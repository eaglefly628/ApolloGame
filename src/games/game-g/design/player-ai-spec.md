# 玩家 AI 行为规格（给甲 · owner 2026-06-21「单独开发·尽其所能写复杂」· design G）

> 背景：sim 里的"玩家"现在是**贪心脚本**（cast天罡 → 部署最便宜 → 抽牌），它只会无脑铺场，**手感不准**——它打出来的胜率既不代表新手、也不代表高手。owner 拍板：
> 「玩家 AI 是我们游戏**非常独特的一部分**，必须**单独开发**。我也不觉得是数据驱动的——**让甲尽其所能地把它写得复杂点**。我也不想第一关就 50%，尽量往 **70%** 靠。」
>
> 所以这是**唯一一处明确豁免"数据驱动宣言"的代码**：玩家 AI = 引擎里一个**手写的、复杂的、搜索/评估型决策组件**，不下沉成数据。它的用途有二：
> 1. **平衡基准**：给 sim 一个"会打的高手玩家"，让 sim WR 代表真实手感（替换贪心脚本）。
> 2. **可选 PvE 演示/托管/教学提示**：同一个 AI 能给玩家做"推荐走法"提示。
>
> 这是 `REQ-G-Player-AI`(P0) 的行为规格。**注意**：它和 `boss-ai-spec.md` 的 Boss AI **是两套独立的智能**——Boss AI 靠信息不对称（读你手牌）；玩家 AI 靠**纯局面推演**（它只看自己合法可见的信息：自己手牌、双方场面、Boss 的明牌地煞/天罡 loadout，但**看不到 Boss 手牌**）。

---

## 一、设计目标：一个"会打"的玩家，不是一个脚本
| | 现贪心脚本 | 目标玩家 AI |
|---|---|---|
| 决策 | 固定优先级（天罡>最便宜部署>抽） | **搜索 + 局面评估**选最优动作 |
| 看局面 | 不看 | 看三路力量对比、连携潜力、源泉曲线、破家进度 |
| 田忌赛马 | 不会 | **会**（弃劣势路、压优势路、错位） |
| 连携 | 偶然形成 | **主动规划**（同点/同花成组再出） |
| 破家 | 三路平摊 | **集中一路凿穿**（认准最弱路） |
| 资源 | 见牌就出 | **管源泉曲线 + 续航轮换** |
| 天罡 | 一有就放 | **算收益最高回合再放** |

> 一句话：把"会玩这游戏的人脑子里那套盘算"写成代码。

## 二、决策架构（甲：建议这样实现·复杂度按 aiSkill 分级）
玩家 AI 每个回合从 4 类合法动作里（抽牌 / 部署一张[按 rank 花费] / 施放天罡 / 弃牌）选**一个**。建议**搜索 + 评估**而非 if-else 堆叠：

1. **枚举本回合所有合法动作**（每张手牌的部署到每条路 / 每张可施天罡 / 抽 / 弃）。
2. **对每个动作做 N 步前瞻**（turn-combat 是确定性 + 掷命有概率 → 用**期望值**：掷命用 logistic 胜率算 EV，不掷骰）。
   - N 随 `aiSkill` 爬（三档·详 §五）：**初级**=贪心(N=0·看哪空往哪放) → **中级**=N=1 + 评估(找弱路堆兵叠 buff) → **高级**=N=3~4 + 全规划层(拖延劣势路 + 精算胜率·argmax P(赢))。
3. **用局面评估函数 `evalState()` 给叶子局面打分**，回溯选**期望分最高**的动作。
4. **规划层（高 skill）**：在纯搜索之上叠**多回合计划**（如"这两回合先凑齐 7♠7♠7♥ 同点连携再一起压中路"）——搜索深度不够看不到的长线，由规划层兜。

> 关键：**掷命对决用期望胜率（EV）参与评估，不实际掷骰**——否则搜索分支爆炸 + 噪声大。clamp 后的 logistic 胜率就是分支权重。

## 三、局面评估函数 `evalState()`（高手"盘感"的量化·甲可调权重）
对一个战场局面打分（越高越接近赢）。建议线性加权这些特征：
1. **破家进度**：`Σ(敌家初始血 − 敌家当前血) × W_break` − `Σ(我家被破) × W_defend`（破家是唯一胜利条件·权重最高）。
2. **三路力量差**：每路 `我方前锋牌力 − 敌方前锋牌力`，但**非线性**——**一路压倒性优势**（能凿穿破家）比**三路都略优**值钱得多（鼓励集中，见 §四·1）。
3. **推进位置**：我方兵越靠近敌家槽位越值钱（`slot` 进度）；敌兵靠近我家则扣分。
4. **连携潜力**：手牌+场上**已成/将成的同点/同花组**给加分（鼓励攒连携，见 §四·2）。
5. **源泉/续航健康度**：当前源泉 + 手牌张数 + 牌库剩余的**有效续航**（别打空·见 §四·5）。
6. **主将安全**：我方主将（A）在场且未被针对 = 加分；暴露在敌强路 = 扣分。
7. **Boss 明牌威胁折算**：读 Boss 的 **3 明牌地煞 + 天罡 loadout**（这些是玩家合法可见的！）→ 预判它的机关/反击，提前在评估里折价（如已知它有 `battery` 周期炮 → 该路推进的兵打折）。

## 四、高手战术启发（评估函数 + 规划层共同实现的"打法"）
1. **田忌赛马 / 集中突破**（最重要）：算出敌**最弱的一路** → **集中兵力一路凿穿**破家；敌**最强的一路**用最小代价**拖住/放弃**（下等马对上等马）。**不三路平摊**——平摊是贪心脚本的病。
   - **典型：避开敌主将路**。敌主将（A）那一路通常最硬（关1 列奥尼达更是 `lastStandGeneral=3` 三命·啃不动）→ AI 应**识别并绕开主将路**、去打另两路破家（owner：「我们一般来说都会避开主将」）。`evalState` 的"三路力量差"对**敌方有主将/多命主将的路**自动折价 → 搜索天然偏向绕路·不必硬编码。
2. **连携规划**：主动攒**同点（对/三条）+ 同花**再成组出，连携加成 EV 高于零散出牌时，**宁可等一回合**凑齐。评估函数的"连携潜力"特征驱动这个。
3. **部署费用曲线管理**：rank 决定费用（2-4=0/5-7=1/8-10=2/JQKA=3）。前期多出**0/1 费铺场占路**、把**高费主将/A 留到关键路关键回合**一锤定音；别早早把 A 拍在无关路。
4. **掷命预报择战**：交战前用 logistic 胜率**预报**——**只在占优路主动迎战**，劣势路**让位/换路/不撞**（避免亏期望的对决）。留场续攻规则下，**赢了能留场续推**，所以"赢一次"价值放大 → 更要挑稳赢的架打。
5. **续航轮换 / 经济**：别把手牌一次打空。维持"手里有牌可应变"，按**源泉曲线**（前 6 源泉起手·每回合+1·后期+2）规划出牌节奏；预判 Boss 的 `stamina.drain`/`focus` 类地煞时**提前囤一手**。
6. **天罡择时**：把 5 张天罡当**关键牌**——算"这回合放 vs 留着放"的 EV 差，在**收益最高的回合**放（如对方将要凿穿、或我方一波能破家时）。不无脑开局清空。
7. **针对 Boss 明牌 counter**：赛前读 Boss 的明牌地煞/天罡 → **针对性组 loadout / 调整推进路线**（如 Boss 招牌是"中路周期炮" → 主攻**侧路**绕开）。这条把"玩家能 out-prepare"做实（对应 Boss AI 的 out-react·两边对称）。

## 五、三档玩家手感（owner 2026-06-23 定义 · `aiSkill` 三级 · design G 用它标 sim）
> owner 拍板：Player-AI 要**分初/中/高三级**，三级**不是同一算法调参数**，而是**质变的三种"玩家心智"**——一档比一档会想。对应 `aiSkill`：初=skill1 · 中=skill3 · 高=skill5（skill2/4 留作平滑插值）。

| 档 | 玩家心智（owner 原话） | 算法实现 | 用途 |
|---|---|---|---|
| **初级** | 「**看哪里有空就往哪派兵**」——贪心铺场·不算账 | **贪心**：枚举可部署 → 选**最空的路/最便宜的兵**·无前瞻·无评估（≈现老脚本） | 新手手感地板 |
| **中级** | 「**看哪一路弱，就往那路叠 buff 加成**」——会找软肋集中 | 贪心 + **`evalState` 单步评估**：识别**敌最弱路**·**集中兵力 + 天罡 buff 往那路堆**（集中破家雏形）·N=1 浅前瞻·会躲明显亏的对决 | 中手手感 |
| **高级** | 「**有策略**：发现哪路打不过 → 那路**用拖延战术**先拖住；**精心计算自己的胜算·不追求满血过关**·非常精巧」 | **搜索 + 全规划层**：N=3~4 前瞻 + 田忌赛马（劣势路**最小代价拖延/弃**）+ 连携规划 + 天罡择时 + **目标函数 = 最大化 P(赢)·不是最大化血量/战果** | **平衡基准**（定稿手感） |

### 5.1 高级档的"灵魂"= 优化胜率，不优化血量（owner 重点）
- owner：「**不是说一定要满血过关**，可能是非常精巧的算法。」→ 高级 AI 的**目标函数 = 最大化「这一局最终获胜的概率」**，**不是**最大化"我家剩几血 / 战果多漂亮"。
- 推论（高级独有的打法，初/中没有）：
  1. **算赢就敢亏**：只要推演出一条**净赢的路径**，它**愿意主动让出某些路 / 牺牲己家血 / 弃子**——只要总账 P(赢) 更高。满血通关不是目标，**通关**才是。
  2. **打不过的路 → 拖延而非死磕**：某路它**算出打不赢**（掷命预报长期亏）→ 不往里填兵硬拼，而是**用最小兵力/弱牌拖住**（迟滞敌前锋·换时间），把省下的资源砸到**算得赢的路**集中破家（田忌赛马的"下等马对上等马"）。
  3. **精算胜算**：交战/部署前，用 logistic 掷命胜率把**多回合后的破家概率**折算进 `evalState`，选 **argmax P(赢)** 的动作（搜索到叶子取期望·见 §二）。
- 工程落点：把 §三 `evalState` 在**高级档**接成**接近"赢/输"终局的胜率估计**（破家进度权重压倒一切·血量差只作次要特征）；初/中档用**更短视的启发**（中级看"哪路弱就堆"、初级看"哪空就放"），不做长程胜率推演。

### 5.2 标定用法
- sim 标关卡用 **高级档(skill5)** 当基准——"一个会算的人能赢多少"才是定稿手感。关1 目标 ~70% = 高级玩家 vs 修好的 Boss AI（关1 tier1·留破绽），靠 Boss 3 明牌地煞把对局压到 ~70%。
- **三档也都跑**：sim 应同时报 初/中/高 三条 WR（像现在报"新手/进阶/老手"那样）——用来验证"难度对不同水平玩家的坡度"（新手别太挫败、高手别太无脑）。
- 也可暴露给真人做**"推荐走法"提示**（同一引擎·高级档算最优动作高亮）。

## 六、与"数据驱动宣言"的关系（明确豁免·别误判为违宪）
- 宣言尺子是"最弱 LLM 能否产出同样数据"。玩家 AI **不是要产出的游戏数据**——它是**引擎侧的一个确定性决策器**（像 turn-combat 的掷命解算器一样属于"固定的解释器"）。owner 明确拍板它**单独开发、不数据驱动、写复杂**。
- 边界：它**只用合法可见信息**做**合法动作**的择优（不读 Boss 手牌、不改数值、不违规多动作）。它强在"算得深/盘得清"，不强在"开挂"。这点与 Boss AI 的信息不对称**互补但不同源**——Boss 靠多看（读你手牌），玩家靠多算（推演自己可见的局面）。

## 七、边界 / 验收
- **不偷信息**：玩家 AI 看不到 Boss 手牌/抽牌（只有 Boss AI 能反向偷看玩家——这是 owner 定的不对称）。
- **不违规**：只在合法动作集里择优；不凭空多动作/多兵/改胜率。
- **可分级**：skill1→5 必须单调变强（高 skill 在同局面下 EV 不低于低 skill）。
- **验收（design G 跑）**：① skill1 ≈ 老贪心脚本 WR（回归对照）；② skill5 在**纯镜像**（双方同牌·Boss AI 也修好到 ~50%）下应 ≈ 50%（证明两套 AI 旗鼓相当·公平底层成立）；③ 接 3 明牌地煞后能把 skill5 玩家标到各关 targetWR（关1 ~70%）。
```
现状（占位失真）: 贪心玩家 vs 菜 BossAI = 96%（双失真·不可信）
目标（两 AI 落地）: 高手玩家(skill5) vs 修好 BossAI + 3明牌地煞 = 关1 ~70%
```
