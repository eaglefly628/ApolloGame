# 英雄专属战术牌 · 天罡扩展（把战斗操作做到极致 · design G 2026-07-01）

> owner 2026-07-01：「**天罡应该扩展**、变得更丰富——是**战斗时能打出的卡**，**对牌使用、针对英雄使用**。这样这些卡就是**对某个英雄的专属牌组**，**收集这些牌组才有意义**。拿破仑 → 望远镜；亚历山大 → 成名物件 / 计谋智囊；孙子 → 孙子兵法（对单体使用）。整套设计还要重新来过，把**乐趣、竞争、体验做到极致**。」
> owner 补：「**这两条线在做，一个是我把战斗的操作做到极致。**」→ 本系统 = "战斗操作做到极致"这条线的核心载体。
> 本档 = 该方向的**结构提案 + 架构评判 + 例子 + 开放问题**（不是全 52 英雄的牌·那是下一步）。

## 一、北极星：让"战斗中的操作"成为爽点
现状：玩家能动性主要在**放牌前**（组牌/布阵）；两军相遇后基本看戏。掷战力骰（vision doc）已经把"临掷改命"打开了一道口子（方片×2/意大利×1.2）。**本系统把这道口子做成完整玩法**：战斗中**主动打专属战术牌**、针对具体英雄/具体一掷施加影响 → 每场对决都有"我要怎么操作"的决策。

## 二、架构评判（CORE RULE·先判该不该做、怎么做才不违宪）
- **该做**：这是真·体验缺口（战斗中无操作=看戏），不是现有能力能重组掉的。✅
- **不新增第 4 套牌**（YAGNI）：owner 明说"**扩展天罡**"，不是"再来一副"。→ **天罡长出子类型**，三副牌（扑克52/天罡/地支）结构不变：
  - **通用天罡**（现状·全军/主将 aura·常驻 loadout）
  - **英雄专属战术牌（新）**：单体定向·战斗中打出·绑定某英雄的招牌。
- **数据驱动过关**（最弱 LLM 能否产出同样数据？能）：每张 = `{hero, target, timing, effect:{op,value}}` 纯数据·复用**已有算子词汇**（改掷 mul/add·+战力·规则）——**不写英雄专属代码**、不建新引擎，靠通用解释器执行。这正是 vision §2.2 改掷层 + §8 #2「改掷牌从哪来」的答案。
- **一句话**：英雄专属牌 = **带定向 + 时机的改掷/加成数据**。引擎只多一个"选目标 + 在掷前窗口应用算子"的通用解释，零 per-hero 逻辑。

## 三、卡结构（数据·通用解释器执行）
```
HeroTacticCard {
  hero:   英雄 id（招牌归属·= 收集绑定）
  target: 'self-unit' | 'enemy-hero' | 'any-unit' | 'lane'   // 定向（单体为主）
  timing: 'preRoll'(掷前改命) | 'onDeploy' | 'clashWindow'    // 何时能打
  effect: { op: 'add'|'mul'|'rule', value }                   // 复用地煞/改掷同词汇
  cost / scarcity: 消耗·限张（防爆炸）
}
```
- **op 复用**（与 `disha-native-power-redesign.md` 四落点同源）：`add`(+战力/+掷)、`mul`(×战力/×掷·"战力%")、`rule`(先手/免疫/预读…)。
- **定向**是新维度：单体（对一张牌/一个英雄）。这就是 owner 说的"对牌使用、针对英雄使用"。

## 四、例子（illustrative·体现"招牌 → 数据"）
| 英雄 | 专属牌 | 招牌幻想 | 数据落点（示意） | target/timing |
|---|---|---|---|---|
| 拿破仑 | **望远镜** | 炮兵观瞄·料敌先机 | `preRoll`：本掷 `+3`（观瞄稳准）或 `rule:预览敌掷范围` | self-unit / preRoll |
| 亚历山大 | **成名物件·王之决断** | 伙伴骑兵一锤凿穿 | `mul ×1.5` 这一掷（爆发翻盘·受护栏）| self-unit / preRoll |
| 孙子 | **孙子兵法** | 庙算多者胜·知己知彼 | 对单体 `+战力` 或 `rule:平局判胜`（先手）| any-unit / clashWindow |
| 汉尼拔 | **坎尼合围** | 两翼包抄 | `rule`：敌前锋被夹时 `−掷` | enemy-hero / preRoll |
> 数值全部方向性·待 sim。**关键是结构统一**：不管多花哨的招牌，都落成 `{target, op, value}`——最弱 LLM 也能照着造新英雄的牌。

## 五、收集 / 竞争 / 体验（owner「做到极致」）
- **收集有意义**：每个英雄一套专属牌 → **凑齐某英雄的牌组 = 解锁一套打法**（拿破仑望远镜流/亚历山大爆发流…）。这就是 owner 说的"收集这些牌组的意义"。
- **竞争（PvP 就绪）**：各自掷各自的 + 各自的专属牌 → 天然是对称对局原子（vision §5）。专属牌暗/明公开度 = 心理博弈旋钮（vision §8 #3）。
- **体验/爽点**：战斗中"我这张望远镜留给哪一掷"= 每场对决的操作决策 → 战斗从看戏变博弈。

## 六、防数据爆炸红线（vision §2.3·本系统头号风险）
专属牌是**玩家侧 power**·最易失控。**一律过三关**（同 vision §2.3）：
1. **乘不叠**：一场对决乘算子至多 1 个（×1.5 与 ×1.2 不叠乘·取一）。
2. **每场限张**：一掷最多发动 N 张（建议 N=2）。
3. **掷后夹 CAP**：`rollFinal = clamp(applyMods, 1, ROLL_CAP=60)`。
4. **稀缺消耗**：专属牌是消耗品/有冷却·非常驻被动 → 天然限流。
> 复诵：**乘不叠·每场限张·掷后夹 CAP·稀缺**。任何新专属牌先过这三关·过不了回驳。

## 七、开放问题（enumerate·下一步逐个钉·先不做死）
1. **对谁用**：只 buff 自己的牌，还是也能 debuff 敌方英雄（counter），还是都行？（孙子兵法像 buff 自己·坎尼合围像 debuff 敌方——建议**都支持·由 target 字段区分**。）
2. **获取 & 绑定**：专属牌怎么拿？必须**拥有该英雄**才能用其专属牌，还是独立收集？（建议：拥有英雄→解锁其专属牌池·强化"收集英雄"主线。）
3. **占不占 loadout 位**：和通用天罡共享 ≤5 loadout，还是英雄专属牌单独一格？（影响组牌取舍。）
4. **操作窗口繁琐度**（vision §8 #1·owner 反感繁琐）：每场都弹"要不要发动"会不会累？→ 建议**只在关键路/玩家主动点**才开窗·或"预设自动发动策略"。
5. **单体 only 还是也有群体**：专属牌以单体为主（owner 原意），但要不要留极少数群体招牌？
6. **和地煞的对称**：Boss 的地煞 ≈ Boss 版"专属招牌"·玩家的英雄专属牌 ≈ 玩家版 → 两边同源（都 `{op,value}`）·可否统一成一张词汇表？（架构上建议统一·实装省事。）
