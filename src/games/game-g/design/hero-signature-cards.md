# 英雄专属战术牌 · 天罡扩展（把战斗操作做到极致 · design G 2026-07-01）

> owner 2026-07-01：「**天罡应该扩展**、变得更丰富——是**战斗时能打出的卡**，**对牌使用、针对英雄使用**。这样这些卡就是**对某个英雄的专属牌组**，**收集这些牌组才有意义**。拿破仑 → 望远镜；亚历山大 → 成名物件 / 计谋智囊；孙子 → 孙子兵法（对单体使用）。整套设计还要重新来过，把**乐趣、竞争、体验做到极致**。」
> owner 补：「**这两条线在做，一个是我把战斗的操作做到极致。**」→ 本系统 = "战斗操作做到极致"这条线的核心载体。
> 本档 = 该方向的**结构提案 + 架构评判 + 例子 + 开放问题**（不是全 52 英雄的牌·那是下一步）。

## 一、北极星：让"战斗中的操作"成为爽点
现状：玩家能动性主要在**放牌前**（组牌/布阵）；两军相遇后基本看戏。掷战力骰（vision doc）已经把"临掷改命"打开了一道口子（方片×2/意大利×1.2）。**本系统把这道口子做成完整玩法**：战斗中**主动打专属战术牌**、针对具体英雄/具体一掷施加影响 → 每场对决都有"我要怎么操作"的决策。

## 二、架构评判（CORE RULE·先判该不该做、怎么做才不违宪）
- **该做**：这是真·体验缺口（战斗中无操作=看戏），不是现有能力能重组掉的。✅
- **不新增第 4 套牌**（YAGNI）：owner 明说"**扩展天罡**"，不是"再来一副"。→ **天罡长出子类型**，三副牌（扑克52/天罡/地支）结构不变：
  - **通用天罡**（现状·全军/主将 aura·常驻 loadout）
  - **英雄专属战术牌（新）**：单体定向·战斗中打出·绑定某英雄的招牌。
- **数据驱动过关**（最弱 LLM 能否产出同样数据？能）：每张 = `{hero, target, timing, effect:{op,value}}` 纯数据·复用**已有算子词汇**（改掷 mul/add·+战力·规则）——**不写英雄专属代码**、不建新引擎，靠通用解释器执行。这正是 vision §2.2 改掷层 + §8 #2「改掷牌从哪来」的答案。
- **一句话**：英雄专属牌 = **带定向 + 时机的改掷/加成数据**。引擎只多一个"选目标 + 在掷前窗口应用算子"的通用解释，零 per-hero 逻辑。

## 三、卡结构（数据·通用解释器执行）
```
HeroTacticCard {
  hero:   英雄 id（招牌归属·= 收集绑定）
  target: 'self-unit' | 'enemy-hero' | 'any-unit' | 'lane'   // 定向（单体为主）
  timing: 'preRoll'(掷前改命) | 'onDeploy' | 'clashWindow'    // 何时能打
  effect: { op: 'add'|'mul'|'rule', value }                   // 复用地煞/改掷同词汇
  cost / scarcity: 消耗·限张（防爆炸）
}
```
- **op 复用**（与 `disha-native-power-redesign.md` 四落点同源）：`add`(+战力/+掷)、`mul`(×战力/×掷·"战力%")、`rule`(先手/免疫/预读…)。
- **定向**是新维度：单体（对一张牌/一个英雄）。这就是 owner 说的"对牌使用、针对英雄使用"。

## 四、例子（illustrative·体现"招牌 → 数据"）
| 英雄 | 专属牌 | 招牌幻想 | 数据落点（示意） | target/timing |
|---|---|---|---|---|
| 拿破仑 | **望远镜** | 炮兵观瞄·料敌先机 | `preRoll`：本掷 `+3`（观瞄稳准）或 `rule:预览敌掷范围` | self-unit / preRoll |
| 亚历山大 | **成名物件·王之决断** | 伙伴骑兵一锤凿穿 | `mul ×1.5` 这一掷（爆发翻盘·受护栏）| self-unit / preRoll |
| 孙子 | **孙子兵法** | 庙算多者胜·知己知彼 | 对单体 `+战力` 或 `rule:平局判胜`（先手）| any-unit / clashWindow |
| 汉尼拔 | **坎尼合围** | 两翼包抄 | `rule`：敌前锋被夹时 `−掷` | enemy-hero / preRoll |
> 数值全部方向性·待 sim。**关键是结构统一**：不管多花哨的招牌，都落成 `{target, op, value}`——最弱 LLM 也能照着造新英雄的牌。

## 五、收集 / 竞争 / 体验（owner「做到极致」）
- **收集有意义**：每个英雄一套专属牌 → **凑齐某英雄的牌组 = 解锁一套打法**（拿破仑望远镜流/亚历山大爆发流…）。这就是 owner 说的"收集这些牌组的意义"。
- **竞争（PvP 就绪）**：各自掷各自的 + 各自的专属牌 → 天然是对称对局原子（vision §5）。专属牌暗/明公开度 = 心理博弈旋钮（vision §8 #3）。
- **体验/爽点**：战斗中"我这张望远镜留给哪一掷"= 每场对决的操作决策 → 战斗从看戏变博弈。

## 五·五、⭐ 操作模型（owner 2026-07-01 拍板 · 自走棋式 · 掷时不加操作）
> **这是本系统最关键的一条·修订 vision §2.2 的"每场掷前窗口"**。owner：「**不能每次掷骰都让我选发动什么**·太繁琐。真正战斗时就像**自走棋**·那一刻没法再追加。我只在**自己的回合**里确定操作。**但掷骰要有仪式感**——看到我掷多少、他掷多少、我要亲手掷一下。挂上 buff 之后·**极少数**牌有机会在掷后改变（如重掷）·这种要**设计得很少**。」

**三段式（谁在什么时候做什么）**：
1. **你的回合（唯一的决策点）**：像放牌/打天罡一样，把专属牌/改掷算子**预挂到某张兵/某条路**（`add/mul/rule`）。**所有战术选择都在这里做完**。
2. **战斗结算（自走棋·零选择）**：两军相遇 → **自动**应用已挂算子 → 双方各掷 `[1,战力]` → 比大小。**掷的那一刻不弹任何选择框**。
3. **仪式感（演出·非操作）**：对决特写里**两颗骰同屏亲手掷**（我橙敌蓝）→ 看双方掷值 → 揭晓。**有仪式感、无决策**——爽在"看命运翻盘"，不在"又要点一次"。

**掷后改变 = 极少数·刻意稀有**：
- 只有**很少**的招牌能在掷出后再改结果（owner 点名例：**重掷/重置一次**）。
- **首选做成"预挂式自动触发"**（回合内挂上"若此掷落败·自动重掷 1 次"→ 掷时无需点）→ 仍零掷时操作。
- 若真要一个掷后交互点·**全局仅留这一类·极稀有**（不破坏"自走棋无追加"的主基调）。

> **对引擎的含义（关键·省一大坨繁琐 UI）**：改掷层**不需要"每场对决的交互窗口"**。算子在**玩家回合**就挂到 unit（像 `castIds` 那样记在兵/路上）·`resolveClash` 掷时**自动读取应用**·只播掷骰演出。**这也一并解决 vision §8 #1（繁琐）**。

## 六、专属牌的"数量上限 + 弊端"（owner 2026-07-01·防信息过载 & 防纯 upside）
- **数量上限（必须有）**：owner「得限制数量·不然玩家信息量太大」。专属牌是**英雄自带**（拥有英雄→带其牌）→ 但要**显式封顶**在场/一 run 可用的专属牌数（建议随养成小步解锁·别一上来一堆）。design G 用 sim + 可玩性定上限。
- **弊端（必须有·非纯增益）**：owner「它也应该有一些弊端」。候选弊端（择一/组合）：
  - **消耗/冷却**：一次性或长 CD·用了就没（稀缺）。
  - **源泉花费**：挂它要花召唤源泉·与部署/天罡抢资源。
  - **风险对赌**：如 `×2 掷` 但**输了这掷则该兵永久退场/额外扣血**（高风险高回报）。
  - **占手/占位**：挤占抽牌/手牌上限。
- **设计量自觉（owner 提醒）**：52 英雄×专属牌 = **设计量很大** → **先做关1-10 涉及英雄·各 1-2 张**·验证乐趣再铺量（见 §八）。

## 七、防数据爆炸红线（vision §2.3·本系统头号风险）
专属牌是**玩家侧 power**·最易失控。**一律过三关**（同 vision §2.3）：
1. **乘不叠**：一场对决乘算子至多 1 个（×1.5 与 ×1.2 不叠乘·取一）。
2. **每场限张**：一掷最多发动 N 张（建议 N=2）。
3. **掷后夹 CAP**：`rollFinal = clamp(applyMods, 1, ROLL_CAP=60)`。
4. **稀缺消耗**：专属牌是消耗品/有冷却·非常驻被动 → 天然限流。
> 复诵：**乘不叠·每场限张·掷后夹 CAP·稀缺**。任何新专属牌先过这三关·过不了回驳。

## 八、决策（owner 2026-07-01 拍板·已收敛）
1. ✅ **对谁用 = buff 自己 + debuff 敌方英雄·都支持**（由 `target` 字段区分）。
2. ✅ **必须拥有该英雄**才有其专属牌——专属牌是**英雄自带**（"你有这个英雄才有他的牌"）·强化收集英雄主线。
3. ✅ **不占天罡 loadout**（天罡=全体用·专属牌=英雄自带·各走各的）；**必须有弊端**（见 §六）。
4. ✅ **操作模型 = 自走棋·掷时零选择·回合内预挂·掷骰有仪式感·掷后改变极稀有**（见 §五·五）。
5. ✅ **每英雄专属牌上限 = 3 张**（owner 2026-07-01）。**渐进解锁**：拥有英雄先给 1 张起始牌·其余 2 张**通关 N 关后才解**（有些**非常难解锁**）。→ 渐进解锁也是**平衡的朋友**：早期可用牌少·杠杆少·好调；复杂度随进度慢慢加（正面回应 owner「数值很难专注平衡」）。
6. ✅ **单体 only·不留群体特殊牌**（owner「不用再留少数特殊的了」）——专属牌一律单体定向·砍掉群体例外·简化设计与信息量。
7. ✅ **专属牌 vs 地煞：引擎统一·概念分开**（owner 担心"混在一起不清晰"·合理）——**底层共用一个 `{target,op,value}` 解释器**（甲实装一次·省事）；但**玩家面前两个概念各自清晰**：`地煞`=Boss 招牌（Boss-only）· `专属牌`=玩家英雄自带。数据文件/UI 分开命名·只是编译到同一套算子。（同 天罡 vs 地煞 已有的"同构不同名"模式。）

## 八·五、起始英雄 + 起始专属牌（关1 教学 · design G 提案）
> owner：「牌组组合变得很重要·一开始要有个**送英雄的角色**·初始英雄给一张**起始专属英雄卡**·作为第一关的教学。」
- **提案·初始英雄 = 斯巴达克斯（4♠·#41·角斗士之王）**。理由：①**名气**大（owner 铁律必留款）；②**角斗士挣脱枷锁的翻身**幻想 = 本作「翻命」主题的化身（从奴隶翻命 = 教学的情感钩子）；③非 Boss（可当玩家收集英雄）；④底层强度中庸·适合当教学基准。
- **起始专属牌 =「角斗士之怒」**（教学款·结构最简·教会"挂牌→自动生效"这一个动作）：
  - `{ hero:斯巴达克斯, target:'self-unit', timing:'preRoll(回合内预挂)', effect:{op:'add', value:+3} }`——回合内挂到斯巴达克斯（或任一友军前锋）·这一场掷战力骰 **+3**（挣脱枷锁·奋起一击）。
  - **弊端（教学款·极轻）**：一次性消耗·每场战斗只 1 张（用完本场没有）→ 温柔地教"专属牌是稀缺资源"。
  - **关1 教学用法**：教程弹「这是你的英雄斯巴达克斯·把他的『角斗士之怒』挂上去 → 看他这一掷 +3 赢下遭遇」。一张牌·一个动作·把整套专属牌系统的心智一次讲清。
- 其余 2 张斯巴达克斯专属牌（藤蔓夜袭/奴隶怒涌/困兽反扑 里选·见 `23-hero-codex §五`）= 渐进解锁款·通关后解。
