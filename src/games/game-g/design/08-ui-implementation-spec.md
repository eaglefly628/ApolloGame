## 一、⭐ 核心裁决（动手前必须先定）：MOBA 三路战场 如何接进 outcome-first

**冲突点**：UI 把对战画成 **MOBA 实时推进**（卡牌沿路走、接敌触发掷命、推塔、占老家、大世界相机）。但正典 `00` 是 **outcome-first**（胜负先由规则定、表现反推、不回灌），且 v0.1 的"RTS 寻路→接触掷命 + 物理"**已被 owner 回退**（见 `05` §演进史）。**直接做实时连续物理 = 重蹈覆辙**（跨端浮点债 + 违反 outcome-first）。

**裁决（推荐·已据此写下文）**：**保留 MOBA 观感，但底层=确定性离散，不引入连续物理。**

| 层 | 做法 | 性质 |
|---|---|---|
| **推进/走位** | 卡牌在路上的位置 = **整数格推进**（每拍 +1 格，仿 gameF `HexPos` 整数移动），确定性、可 lockstep | 离散 sim（进 hash）|
| **接敌掷命** | 两卡进到同格 → 触发 `decideFaceUp(favor,seed)` 定生死（`01`）| 规则胜负（进 hash）|
| **老家血/推塔** | 整数资源 `Resource`，掷命结果累加扣减 | 离散 sim（进 hash）|
| **3D 翻牌/相机/小地图/滞空/转速** | 纯表现（ThreeRenderer），各端各演不影响结果 | 表现（不进 hash）|

> 结论：**owner 要的 MOBA 战场视觉全保留**；我们只把"推进"做成**整数格离散**（不是连续物理），"胜负"仍是 `decideFaceUp` 规则——**完全 outcome-first、确定性、多人安全**。这也是 `06`「三路同时开战」的自然空间化。
> **替代方案（不推荐）**：真做实时连续 RTS 物理 → 重开跨端浮点债 + 违 outcome-first + 撞已回退的 v0.1。**若 owner 坚持，须先立 REQ-G 确定性探针，按 `04` 评估**。

## 二、GameShell vs canvas 分工（program G 照此分层）

| UI 区域 | 落地 | 理由 |
|---|---|---|
| 大厅 5 屏（顶栏/tabs/面板/列表/按钮/货架/天梯榜）| **GameShell**（`@ui/shell` UILayout：col/row/panel/tabs/text/stat/bar/button/image）| 布局即数据，gameF 去腐已证 |
| 三路战场 **世界**（三路/卡牌/老家/哨塔/捷径门/相机/小地图）| **canvas（ThreeRenderer，已有）** | 3D 世界 = 渲染后端解释 render 数据（`03`）|
| 战场 **叠层 HUD**（左栏干预卡/右栏三路战况/顶部目标/底部选路派牌）| **GameShell 2D overlay**（盖在 3D canvas 上，`03` §四已许）| HUD=数据；与 3D 共存 |
| 选路派牌（拖牌到某路）/ 点「门」开合 / 卡牌选中 | **canvas 交互**（drag-place 能力，gameF 有）+ 信号 | 空间操作走 canvas，不归 GameShell |

## 三、逐屏实装规格

### 3.1 大厅（GameShell · 5 tabs）

| 屏 | 组件 | 数据/能力（先复用）|
|---|---|---|
| 顶栏 | 头像/主牌/段位、皮肤切换(玄铁/锦霞)、货币(🪙金/◈干预能量/💎钻)、⚙ | `image`+`stat`+`button`；皮肤=GameTheme 数据换皮（gameF sanguo 同款）|
| **大厅** | 命运牌桌、赛季横幅、主 CTA「天梯掷命 1v1」、好友切磋、**单人·AI庄家**、出战牌组/每日箱/上新角标、牌友栏 | `panel`+`button`(→signal)；红点=flag |
| **牌组** | 我的牌组(每副 N 张·**花色配重**)、流派筛选、卡位预览、`核心:{{d.key}}`、[改造][设为出战] | `card-pile.deck` 数据 + 列表渲染；配重=favor 分布(`07`) |
| **收藏** | 花色/点数/稀有度筛选、搜索、卡详情(效果/改造/拥有数)、[分解][加入牌组] | 账号收藏=服务层(非 ECS，`02`)；卡效果=`07` 融合数据 |
| **改造坊** | 改造台(熔铸:消材料镶字/配重)+ 庄家货架(买/刷新🪙2/锁定)、集材/任务 | `craft-recipe`+banded 经济(`02`/`07`)；NPC 庄家=数据 |
| **天梯** | 段位/LP、近10局(胜率/连胜/**翻正率**)、天梯榜、好友邀战 | 服务层(`04`)；榜单=mock→真服务 |

> **改进①**：大厅缺一个显式 **开局布阵/分兵屏**（`06` 的"田忌赛马"深度）。建议在「设为出战 → 进对战」之间插一步**布阵**（把 54 张分到上/中/下三路 + 路内站位），或并入对战的备战相位。见 §四改进 5。

### 3.2 三路战场（canvas 世界 + GameShell HUD）

**世界（ThreeRenderer 画，整数离散 sim）**：
- 左右**老家·牌王座**（♔）：`Resource{home_hp}`，"占领敌方老家=即胜"=胜负转移读它。
- **三路**：上路(弧)/中路(直)/下路(弧)；每路一条**整数推进轨**（格序列）。卡牌带 `lane + track_pos`(整数)。
- **哨塔**：路上的中继 `Resource{tower_hp}`，掷命推进打掉(推塔5 = 5 座？数据)。
- **捷径门**：上↔中、中↔下各一道，`Flag{gate_open}`，点击翻转(绿通/红封)→ 改寻路可走格。
- **相机/小地图**：缩放(55%↔260%)/拖拽/快速聚焦(老家/团战/敌家/全局)=**纯表现**（相机绝不进 hash、不读 sim 真相外的东西）。

**HUD（GameShell 叠层）**：
- 左栏 **干预卡·Levers**：每张 `⚡cost`（◈干预能量），点击=出功能牌信号(`07`/`01` 干预)。
- 右栏 **三路战况**：每路存活/推进/战局（`group-count` 按 lane tag + home/tower hp 投影）。
- 顶部 **当前对手**(红桃皇后·蓝方·火攻流) + 目标(占老家即胜)。
- 底部 **选路派牌**：拖牌到某路 → `track_pos=0` 入轨推进（drag-place + 信号）。
- **台面机关**（🌪河道·低重力"过河滞空更久"）：见 §四改进 4——**须落成 favor/规则修正或纯表现，不做物理**。

**战斗流（接 `01`+`06`，整数离散）**：
```
派牌入路(track_pos=0) → 每拍沿轨 +1 推进(确定性) → 双方同格接敌
  → decideFaceUp(favor,seed) 掷命(正面活续推/反面死移除) → 3D 翻牌演出(表现)
  → 将领牵动(06:队长活→队 +favor / 阵亡→hierarchy-cascade 溃散)
  → 打哨塔/老家 hp → home_hp≤0 一方 → 胜负(占老家即胜)
```

## 四、改进点清单（架构师评审 · 带裁决）

| # | 改进 | 裁决 / 做法 |
|---|---|---|
| 1 | **战斗模型连贯**（最重要）| 见 §一：MOBA 观感 + 整数离散底层，**不做连续物理**（守 outcome-first + 确定性，避开已回退的 v0.1）|
| 2 | **三三制/将领的"灵魂"在 UI 不可见** | 战场只画了路/卡/塔/老家，没体现 `06` 的**军衔(点数)/小队-中队-大队长指挥树/将领牵动溃散**。**加**：卡牌按点数显军衔角标；队列凝聚/将领存活指示；"擒贼先擒王"连锁溃散的演出反馈。否则游戏核心深度玩家看不到 |
| 3 | **牌数 52 vs 54 + 王/joker 定位** | 大厅写"每组52张"，但 `06` 是 **54(52+2王)·王=大队长**；战场 ♔=老家牌王座、🃏=干预牌库。**须 owner 定**：王是「大队长名将位」还是「干预牌」？我建议 **54·王=大队长**（与 `06` 一致），干预卡另用功能牌池 |
| 4 | **干预/台面机关的语义** | 必须**改 favor/规则输入**（outcome-first），不是"改物理量"(早期版旧框架)。🌪低重力滞空 = **要么纯表现、要么落成 favor 修正**(如"过河该路 +favor")，**不做真物理影响胜负** |
| 5 | **缺开局布阵/分兵** | `06` 的"把 54 张分三路"是第一层战术(田忌赛马)。**加**一个布阵步骤(大厅出战前 或 对战备战相位)：分兵到上/中/下 + 路内站位 = 纯数据布局表 |
| 6 | **vs AI 优先的相位** | UI 把"天梯1v1/真人"放很显眼；MVP=vs AI。**当前对手**首发=AI(数据配置军队+出牌策略)；真人/天梯走 `04` 后置。纯数据相位差异 |
| 7 | **皮肤/美术** | 玄铁/锦霞双皮 = GameTheme 数据换皮(gameF 已证)；牌面/立绘=占位，走 R9 资产清单硬校验(防编造 key)，待美术替换 |

## 五、数据驱动落地 + 验收（守宪法尺子）

- **大厅** = 一份 `GAME_G_LOBBY_UI: UILayout` 数据 + GameShell；tabs/面板/按钮→信号、绑定→resourceId。**零手写 React 壳**（照 gameF GAME_F_UI）。
- **战场世界** = render-only 数据（卡牌/老家/塔/门的 `Transform`+`Card3D`+`Resource`）交 ThreeRenderer；**整数 sim 进 hash、3D/相机不进**。
- **战斗规则** = `decideFaceUp` + `group-count` + banded `event-when`/`effect`（全现成）。
- **验收**：① 同 seed 同布阵 → 逐拍 `world.hash()` 一致（确定性，相机/3D 不破坏它）；② 大厅 5 屏 GameShell 数据可走查；③ 一局 vs AI 闭环(派牌→推进→掷命→将领牵动→推老家→分胜负→掉材)；④ tsc+vitest+build 全绿。
