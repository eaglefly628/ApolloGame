# 02 · 局外 · 元循环（集材 / 改造 / 商城 / 出征）

> 承 `00` §三核心循环的局外半边。形态 ≈ gameF 大厅 + gameE 收藏，**全部数据 + 服务层边界清晰**。

---

## 一、元循环（养成动力）

```
局内攻克(掷命对决) ──产出── 素材(mats)
        │
        ▼
   改造牌组(craft：升 favor / 换皮) ──► 更高 favor = 下一局更易活、流派更鲜明
        │
        ▼
   商城(NPC 庄家：买卖卡 / 素材) ──► 加速构筑
        │
        ▼
   选阵出征(选牌组 / 选关卡) ──► 再战，更深
```

- **核心钩子**：favor 是"持久强度"的载体——局内掷命公平（5%/95% 边界保翻盘），局外构筑决定**基准胜率倾向**。强度可成长，但**永不必然**（封顶 95%）。

---

## 二、改造 craft（升 favor / 换皮）

- **升 favor**：消素材提高某牌的 favor（0..100）→ 提高它的存活概率。数据：`craft-recipe`（消耗素材）+ `effect`（写 favor 资源）。
- **换皮**：换牌的表现外观（`Card3D.frontTint/backTint` 等 render 数据），**不影响 favor / 胜负**——纯表现收集欲。
- 全部 = **现成 `card-pile` + `craft-recipe` + banded 经济**（gameF/gameE 已证），零新能力。

---

## 三、商城 + 经济

- **MVP = NPC 庄家店**：买/卖卡、买素材；价格表 = banded 数据。
- **局内经济**：结算掉材 = banded `event-when`→`effect`（gameE/gameF 同形）。
- **货币/素材** = `Resource`，改造/购买 = `craft-recipe` 原子扣费。

---

## 四、牌组构建 / 羁绊（Phase-3）

- **牌组构建**：从收藏拼一副出战牌组（选哪些牌 + 各自 favor）。= `card-pile.deck` 数据 + 局外选择。
- **羁绊（可选）**：同花色/同点数/牌型成套 → 集体 favor 加成。= `group-count`（数成套）→ 写全局 favor buff（守 gameF「全局 stat + 能力读全局」重组纪律，**不逐张 fan-out**）。届时按真实拉动评审，YAGNI 不预先做。

---

## 五、服务层边界（架构红线）

```
   确定性 ECS(引擎)              │   服务 · 账号 · 账本层(后置)
   ─────────────────────────────┼──────────────────────────────
   一局掷命 sim / 局内经济        │   收藏 / 牌组库存
   消费:出战牌组数据(输入)       │   天梯 / 解锁
                                 │   交易市场 / 挂单 / 成交(R-2)
   ──────────────────────────────────────────────────────────
   单向:服务层 →(出战牌组数据)→ 喂引擎一局;引擎不反向依赖服务层
```

- **R-2 回驳记账**：**玩家间 P2P 交易 = 后端市场服务**（撮合/账本/反作弊），不是游戏数据/capability。**MVP 只做 NPC 庄家**；真 P2P 市场 = 未来 `services/net` 基建，与确定性引擎解耦。
- 与宪法一致：收藏/天梯/市场都不是"一局游戏的数据"，是元层基础设施，**不污染确定性边界**。
