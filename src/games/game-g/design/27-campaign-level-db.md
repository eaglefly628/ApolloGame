## 一、关卡数据 schema（一关一条 · 主程读）
```
Level {
  id:        1..52,                       // 关序(= 难度序·关1最易→关52孙武终章)
  heroId:    string,                      // 对应英雄(doc23 §三 rank)
  battle:    { name, oneLine },           // 战役名+一句(doc23 §七)
  intro:     string,                      // 战役背景介绍(开场旁白·本doc §五)
  bossLines: { open[], mid[], lose[] },   // Boss 对白(开场/劣势/败北·本doc §五)
  boss: {
    homeHp:   number,                     // 大本营血(难度档·§四)
    pokerDeck:[cardId×16],                // ⭐ Boss 16 张扑克牌组·**写死在关卡配置**(owner 2026-06-21·与玩家 16 对称·authored/确定·可仿真)
    tiangang: [tiangangId≤5] | {pool:"all36"|ids[],pick:5,seed},  // ⭐ Boss 5 天罡·**可写死 或 定义随机给 5 组**(owner 2026-06-21·改自旧 12 随机)
    disha:    [dishaId×3],                // 3 专属地煞(doc23 §八/§九)
    dishaScale:number,                    // ⭐ 地煞加成系数·**由 sim 标定**(§三·调到 targetWR·非手填)
    aiTier:   number,                     // AI 智能档(§四·难度)
    aiProfile:{aggression,lanePref,spellEager,targetPref,risk,economy},  // Boss 策略画像(§八·数据·调通用AI)
  },
  reward:    { unlock:[tiangangId×4], gold:number },  // 解锁+金币(doc25)
  loadoutCap: 2..5,                       // 玩家本关 天罡 loadout 上限(§四)
  targetWR:  number,                      // 基准牌组 sim 目标胜率(§四·**地煞 sim 标定的目标**)
}
```
> 全字段可选缺省·缺则用难度档默认。引擎按 `id` 逐关加载。**Boss `pokerDeck` 16 张写死**（关1-5 手挑贴 Boss 风格·关6-52 可先用 `seed` 确定性铺一副、再逐期手调）；`tiangang` 写死或带 `seed` 随机 5；`dishaScale` 由 §三 sim 标定回填。

## 三、Boss 牌组配置 + 地煞 sim 标定（owner 2026-06-21 · 策划=调数值）
### 3.1 Boss 出战牌组（与玩家 16+5 对称）
- **16 扑克·写死**：`boss.pokerDeck = [cardId×16]` 直接写在关卡配置里（authored·确定·可仿真）。**关1-5 手挑贴 Boss 风格**（守势 Boss 多低点铺场 / 突击 Boss 多高点尖兵 + 同花/同点线）；**关6-52** 可先 `seed=关id` 确定性铺一副、逐期手调。
- **5 天罡·可随机**：`boss.tiangang` = 写死 5 张 或 `{pool, pick:5, seed}` 随机给 5（贴 Boss 流派权重·缺省纯随机）。**改自旧 12 随机**（与玩家 loadout≤5 对称）。
- **3 地煞**：`boss.disha`（doc23 §八/§九）= Boss 招牌战术·非对称难度来源。

### 3.2 地煞加成 = sim 标定到 targetWR（核心·策划主调）
> owner：地煞给多少加成，**不手拍**——跑 sim 测胜率、不断调到该关 `targetWR`。
- **标定量 = `boss.dishaScale`**（地煞加成全局系数·乘在 disha-pack 的 base 数值上）。disha-pack 的 winPct/power 等 = **起点 base**；最终强度 = `base × dishaScale`。
- **标定循环（对每关）**：① 构「**该关玩家真实强度基线牌组**」(见 3.3) ② sim 跑 N 局（基线玩家 vs Boss[16+5+disha×dishaScale]）→ 实测 WR ③ 二分调 `dishaScale`（WR 高于目标→调大加成、低于→调小）④ 收敛到 `|WR − targetWR| < ε` → 回填 `dishaScale`。
- targetWR 见 §四（早关 ~80% → 终章 ~40%）。

### 3.3 ⭐ 玩家该关真实强度基线（标定的"对照玩家"·策划定）
> 关键：Boss 牌力要**对着玩家在这一关真实能有的强度**调，不是对空气。基线 = 该关玩家**合理拥有**的：
- **地支镶嵌加成**：开局送子丑寅卯(铜)；按 doc25 揉/合成节奏，关N 估 player 有 ~`min(12, 4+关数×?)` 生肖、部分升银/金 + 少量三合/六合连携 → 折成基线牌的 favor/buff。
- **天罡解锁 + 配合**：天罡按 9关×4 解锁（关N 已解锁 ~`min(36, 4×已通关数)` 张）→ 基线带其中**贴流派的 ≤5 张**（不是乱配·按一个能成型的流派 build·体现"天罡配合"）。
- **扑克养成**：基线 16 扑克 = 一副「一键自动构筑」式均衡曲线 + 已养成 favor。
- **基线分档**（策划给·sim 用）：新手区(关1-5)=弱基线(少地支/2-3天罡)；中期(关6-30)=中基线；终章=满养成强基线。**每关 sim 对照各自基线**，dishaScale 调到 targetWR。

> **派甲**：① 真缺口=**sim harness**（自动双方 AI 跑 turn-combat 到底 × N seed → WR·见 §六派单/REQ）；② level loader 读 `pokerDeck(16)+tiangang(≤5)+dishaScale`；③ 标定脚本：扫 dishaScale 收敛 targetWR、回填关卡配置。**策划(design G)出基线模型 + Boss 牌组草案 + 复核 sim 结果调参。**

### 3.4 ⭐ sim 实测（design G 2026-06-21 · 跑 simulate-balance.ts·N=500）：**标定被结构性问题阻塞**
> owner 让我「调 Boss 牌力到 targetWR」。我把 sim 接到 mainbranch、按 owner 要求**计入玩家地支附魔 + 天罡 loadout + 放牌按点数收费**后实跑——**结论：关1 通关率恒 ~100%，且对一切 Boss 数值旋钮免疫。数值标定现在做不了，根因是战斗结构，不是数字。** 证据（全 N=300~500）：

| 实验 | 通关率 |
|---|---|
| 新手 deckBias=3 完整装备（虎符+旗手+5铜地支） | ~99.6% |
| 裸装 vs +天罡 vs +地支 vs +全部（消融） | **全 ~99.6%·无差** |
| Boss favorBias −6 / 0 / +6 / +12（牌力扫描） | **全 ~100%** |
| Boss 改激进 AI(aggression9) + 家血 4 / 6 | **全 100%** |

**根因（读 turn-combat.ts·结构性·非数值）**：
1. **掷命后胜者立即「光荣回牌库」离场**（`resolveClash` L345-353·owner 2026-06-21 改「替原续航−1退场」）→ **每次遭遇双方前锋都清空**（败者亡 + 胜者回库）→ **任何一路都守不住**：再强的防守牌赢了也走人，下一格立刻空出来。
2. **空路 = 白送 chip**（`advanceColumnToBase` L368-383）：某路只有你的兵、对面该路空 → 直接行军破家 −1 血，**不经掷命**。
3. **Boss 铺场吞吐 < 玩家**（贪心玩家每回合按点数狂铺最便宜兵铺满三路；Boss utility AI 还要权衡抽/施法）→ Boss **覆盖不全三路** → 玩家总有一条空路走进去破家。
4. 合流 → **胜负由"谁占的路多/谁先到家"决定，牌力(favor/地支/天罡)几乎不参与** → 整套掷命对决/养成/天罡体系在当前模型下**对胜负近乎无效**。源泉还会堆到 20+ 没处花（瓶颈是手牌不是源泉）→ **「按点数收费」这条低牌价值经济杠杆当前咬不动**。

**裁决（design G 上报 → owner 2026-06-21 拍板：胜者「概率留守」模型）**：
- 数值标定（dishaScale / Boss favorBias / targetWR 收敛）**暂挂起**——在结构修好前任何标定都是噪声。
- **owner 定夺**（不擅改 owner 6-21「胜者回库」决定·上报后定）：**胜者不再必定回库——掷一枚确定性硬币：正面(概率 P·默认0.5)→回库(奖励·保留)、反面→留格把守(防守成立)；stamina 兜底防站桩；「死战不退/督战」类天罡/地煞把币压成"永不主动回库"。** 完整契约见 `doc24 §4.2`（已派甲）。
- **必须同时**：甲按 §六 把 **16写死 pokerDeck + ≤5 tiangang + dishaScale** 接进 loader/sim（当前仍跑旧 54张+favorBias+12随机天罡 模型）→ 否则即便结构修好，标定的也不是真 Boss。
- 两者落地后，design G 重跑 sim、按 §3.2 循环扫 **P + dishaScale** 把各关 WR 收敛到 §四 targetWR。

> sim 增强（design G 已做·本次提交）：`simulate-balance.ts` 已计入 **玩家天罡 loadout（按 loadoutCap 取关1解锁的虎符/旗手…）+ 地支附魔 favor（核心英雄叠 favor·新手≈5铜=+20）+ 放牌按点数 deployCost**，并加 `bossDelta` 牌力扫描旋钮 + 地支/天罡消融实验。结构修好后即可直接复用标定。

### 3.5 ⭐ 每 Boss = 一个招牌「被动」(地煞) + 前五关标定草案（owner 2026-06-21 · design G 原型实测）
> **owner 拍板**：**每个 Boss 有一个自己的被动属性 = 它的招牌地煞**；**轮到它掷命时，全屏亮「XX 被动发作」**（=已登记的 `REQ-G-战斗逻辑批次·敌用地煞全屏通知`）。难度=被动强度，逐关加码。**留场率(§4.2 stayPMul)是被动的一种**；后期还可叠**新被动「诅咒」**（见下）。
> **前五关目标通关率（owner 锁定·"压到"）**：**关1=98% · 关2=87% · 关3=75% · 关4=70% · 关5=65%**（递降=难度爬升）。

**design G 原型实测（临时 patch 留场机制·已撤·N=240·玩家按 §3.3 逐关递进养成）→ 每关该挂的被动 + 标定**：

| 关 | Boss·招牌被动 | 实测可达档（守将留场P / bossDelta） | 命中目标？ | design G 调法 |
|---|---|---|---|---|
| 1 列奥尼达 | 温泉关死守（家厚）+ 主将死战不退（留场P=1·**仅主将**）+ 斯巴达方阵 | P0.5/Δ0 → **96%**（再 Δ−6 ≈ 98%） | 接近·略调轻 | 死战不退**只作用主将**·disha base 取小 → 98% |
| 2 亚历山大 | 伙伴骑兵突击（留场P=0.75·乘胜追击）+ 锤砧 | **P0.75/Δ0 → 87%** | ✅ 正中 | 守将留场 0.75·Δ0 |
| 3 曹操 | 连环船 + 兵海（swarm） | P0.5/Δ0 → **仅 40%**（其余更低） | ❌ **远超目标·过难** | **dishaScale↓（兵海/连环减半）+ Δ 负** 才回 75% |
| 4 拿破仑 | 大炮兵（battery·周期轰路）+ 近卫 | P0.5/Δ0 → **仅 26%** | ❌ **远超目标·过难** | **dishaScale↓（大炮减频/减伤）** 才回 70% |
| 5 项羽 | 破釜沉舟（全军留场P→1·莽一波）+ 九战九捷 + **诅咒** | P0.75/Δ24 → **64%**·P1.0/Δ18 → 67% | ✅ 贴 65% | 守将留场 ~0.85 + Δ~20 |

**design G 关键发现 + 评判（CORE RULE·不照单全收）**：
- **关3/关4 当前已"过难"**（实测 40%/26% ≪ 目标 75%/70%），**不需要再加被动/诅咒——反而要把现有地煞 dishaScale 调小**。owner「后面几关再加难度技能」的直觉，对关3/4 不成立（数据反驳）：它们的兵海/大炮 base 相对玩家该关养成**已过强**。**诅咒留给真有空间的地方**：关5 终战（65%）或后续 Ascension。
- **难度非单调**（关3/4 比关5 还难）：因玩家养成（地支/天罡/favor）逐关变强，而关3/4 的 disha base 没随之回调 → **disha-pack 各关 base 需按"该关玩家真实养成"重标**（§3.3）。这正是 dishaScale 逐关标定要解决的。
- ⚠ **以上为旧 Boss 模型**（54张 spadeK + 12随机天罡·16写死未接）→ 方向性草案；甲接 §4.2 留场机制 + §六 16写死 loader 后，design G 重跑定稿。

**新被动「诅咒」(owner 提·真缺口·下沉新 disha op·派甲)**：
- **效果**：**每 N 回合（默认 3）一次**，把玩家**场上随机一张兵**直接**返还牌库** 或 **退回起点格**（随机/可配）。= 周期性骚扰·打断玩家铺场推进。
- **数据形**（复用 disha schema·新增 op）：`{ kind:'curse', op:'bounceUnit', everyTurns:3, mode:'toDeck'|'toStart', pick:'random' }`。
- **同构先例**：现有 `batteryEveryTurns`（大炮兵·每N回合压一路）→ 周期触发机制甲已有·`curse.bounceUnit` 是同类新 op，**确定性**（用 `b.rng` 选牌·进 turnHash）。
- **派甲**：`DishaFx` 加 `curseEveryTurns/curseMode`；`aiTakeTurn`/推进阶段按周期触发（仿 batteryLane）；`aggregateDisha` 填；数据写进 disha-pack（关5/终章）。

## 五、战役背景 + Boss 对白（关1-5 全 · 关6-52 §六逐期）

### 关1 · 温泉关 · 列奥尼达 ★
- **背景**：公元前 480 年，波斯百万大军压境。列奥尼达率三百斯巴达勇士死守温泉关隘口——以血肉筑成不可逾越之墙。**而你，要翻动这场死战的结局。**
- **对白**：开场「波斯人！来取我的长矛吧——如果你们能。」｜劣势「斯巴达人，早餐尽情吃——晚餐我们在冥府享用！」｜败北「……斯巴达的荣耀，今日终结于你手。」

### 关2 · 高加米拉 · 亚历山大 ★★
- **背景**：公元前 331 年，高加米拉平原。亚历山大以四万直面大流士二十万波斯大军，亲率伙伴骑兵直取王旗。
- **对白**：开场「我不窃取胜利。来吧，让命运在阳光下见分晓。」｜劣势「看我的伙伴骑兵，如何凿穿你的中军！」｜败北「……连我，也有马失前蹄之日。了不起。」

### 关3 · 赤壁 · 曹操 ★★
- **背景**：建安十三年，赤壁。曹操列八十万众于江北、铁索连环。一把火，将改写天下三分。**这一回，你是那把火。**
- **对白**：开场「孤提百万雄师，踏平江东，弹指间耳。」｜劣势「区区火攻，也敢撼我连环巨舰？」｜败北「……华容道上，孤竟败于这一炬。」

### 关4 · 滑铁卢 · 拿破仑 ★★★
- **背景**：1815 年，滑铁卢。从厄尔巴归来的拿破仑，要在此重夺欧洲——或永远落幕。
- **对白**：开场「近卫军从未后退。今日，让世界再记住我的名字。」｜劣势「大炮是我最忠诚的女儿——听她歌唱吧。」｜败北「……普鲁士人来得太快。命运，终弃我而去。」

### 关5 · 霸王别姬 · 项羽 ★★★
- **背景**：垓下，四面楚歌。西楚霸王力能扛鼎、勇冠三军，却已陷十面埋伏。虞兮虞兮奈若何——**而你，能否为霸王翻这一局命？**
- **对白**：开场「力拔山兮气盖世！纵八千子弟散尽，此身亦战至最后一人！」｜劣势「此天亡我，非战之罪也！」｜败北「……无颜见江东父老。罢了，就让你来翻这命吧。」

## 六、关6-52 背景/对白（子代理生成 · design G 复核）
> ✅ **全 47 位齐**（顶级 10 + 中段 23 + 末段 14）。配 §五 关1-5 = **全 52 关战役背景 + Boss 对白齐**。data 真机微调措辞即可。

### 孙武·柏举
- **背景**：公元前 506 年，吴师破楚，五战及郢。孙武以三万锐卒长驱千里，破楚二十万于柏举，旬日入郢——兵者，诡道也。这盘奇正之局已成定数，唯有你能翻动它。
- **对白**：开场「兵无常势，水无常形。你这一手，我早算在局中。」｜劣势「以正合，以奇胜……可你的奇，竟在我算路之外。」｜败北「我著兵法十三篇，算尽天下，独独算漏了你这执命之手。」

### 成吉思汗·野狐岭
- **背景**：公元 1211 年，野狐岭。金以四十五万据险，蒙古十万铁骑迎风而立。大汗一声令下，万马踏碎金国大军——苍狼的子孙从不问敌众我寡。可这一战的天命，今日由你改写。

## 八、Boss AI（通用效用解释器 + 每 Boss 画像数据 · owner 2026-06-20 问）
> 问题：Boss 与玩家**同规则**（同回合·四选一·15 张牌库[3 地煞 + 12 随机天罡]），AI 怎么每回合决策？
> **答（数据驱动宪法）**：**不**为每个 Boss 写代码（52 段自由代码=失控、违宪），而是 **「一个通用 AI 解释器（写一次）+ 每 Boss 一份策略画像（数据）」**。

**① 通用 AI = 效用(utility) AI（甲写一次 · game-side · 确定性 · 可仿真）**
- 每回合：**枚举所有可行动作**（抽天罡/抽兵 · 放某兵到某路 · 打某天罡 · 弃）→ **效用函数打分** → **选最高分**（seed 破平局·确定性·可回放）。
- 效用 = Σ(局面因子 × Boss 画像权重)：如 `放兵→X路` = f(该路我方劣势 · 推进价值 · 8 邻方阵收益…)；`打天罡` = f(全军/该路收益 · 时机)；`抽/弃` = f(手牌空否 · 源泉余量)。
- **零 per-boss 代码**：所有 Boss 共用这一个解释器，差异全在数据画像。

**② 每 Boss 画像（数据 · `Level.boss.aiProfile` · 最弱 LLM 能填权重）**
`aggression`(攻↔守) · `lanePref`(专一路↔铺三路) · `spellEager`(早放↔攒大招) · `targetPref`(打弱/强/主将) · `risk`(赌低胜率↔求稳) · `economy`(囤源泉↔快花)。
- 例：**列奥尼达**=守(aggression 低·lanePref 守家) · **项羽**=莽(aggression 高·risk 高·targetPref 强) · **曹操**=铺场(economy 快花·lanePref 铺三路)。**性格即数据**，与他的地煞自洽。

**③ 难度 = `aiTier`（数据档·配 sim）**
- 低档(新手)：有概率选**次优/随机**（会犯错·好赢）；高档(终章)：**总选最优** + 可加 1 步预判。aiTier 调每关目标胜率。

**④ 教学关特例**：稻草兵 = **固定脚本**（数据序列·doc28）·不走 utility AI（要可预测·教学用）。

> **谁写**：通用 utility AI 解释器 = **甲**（turn-combat·一次写好·零 per-boss 代码）；`aiProfile` + `aiTier` = **数据**（design G 填进各关）。真引擎缺口才提 REQ-G。**这正是宪法尺子的标准答案：逻辑下沉成一个 capability，个性全是数据。**
