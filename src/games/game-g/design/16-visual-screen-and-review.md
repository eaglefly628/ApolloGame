## 一、现状画面评审（读 `three-renderer.ts`/`game-g.tsx`）

| 现状 | 判定 |
|---|---|
| 卡 = 薄盒（正面点数花色贴图 / 反面花纹）+ 飞牌弧 + **翻面金石对比**（`feel.ts` 命门已落）| ✅ 有，但孤立 |
| 相机静态 (0,0,6)、深色空场背景 | ⚠️ 空 |
| **三路（上/中/下）/ 左右老家·牌王座 / 哨塔 / 路的空间** | ❌ **根本没建**（grep 无 lane/home/tower mesh）|
| 布阵屏 / HUD 布局 / 大厅 | ⚠️ `game-g.tsx` 手写 DOM、未对齐 UI 设计稿 |

> **结论**：画面"好简陋"的根 = **有牌、没战场**。逻辑（1311 测）扎实，但玩家看到的只是"空场里几张牌翻"。UI 设计稿（`UI/三路战场.dc.html` 的 MOBA 三路战场）的场景结构**一个都没落**。

## 二、⭐ 第一优先 · 离线看帧（让画面"看得见、可评"）—— enabler，先做

- **现无任何看帧**：game-d/game-f 都有 `render-frame.ts`，game-g 没有 → **谁都看不见画面、没法评、没法迭代变好玩**。
- **要 program G 做**：仿 `game-d/render-frame.ts` 给 game-g 加 `render-frame.ts`——跑一局到关键拍、ThreeRenderer 渲到离屏 canvas → **导 PNG** 落 `src/games/game-g/doc/screenshots/`。
- **关键帧**：① 布阵屏 ② 三路开战(抛牌) ③ 掷命揭晓(金石+溃散) ④ Boss 决战 ⑤ 大厅。
- → design G 读图评审、owner 也能看。**没有看帧 = 没法评画面 = 这条优先级最高。**

## 六、持续迭代评审环（design G ↔ program G）

```
program G 做出画面 + 出帧 → design G 读图 + 读码 评 → 提改进需求 → 再迭代 → … 直到"好看 + 好玩"
```

**评审尺子（design G 每轮拿这把量）**：
1. **博弈悬念演出来没**——命运一掷有戏剧感吗？逐路揭晓紧张吗？
2. **可读性**——三路谁赢、牌型、流派、招牌激活，玩家看得懂吗？
3. **美术基调对没**——拟人扑克 + 古风，对齐 UI 稿玄铁/锦霞？
4. **布局顺手没**——干预/派牌/看战况的操作流顺吗？
