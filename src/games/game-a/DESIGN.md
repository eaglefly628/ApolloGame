# Game A · 设计与引擎需求分析

> 主策划 + 主程：PA · 2026-06-03
> 上位设计：`docs/game-design/game-a-coop-platformer.md`（定位/机制池/世界结构）
> 本文：把"完整游戏"拆成系统 → 映射到引擎能力 → **标出缺口 → 拉动引擎需求**（v2 模型）。

---

## 1. 这不是一个跳跃小游戏

目标是《双人成行》式**合作冒险**：两个能力互补的角色，靠配合通关。完整体验需要的远不止移动+跳跃——
血量/伤害/死亡重生、交互、机关、抛射搭档、绳索、跷跷板、传送、卷轴大关卡、AI/Boss、存档、音效、粒子。
其中**很多引擎现在没有**。Game Creator 的职责就是用真实游戏把这些缺口逼出来，写成需求交给 Lead 收敛为通用原子。

## 3. 引擎需求路线（按版本拉动，避免 YAGNI）

> 原则：**只在真要做某版本时才提该版本的需求**，让需求被真实游戏拉动，便于 Lead 收敛成两个游戏共用的通用原子。

| 版本 | 我要做的 | 需要 Lead 提供的引擎能力 |
|------|---------|----------------------|
| **v0.1** ✅本次 | 双人移动+跳跃+平台（固定屏） | 无（全现成） |
| **v0.2** | 卷轴大关卡 + 踩开关/限时门/重量台 + 交互 | **REQ-001 相机/卷轴**（已提）；交互约定（按需提） |
| v0.3 | 推箱/小洞/抛射搭档（能力差异） | 多为现成；移动平台可能提"mover" |

| v0.5 | 动画/粒子/相机震动打磨 | 粒子系统、相机震动系统 |

## 4. v0.1 范围（本次交付）

固定屏 640×400，双人（蓝 A / 橙 B）移动 + 跳跃 + 平台 + 重力 + 落地 + 边界 + 确定性。
**全部用现成引擎原子，零引擎改动**——先把核心手感和确定性闭环钉死，作为后续所有版本的回归基线。

文件：`level.ts`（关卡数据）· `blueprint.ts`（世界拼装）· `keymaps.ts`（双人键位）· `game-a.test.ts`（落地/跳跃/无二段跳/路由/确定性）。

## 5. 卷轴怎么处理（REQ-001 摘要）

当前渲染器 `ctx.translate(r.x, r.y)` 把**世界坐标直接画到固定画布**——世界不能比屏幕大，无从卷轴。
解法是把**世界空间**与**屏幕空间**用相机解耦：

1. 关卡世界可远大于视口（如 4000×720），实体用世界坐标，`bounds-clamp` 钳到**关卡**边界（纯 config）。
2. **合作相机**（复用 L5 `Camera` 组件）：每 tick 取两名玩家 AABB 的中心为相机中心，缩放 = 把两人+边距塞进视口（钳在 [minZoom,1]），再把相机框钳在关卡边界内（不露出界外空白）。
3. **渲染器施加世界→屏幕变换**：`screen = (world − camera.topLeft) × zoom`。玩家右移 → 相机偏移增大 → 世界向左卷动。

为什么是**引擎需求**而非我自己改：渲染器（世界→屏幕投影）是两个游戏共享的基础设施，归 Lead 守护；相机跟随逻辑也可做成两游戏复用的通用系统。详见 `docs/workflow/requests.md` REQ-001（含伪代码）。
