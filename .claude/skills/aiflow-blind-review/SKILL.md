# 关键图盲审（R1）

规则来源：`docs/workflow/ai-production-flow.md` §3 / §7、`docs/playbooks/review-gates.md`。采集配置与命令见 `docs/design/ai-pipeline/keyart-review.md`。

## 输入隔离

复查人必须独立于施工人。第一轮只接收已定稿参考图与本轮真实截图；动作问题同时给按机位排序的帧序列。UI 参考须先渲染为图，与实际屏使用同画布尺寸。文件名中的机位和帧号可用于定位，不能把施工方自评混进图片说明。

不读施工方 Review 单、自证说明、修复理由或“已经一致”的自陈，也不先读 metrics 的分析结果。先将直接目击的差异固定成记录，再用客观指标定位；指标不能推翻可见缺陷或替代缺失证据。已误读施工结论时如实说明，另派未受引导的复查人完成盲判。

## 先盲看，逐项留证

| 项目 | 比较内容 |
|---|---|
| 构图 | 主体位置、视角、地平线、裁切、负空间；跨机位核对，不能只挑最接近的截图 |
| 色调 | 主色与辅助色、冷暖关系、饱和度、明暗分布；同色直方图不证明同构图 |
| 光源 | 主光方向、阴影投向、亮面与接触阴影、人物与背景受光一致性 |
| 层次 / 比例 | 前中后景遮挡、人物与道具尺寸、透视、接地、主体辨识度 |
| 动作 | 顺帧看起止与过渡；检查穿模、足底滑步、肢体翻折、IK 抖动、手与物件接触点、循环接缝；静态看不见的问题不能凭单帧判过 |
| UI 模式 | 同尺寸并排看参考稿与实际屏，逐件核位置、尺寸、背景 / 文字色与缺失项；布局接近仍要看层次与可读性 |

每条记录“参考图位置 / 实际机位与帧号 / 看见的差异 / 影响 / 需复现或补证内容”，引用实际图片路径与可核查坐标，避免“差不多”“还行”。视角、状态、动作阶段不匹配时先补对应机位或帧；动作覆盖不足明确写“需补帧”，不能宣称动作已过。

## 再用机器信息定位

盲判记录完成后可读 `metrics.json`：色调直方图距离、分区亮度与 UI 逐件位置 / 尺寸 / bg / color 差只作辅助。UI missing 是待核实差异，需回图确认是否真缺件、选择器不匹配或状态未到。没有通用通过阈值，不用分数自动写 PASS。

需要独立采集时运行：

```bash
node scripts/keyart-review.mjs <slug> <scene>
node scripts/keyart-review.mjs <slug> <scene> --mode ui
```

同场景同机位重复截图字节不一致会报错；先记录不稳定并查采集条件，不能拿漂移图作稳定证据。截图文件名帧号补足四位，如 `main-0060.png`；配置缺省为 main 机位、第 60 帧、1000×640 截图。动作帧须递增，范围 0–600，最多 120 项，每机位 actions 最多 20 项。`--mock` 截图与指标只写 `self-check/mock/shots/<scene>/`，骨架只写 `self-check/mock/R1-keyart-review.md`，不生成真实 R1 门工件，也不能作为视觉复查证据。

## 留给谁决定

将独立观察写入 `self-check/R1-keyart-review.md` 的差异项，标明复查主体、输入图、机位、帧与未决证据。工具只创建骨架：重复场景保留已有章节，新场景仅追加骨架；施工人不填复查判词。结论须由真实独立复查人依据自己的核证填写，仍遵守既有复查纪律，不代签任何人门。

差异回施工修复并重截；若要求改参考图，回 K2 由 owner 重新确认，不能把目标改得接近现状来消除差异。采集失败、缺参考、缺动作帧或设计未定稿时明确留未决项，不把工件在档视为通过。
