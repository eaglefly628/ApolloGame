# Steam 上架全流程（有账号后照此走）

> 从「有 Steamworks 账号」到「玩家能买到」。⚠️ Steam 政策/页面会变，以 Steamworks 后台
> 当前提示为准；本表是 2024–2026 的通行流程。带 🛠 的步骤本仓库 `steam-publisher` 工具能帮你做。

## 阶段 0 · 账号与公司资料（一次性·人工）
1. 注册 Steamworks 合作伙伴账号，签电子协议。
2. 填**身份 / 银行 / 税务**资料（个人或公司）。**没填完不能上架收款** —— 这步常卡最久（税表审核要几天）。
3. 付 **Steam Direct 费 $100 / 每款游戏**（营收满 $1000 美元后返还）。付完即生成一个 **App（拿到真 AppID）**。

## 阶段 1 · App 基础设置（后台·人工）
4. 在 App Admin 里建 **Depot**（每平台一个：win/mac/linux），记下 **DepotID**。
5. 设 **Package / 定价**（区域定价表 Valve 给建议值，可调）。
6. 🛠 **登记成就 / 排行榜 / Cloud**：把代码里的成就 id（`GG_FIRST_BOOT / GG_FIRST_WIN / GG_FLAWLESS`，见 `src/services/platform/achievements.ts`）、排行榜 `campaign_progress`、Steam Cloud 配额在后台**登记同名**才真生效。

## 阶段 2 · 商店页（后台·人工 + Valve 审）
7. 填商店页：**名称 / 简介 / 标签 / 分类 / 截图 / 预告片 / 胶囊图(capsule)** 等美术素材（有尺寸规范）。
8. 填 **内容调查问卷**（暴力/性/敏感内容）→ 决定年龄分级。
9. **提交商店页给 Valve 审**（Store Page Review）。通过后才能把页面设为 **「即将推出 Coming Soon」**。
   - ⏳ **硬规则：商店页必须在正式发售前至少「上线满 2 周」**（Coming Soon 攒愿望单）。所以**别等到发售前一天才建页**。

## 阶段 3 · 上传游戏构建（🛠 工具搞定）
10. 🛠 用 `steam-publisher`：填真 AppID/DepotID → **🔨 构建裸目录**（electron-builder --dir）→ **📝 生成 VDF** → **🚀 一键发布**（steamcmd 经 SteamPipe 上传成一个 build）。
11. 在后台 **SteamPipe → Builds**：把刚上传的 build **Set Live 到 `default` 分支**（送审要求 build 在默认分支可跑）。

## 阶段 4 · 送审游戏构建（Valve 审·几个工作日）
12. 走后台 **发售前检查清单（Release Checklist）**：把所有项打绿（build 已设默认分支、商店页已批、定价已设、分级完成…）。
13. 点 **Request Review / 提交审核**。Valve 会**真下载你的 build 跑一遍**，检查：能正常启动、与商店页相符、无恶意/违规内容、成就等功能不崩。
    - ⏳ 一般 **1–5 个工作日**。被打回就按意见改、重传 build、再交。

## 阶段 5 · 发售（你点 / 到期自动）
14. 审核通过 + 检查清单全绿 + 设好**发售日期** → 到点你点 **Release**（或按日期自动放出）。
15. 上线后更新游戏 = 重复阶段 3（🛠 一键发布新 build → Set Live）。重大更新无需重新付费审核（除非改分级/重大内容）。

---

## 时间线预期（别踩的坑）
- **税务/银行资料**：可能要数天审核 → **第一件事就去填**，别拖到最后。
- **商店页 2 周**：发售日往前倒推≥14 天必须有 Coming Soon 页 → 提前建页。
- **build 审核**：留足 ≥1 周缓冲（被打回要返工）。

## 本仓库帮你免去的活
- 上传/打包：`steam-publisher`（SteamPipe 编排，傻瓜界面）。
- 成就/云/排行榜：代码已接好（假 Steam 可先验），后台登记同名 id 即生效。
- 一句话：**「写代码 + 上传」我们包了；「账号 / 钱 / 商店页 / 送审点按钮」是你在 Steam 后台的人工活**——Valve 不给这些步骤 API。
